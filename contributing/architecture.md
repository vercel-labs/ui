# Architecture

How the code is shaped: the layers in core, how a primitive is defined, how each framework renders it, and the popup layer every overlay shares. Read it before you write core code.

## Layers

| Layer              | Path                                                                                                                                                                                                    | Owns                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Kernel             | `packages/core/src/foundation/kernel/`                                                                                                                                                                  | `primitive.ts` (`definePrimitive` and its instances, typed in `primitive-types.ts`), the store, the lifecycle, parts and binding, controllers, changes and reasons, input sources and modality, live and state attributes. Imports nothing else in core                                                                                                                                                                                                                                                                                         |
| Platform           | `packages/core/src/foundation/platform/`                                                                                                                                                                | What every job shares about the page: `platform` (checks, shortcut labels), `layers` (dismissal), `position` (our own positioning), the announcer                                                                                                                                                                                                                                                                                                                                                                                               |
| Jobs               | `packages/core/src/foundation/<job>/`: `focus`, `selection`, `drag-and-drop`, `direct-manipulation`, `lists`, `motion`, `popups`, `canvas`, `date`, `text`, `forms`, `disclosure`, `gauge`, `shortcuts` | One folder per job, named like the Behaviors docs pages. `popups` has `createPopup`, `createOpenSteps` and the sheet; `lists` the listbox engine Select, Combobox, Autocomplete, Command and Listbox share; `motion` presence and the gesture physics; `forms` form state, `text-field` and the toggle control Checkbox and Switch share; `disclosure` the trigger and panel Collapsible, Accordion, Tabs and Navigation Menu share; `gauge` the value bar of Progress and Meter; `shortcuts` the page's shortcut manager and the Shortcut part |
| Component behavior | `packages/core/src/components/<name>/`, one folder per component, files named `<name>-*.ts`                                                                                                             | State, transitions, keyboard, focus, everything that decides. A helper only this component uses lives here, like Select's `select-keyboard.ts`                                                                                                                                                                                                                                                                                                                                                                                                  |
| Page               | `packages/core/src/page/`: `agent`, `observe`, `timeline`, `overlays`, `shortcuts`                                                                                                                      | What works across a whole page. `page/shortcuts` is the public entry of the manager in `foundation/shortcuts`                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Adapters           | `packages/{react,solid}/src/use-primitive.tsx`, `packages/{vue,svelte}/src/create-parts.ts` and `use-primitive.*`, `packages/web/src/define-element.ts` (`createParts`, internal `definePart`)          | Generic. Never import a specific component                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Parts              | `packages/{react,vue,web,solid}/src/<name>.*`, `packages/svelte/src/<name>/`                                                                                                                            | Prop mapping and rendering only                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |

Core imports downward only: kernel, platform, the jobs, components, page. Each foundation folder's `index.ts` lists what other folders may import from its files, and an import from another folder names only what that list has. Imports still name the file, not the index: a bundler places a module by what imports reach, so imports through an index would pull lazily loaded code, like the sheet, into every entry. A component imports foundation, not another component or the page. `pnpm lint` checks it (`import-layers` in `scripts/check-code.mjs`), and the exceptions are listed there with why: Date Picker on Calendar, Drawer on Dialog, Menu and Menubar on each other, Dialog and Toast on `page/overlays`, and the kernel's development warnings and lazy announcer.

## Shared engines

- **Lists.** One listbox engine sits under Select, Combobox, Autocomplete, Command and Trigger Menu (`lists/listbox*.ts`, `collection.ts`, `async-options.ts`, `fuzzy.ts`, `match.ts` with `Intl.Collator`). Autocomplete is the general "input filters a list" core; Command is Autocomplete inline, with action items.
- **Roving focus.** One engine, the public `createRovingFocus` (`focus/roving-focus.ts`), runs Tabs, Radio Group, Toggle Group, Toolbar, Menubar and Carousel's indicators. It's the same block an agent's component uses. `focus/roving-scope.ts` holds the scope a toggle joins in a toolbar. Components guard Shift themselves, since `createRovingFocus` reports it rather than swallowing it.
- **Pointer and actions.** Pointer tracking is in `drag-and-drop/pointer.ts` (`bindDrag`, `repeatWhileHeld`). Async actions are in `action.ts` (Button, Dialog Close, toast buttons).
- **Overlay host.** `page/overlays/overlays.ts`, plus one host per adapter (`<OverlayHost />`, `<ui-overlay-host>`), renders overlays opened from code: `await confirm({...})` and `toast()`.
- **Shortcuts.** `@ui-sdk/core/shortcuts` is a layer-aware manager; triggers and items take `shortcut="mod+k"`.
- **Dev checks.** Development-only code comes from the `#dev` conditional import (`dev.ts`, `dev-stub.ts`). Warnings name the component and its id, and production builds drop all of it. Wrap development work in `if (dev)` so esbuild drops the arguments too.

## definePrimitive

```ts
export const thing = definePrimitive({
  name: "thing", // data-slot becomes "thing-<slot>"
  // Every option's kind, which renderers read to tell options from element props. Required.
  options: {
    open: "boolean",
    defaultOpen: "boolean",
    onOpenChange: "callback",
  },
  state: (options: {
    open?: boolean
    defaultOpen?: boolean
    onOpenChange?: (open: boolean, details: ChangeDetails) => void
  }) => ({
    open: options.defaultOpen ?? false,
    highlighted: null as string | null,
  }),
  live: ["highlighted"], // Changes often, never affects rendering. Written to the DOM, no re-render.
  sync: (options) => (options.open === undefined ? {} : { open: options.open }), // Controlled options.
  // Context: { id, label, store, options, onOptions, onDestroy, parts, element, props }. Everything
  // else is an opt-in import, so a component pays only for what it uses.
  api: (context) => {
    // change() calls on<Key>Change with { reason, event, source, cancel, canceled } and skips the
    // write when controlled or canceled. Only for keys with a public on<Key>Change. It tracks
    // input from the start, so each change's details say what caused it.
    const change = createChange(context)
    // A `controller` option drives what this returns. elements(context, slot) reads bound parts in DOM order.
    return {
      toggle: (event?: Event) =>
        change("open", !context.store.get().open, {
          reason: "trigger-press",
          event,
        }),
    }
  },
  slots: (slot) => ({
    trigger: slot({
      attrs: (state, { id }) => ({
        type: "button",
        "aria-expanded": String(state.open),
      }), // Pure, SSR-safe.
      press: ({ api }, event) => api.toggle(event), // Runs on click.
    }),
    item: slot<{ value: string; disabled?: boolean }>({
      // Typed per-slot props, and their kinds, required when the slot takes props.
      props: { value: "string", disabled: "boolean" },
      present: (state) => state.open, // Element should exist. Custom elements bind and unbind on it.
      attrs: (state, { id, key, props, api }) => ({ role: "option" }),
      live: live((state, { key }) => ({
        "data-highlighted": state.highlighted === key ? "" : undefined,
      })),
      selects: selects({ highlighted: ({ key }) => [key] }), // Hear only changes that concern this part.
      // Public state for render functions, typed by slot's second type argument: slot<Props, State>.
      state: (state, { key, props }) => ({
        highlighted: state.highlighted === key,
        disabled: !!props.disabled,
      }),
      on: { keydown: (event, { el, api }) => {} }, // Declarative DOM events. Use ctx.el, not event.currentTarget.
      bind: (el, part) => () => {}, // Once the element is in the page: focus, positioning, observers. part.props is the newest render's. Return cleanup.
    }),
  }),
  agent: { actions: ["toggle"] }, // The api methods an agent may call. After slots, so the api is inferred.
})
```

- **Attributes are HTML attributes,** strings only, with `""` for booleans. React renames 4 of them and Vue binds them as they are.
- **A slot's `direct` attributes** render like any other, but core writes them to a framework-rendered element itself, so a change to only those re-renders nothing (an option's `hidden`).
- **`bind` gets `onProps`** to hear each render, so work that depends on a prop, like a trigger's shortcut (`bindPartShortcut`), runs only while the prop asks for it.
- **Events go through adapters.** User handlers run first and can call `preventDefault()` to skip ours. Later props run first in `slot()` and React's `mergeProps`. React passes `event.nativeEvent`.
- **Element identity** is `props.id ?? props.value`, and a value of any type keys its part by `String(value)`. Singleton slots are found by `element(slot)` without a key.
- **Author ids win.** Adapters let a user's `id` win when they merge, and `applyAttrs` never replaces an id it didn't write, so an author's id stays on a part's element. Adapters hand that id to `takeOwnId` as the part renders, so the parts rendered after it point at it from their first render, on a server too. Once the element binds, and whenever its id changes, `attrs()` and `liveAttrs()` point every reference to the id its slot makes (`aria-controls`, `aria-labelledby`, `for` and the rest) at the element's. An api writing references to an element that isn't a part, like an editor, passes them through `aliasReferences`.
- **`elements(slot)`** returns bound elements in DOM order, so collections need no index bookkeeping.
- **Lifecycle.** Each instance has one lifecycle (`kernel/keep.ts`). Work that reaches outside it, like attaching its controller, the agent hearing it or following an editor, starts through `whenKept(start)` in its setup, and `start` returns its stop. The framework keeps the instance while it holds it: in a browser it's kept as it's made, and on a server never, so nothing outlives a request. React keeps it once it commits and releases it while `<Activity>` hides it, which keeps its state; Vue keeps it on mount. Every adapter calls `instance.destroy()` when the component leaves the page (React from a passive effect cleanup, a microtask later for StrictMode; Vue from `onScopeDispose`; web components from `whenGone`). It stops the kept work for good, which detaches the controller unless another instance attached since, then runs the `onDestroy` callbacks setup registered, once. `onDestroy` is for what the instance holds itself, like a timer.
- **Controllers.** `definePrimitive` connects a `controller` option to whatever `api` returns. It attaches once the framework keeps the instance, and again when `setOptions` swaps it, through `attachController()`: the attach hook is a symbol, so a controller's only public keys are its methods. Expose a typed `create<Name>Controller()` with JSDoc on every method, following the API guide (`get<Key>`/`is<Key>`, `set<Key>(value, { reason })`, verbs, `focus()`), and re-export it from every framework package.
- **Reasons.** Every `on<Key>Change` has an exported reason union, a subset of `ReasonVocabulary` in `details.ts`. A new reason goes into the vocabulary first, with its JSDoc line and its event type in `dev.ts`, which the docs' `ReasonTable` shows.
- **State attributes.** Use `openAttrs(open)` and `checkedAttrs(checked)` from `kernel/attrs.ts`. Never `data-state`.
- **Controlled warnings.** `definePrimitive` warns once in development for `x` with `defaultX`, and for `x` switching between controlled and uncontrolled, for whichever of `open`, `value` and `checked` the state has. Pass `controlled: [...]` when the state reuses one of those names for something else.
- **The api is named where it's defined.** `definePrimitive({ api: (context) => ({ ... }) })` returns what slots reach as `({ api }) => api.x()`. Helpers that build an api are `<name>Api` (`tabsApi`) in `<name>-api.ts`. The `options` schema is required only when `state` takes options with keys, and renderers read a missing one as `{}`.
- **Internal options.** Options only adapters pass, like a submenu's `parent`, go in `<Name>InternalOptions`, never the public `<Name>Options`.
- **Exports.** `@ui-sdk/core` exposes `.` and one entry per component. `.` is the kit for building components, ours and an agent's: the kernel plus building blocks like `createRovingFocus`, `createSelection`, `createFocusRecovery`, typeahead, `bindPanel`, `isRTL`, `pageLocale` and `idPart`. Part readers (`partAttrs`, `partState`, `partPresent`) are in `@ui-sdk/core/testing`. When a component needs a helper an outside primitive would need too, export it from `.` with JSDoc, a stability label and an example on its Behaviors docs page. A new component of ours uses these blocks too, so both stay one implementation. Helpers only renderers need are on `@ui-sdk/core/renderer`, a checked list kept out of the docs; renderers never import `@ui-sdk/core/internal/*` (the `renderer-imports` lint), which resolves only inside this repo.
- **Several components on one core.** When components share behavior (Accordion and Collapsible, Checkbox and Switch), put the shared logic in its own core module and keep one module per public component on top. Each component still gets its own fixtures, specs and docs page.
- **Form controls.** Anything that holds a value in a form follows `foundation/forms/form.ts`. React, Vue, Solid and Svelte render a visually hidden native input that's in the server HTML, so forms submit before hydration. Web components are form-associated custom elements (`formAssociated` in a part's options) with `ElementInternals` and no hidden input. Every control handles form reset, `disabled` on a parent `<fieldset>`, the `form` attribute, `required` with native validity, and labels through `<label>` and Field.
- **Data API, only for collections.** Add an `items` prop only when the component must know its items before they render: shortcuts while closed, typeahead over unrendered items, virtualization, filtering. That covers Menu, Context Menu, Select and Combobox. Export a type for the data (`ListData`, `MenuData`, `TreeItemData`) from every adapter, so a user writes `const plans: ListData = [...]`. Items with fields of their own extend `ListItem` and take the names `<Root>DataItem`, `<Root>DataGroup` and `<Root>Data`, since `<Root>Item` names a part. Render the data with the same parts the composition API uses, bare and unstyled. People style it by rendering the parts themselves, and web components copy the parts written in a `<template>` inside the element (`copy` and `templateOf` in `packages/web/src/list.ts`).
- **Docs read the core.** `DataAttributes` samples `attrs()` and greps `setAttribute("data-…")` in core files. `CssVariables` greps `setProperty("--…")`. `TypeTable` reads exported prop types with JSDoc. New attributes and variables show up in the docs only if they're written that way.

## Rendering contract

Every renderer has `createParts(primitive, tags)`, which returns `Root` and a Pascal-case part per tagged slot (`tab-icon` is `TabIcon`), typed from the primitive. `usePrimitive` is for a root written by hand, and `usePart(handleOrPrimitive, slot, slotProps, props, tag)` for a part written by hand, which re-renders it only for the attributes, presence and state it read. On web, `createParts(primitive, tags)` registers a custom element per part and returns their classes the same way; the package's own components also use the internal `definePart(primitive, slot, tag)`, which defines one element at a time.

It rests on the primitive's schema: `definePrimitive({ options })` and slot `props`, each name with its kind (`string`, `number`, `boolean`, `list`, `value`, `callback`, `action`, `id`, and `key` for a list item's value, which keys the part and reaches nested parts as that key). `{ kind, from: "item" }` marks a prop a nested part takes from its parent, and `required: true` makes a part outside that parent throw. TypeScript checks the schema names every option and prop. Schemas are plain object literals, never spreads, so esbuild can drop unused primitives.

- **Named types.** Define a primitive as `xPrimitive`, and export `interface XPrimitive extends Named<typeof xPrimitive> {}` with `const x: XPrimitive = xPrimitive` (see Separator), so adapters' declarations name `XPrimitive` instead of printing the whole primitive. A primitive whose types take a value type extends `WithGeneric<typeof xPrimitive, XGeneric>` instead (see Tabs), with `XGeneric` declared in a module that isn't an entry and exported from `@ui-sdk/core/renderer`; `pnpm build` fails with TS4023 when no entry exports it.
- **Every part renders as any element through `render`.** There is no `as` prop in any framework. Render functions get the slot's `state`. Export a `<Name><Part>State` type per slot with JSDoc, and declare it with `slot<Props, State>({ state })`.
- **State is tracked by reading.** A part re-renders for a state key only if its render function read it. Never make parts read live state eagerly, or highlight changes re-render every item again.
- **Links.** Keyboard activation of an `a[href]` item calls `el.click()`, so routers and modifier keys work. Do the same for any activatable part that can be a link.

Per framework:

- **React.** `render` takes an element (props merge) or `(props, state) => element`. `className`, `style` and `children` take functions of state. Library parts are named consts with JSDoc (`const TabsList = parts.List`), since TypeScript drops a property's JSDoc when a mapped type renames keys. `usePrimitive` returns one object for the instance's life, so context never re-renders consumers. Every component is imported from its subpath (`@ui-sdk/react/dialog`): there is no root entry, and helpers for custom parts come from `@ui-sdk/react/primitive`. Every module ships with "use client" except the build's `--server` list in `packages/react/package.json` (`render-element.ts` and the `primitive` entry), so `renderElement` stays a function a Server Component can call; `scripts/build/server-modules.mjs` checks it.
- **Vue.** The `render` slot receives `{ props, state }`, and the default slot `{ state }`. Schema props become runtime props, and callbacks become emits: `on<Key>Change` emits `<key>Change`, then `update:<key>` unless canceled, so `v-model:<key>` works. An `"action"` stays a function prop, so its return value counts. A part written by hand is a `defineComponent` with `inheritAttrs: false` calling `usePart`; optional booleans use `optionalBoolean`. Component refs are unwrapped to their element. `@ui-sdk/vue/nuxt` is a Nuxt module, built from `packages/vue/nuxt` rather than `src`: the build lists each entry's components and other values in `dist/nuxt/entries.json`, and the module registers them. Nothing in `src` imports Nuxt (`nuxt-imports` in `pnpm lint`).
- **Solid 2.** Like React over signals: `render(props, state)`, and `class`, `style` and `children` as functions of state. A part binds once its element is in the document, and from the microtask after `hydrate()` while hydrating.
- **Svelte 5.** `<Part tag part props>` renders a part and its `render` snippet with `{ props, state }`. Roots call `provideInstance(primitive, handle)`, and the library's parts stay hand-written on `useHandlePart`, since Svelte's runtime `createParts` costs about 1 KB per entry; `createParts` exists for components written outside the library. Popups pass `portalTo(container)` to `usePart`. Every bindable prop is `$bindable`, and the root passes it to `usePrimitive` as a getter (`get value() { return value }`), so a bindable prop is controlled from the start or once the parent sets it, never by the component's own write-back.
- **Web components.** One custom element per part, named like the React part (`MenuSubTrigger` is `<ui-menu-sub-trigger>`). `createParts(primitive, { root: { tag, display, state, api }, item: "ui-x-item" })` reads attributes, properties and events from the schema: string, number, boolean and list kinds are attributes, each reflected as a property too (booleans that start on are named in the root's `defaults`), `value` is a property only, and callbacks are lowercase events (`onCheckedChange` fires `checkedchange` with `detail.value`). Events don't bubble; they're composed, so a shadow host hears them, and a container hears every element inside with `{ capture: true }`. `state` declares the live property (`open`, `value`), `api` the controller methods `el.api` exposes. Triggers wrap the user's own `<button>` (`display: "contents"`), so native button behavior stays. `import "@ui-sdk/web/<entry>"` defines that entry's elements, with the same entries as React; the root `@ui-sdk/web` has no side effects. The prefix stays `ui-`, with no runtime renaming and no scoped registries, and a tag someone else defined first keeps their definition, with a development warning (`claimTag` in `define-element.ts`). Rules ship in `@layer ui-sdk`. A prop named `on` plus a capital letter becomes an event on web, so internal props must not look like that.

Solid and Svelte can't read composed children before they render, so a composed Select shows its value key in server HTML until mount.

## Popups

Every overlay uses the popup layer in `popups/popup.ts`. **New overlay components must use it,** and should copy Popover's shape. Don't copy presence, dismissal, focus return or modal code from an existing component.

- **`createPopup({ preset, ...wiring })`** once in `api`, then `popup.bind(el, { position, anchor, initialFocus })` from the content slot's `bind`. `preset` names the behavior (`menu`, `select`, `combobox`, `popover`, `dialog`, `tooltip`, `hoverCard` in `popups/popup-behavior.ts`: Tab mode, blur, outside press timing, shield, trigger kept live, focus on mount, focus loss, close watcher, blocking), and any of those passed beside it override the preset. A new kind of popup adds its preset there rather than another option. Then `createOpenSteps({ popup, store, change, onDestroy, payload?, returnFocus?, rules })` from `popups/popup-steps.ts` beside it, and spread its `api` into the component's api. It owns:
  - **presence and focus return** in one store subscriber, so a trigger press, Escape, an outside press, a controller and a controlled `open` prop all close the same way. A request's `focus` sets the mode for that close: `true`, `false`, or `"later"` (after the press, for presses on empty space);
  - **the focus return chain**, looked up at close time: `finalFocus` if set, then the trigger, the element focused before opening, the trigger of the popup it was opened from, then the nearest element that survived where the trigger was. Each candidate is checked by focusing it;
  - **the top layer**: `popover="manual"` is set in `bind`, never in `attrs`, so content rendered open on the server is visible before hydration. `showPopover()`, the z-index fallback and the StrictMode-safe `hidePopover()`;
  - **positioning** through a getter, so prop changes apply while open. Leave `position` out for sheets or CSS-placed popups;
  - **the dismissal layer**: the parent is `findLayer(trigger)` unless the component passes `parent` (submenus do), so any popup inside any other popup nests, portaled or not;
  - **the modal triple** `{ consumeOutsidePress, trapFocus, inertAndLock }`. Keep the component's public `modal` union and map it with `modalTriple()`. `inert` comes off when the close starts; the scroll lock stays until unmount;
  - **Tab modes**: `"close"` (menus), `"flow"` (computed order, close on focus out), `"trap"`, and `"native"` (the browser's own order, for comboboxes and tooltips). Call `popup.keydown(event)` from the content's keydown and `popup.triggerKeydown(event)` from the trigger's;
  - **blur**: `"always"`, `"iframe"` or `"never"`;
  - **openers** (`pointer`, `touch`, `keyboard`, `hover`, `imperative`, `initial`) from the request's `by`. Hover and an open from the start move no focus, touch focuses the popup, anything else calls the component's `initialFocus` resolver. Focus waits a frame after a pointerdown open.
- **What stays in the component:** its `modal` union, role and ARIA (`popupTriggerAttrs` and `popupContentAttrs`), its initial focus resolver, hover opening, item registries, typeahead, submenu trees and anything else only it does.
- **Dismissal.** Popover, Menu, Select, Combobox, Autocomplete, Trigger Menu, Dialog, Alert Dialog and Drawer take `dismissible` and `onDismissAttempt` (`popups/dismissal.ts`, checked in `createOpenSteps`). Focus or the window leaving is refused silently. Tooltip and Hover Card don't take it, since WCAG 1.4.13 requires hover content to be dismissible.
- **Controllers:** `createPopupController<Payload, Reason, ExtraOpenOptions, Result>()`, driven by `createOpenSteps`, which runs every open and close step in order and settles `open()` once: on the next close, on abort, or with `unmount`. A component adds only its rules: `open`, `reopen` and `close`; `pnpm lint` (`popup-steps`) fails on a direct `popup.opening(` or `popup.returnFocus(`. The payload lives in state until the next open. Content state is generic in it (`TooltipContentState<Payload = unknown>`), and each adapter's content part takes it as a type argument.
- **Several triggers and triggers outside the root.** Key each trigger by an id, keep the active trigger's key in state, and pass it to `popupTriggerAttrs(state, id, haspopup, key)`, so only that trigger is expanded and named. Adapters find a component from outside its tree through its `controller`, or `for="id"` on web parts.
- **Presence options:** `keepMounted` content binds while closed; `createPopup` shows it on open and hides it after the exit. `onOpenChangeComplete` comes from `createPopup`'s option of the same name.
- **Built in, not per component:** forms with `method="dialog"` close the popup and report the submitter's value; focus returns through `restoreFocus`, marked so a tooltip can skip it; `bindPersistentLayer(el)` keeps an element live over modals; `"unless-moved"` focus return skips the return when something the press opened took focus, like a dialog opened from a menu item.
- **Layers** (`platform/layers.ts`): `pushLayer({ contains, parent, active, exiting, overBackdrop, modal, keep, returnTarget, onEscape, onOutsidePress, onBlur })`. `createPopup` fills it in. An outside press is decided at pointerdown, never on a scrollbar, and touch dismisses on click. Escape skips IME composition. A layer animating out lets presses on its popup through to the page. A modal one swallows presses on its backdrop, outside the popup, so a double click that dismissed it never lands on the page, and shields the layers beneath it.
- **Modal side effects** (`popups/modal.ts`): `inertOutside(keep)` keeps live regions live, crosses shadow roots, and returns a release with `keep(el)` for child popups rendered into an inert container. `lockScroll()` locks whichever of `html` or `body` scrolls, keeps a classic scrollbar's gutter with `scrollbar-gutter`, writes `--scrollbar-width`, restores only the properties it set, and guards touch moves on iOS. Never `body { position: fixed }`.
- **Presentation.** Menu, Popover, Dialog, Select, Combobox and Autocomplete take `presentation`, and `"auto"` picks a sheet on small touch screens. The sheet comes from the Drawer's engine and loads with `import()` only for a popup set to `"sheet"`, or `"auto"` on a phone. A sheet is modal unless `modal={false}` is passed (`popups/presentation.ts`).
- **Portal into a container** for the cases the top layer doesn't cover: a specific container, iframes, shadow roots, or browsers without `popover`. Each root popup part takes a `container` prop, resolved with `portalTarget(container)` from `@ui-sdk/core/renderer`: the explicit container, else `document.body` when there's no top layer, else `null` to render in place. A popup without `container` inherits the nearest enclosing popup's. Each adapter has one helper: React `renderPopup` in `packages/react/src/popup.tsx`, Vue `renderPopup` and `containerProp` in `packages/vue/src/popup.ts`, Solid `renderPopup` in `packages/solid/src/popup.tsx`, Svelte `portalTo` from `packages/svelte/src/popup.svelte.ts`, and web a popup part's `portal` option (`popupPortal` in `packages/web/src/popup.ts`). Submenus and nested popups never portal; they move with their root popup. The `*-portal` Playwright projects rerun the popup specs with `?container=portal-root`.
- **Positioning:** `position(anchor, el, { side, align, sideOffset, alignOffset, collisionPadding })` from `platform/position.ts`. `anchor` is an element, a point, a rectangle, or a getter of one, read on every check. `side` takes logical `start` and `end`. `computePlacement` is pure and unit tested: flip to the side with more room, shift along the anchor, logical sides swapped in RTL. `position` places synchronously on bind, then checks each animation frame while something moves, sleeps after a few still frames, and wakes on scroll, resize, DOM changes, input, loads and animation starts, with a 500 ms slow check for anything else. It only writes values that changed, and measures at 0,0 first so popups inside transformed containers land right. It sets `data-side`, `data-align`, `--available-height`, `--available-width`, `--anchor-width`, `--anchor-height` and `--transform-origin`. The two `--available-*` variables are registered as not inherited, so a scroll restyles the popup and not every item in it; a child that needs them copies the value on the popup. Extend it there rather than adding a library.
- **Presence:** `mounted` is render state, separate from `open`. `createPopup` calls `animateIn(el)` on bind and `animateOut(el, done)` on close, which has a timeout and sets `inert` while exiting. Core writes a part's state attribute before `animateOut`, so exit keyframes keyed on `data-closed` play; a new part that animates out does the same.
