# Skills

These skills help you and your agent work on ui-sdk itself. Each one is a folder with a `SKILL.md` written in plain Markdown, so it works in any agent harness.

| Skill                                                   | Use it when                                                                                      | How to run it                                                                                        | What it does                                                                                                                                                                                          |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [`ui-sdk-write-code`](ui-sdk-write-code/SKILL.md)       | You write or change code anywhere in the repo: core, an adapter, an example, a spec or a script. | `/ui-sdk-write-code`, or ask "write this the ui-sdk way".                                            | Starts from the file that already does the same job, loads the framework expert's notes, writes the code, then runs the linters, type checks and tests your change reaches and rereads the diff cold. |
| [`ui-sdk-write-docs`](ui-sdk-write-docs/SKILL.md)       | You write or review website docs, including guides and component pages.                          | `/ui-sdk-write-docs`, or ask to write or review a docs page.                                         | Follows the current writing guide and comparable pages, checks API behavior, and verifies the changed prose and examples.                                                                             |
| [`ui-sdk-unslop`](ui-sdk-unslop/SKILL.md)               | You're finishing a change, or a file reads as generated.                                         | `/ui-sdk-unslop`, or ask "clean up this diff". Pass files to go beyond the diff.                     | Removes comments that restate the code, filler JSDoc, defensive checks the types rule out, one-caller helpers and vague names. Behavior stays the same.                                               |
| [`ui-sdk-expert-review`](ui-sdk-expert-review/SKILL.md) | Before you merge a change to an adapter, core, the specs, examples or framework docs.            | `/ui-sdk-expert-review`, with a base ref (`origin/main`), framework names (`svelte vue`) or nothing. | Finds which framework experts the change reaches, runs each framework's lint rules, asks those experts to review, and hands you one table of findings.                                                |

For code, write with `ui-sdk-write-code`, finish with `ui-sdk-unslop`, then run `ui-sdk-expert-review` before you merge. For website documentation, use `ui-sdk-write-docs`; it also loads the code conventions when writing examples.

The skills live in `.agents/skills/`, where Codex, Cursor, Gemini CLI and GitHub Copilot find them, and `.claude/skills` links to the same folder for Claude Code. Type a skill's name as a slash command, or describe the task and the skill loads on its own. In a harness that doesn't load skills, ask your agent to read the skill's `SKILL.md` and follow it.

Building an app with ui-sdk rather than working on it? The skill for that is [`ui-sdk-create-component`](../../packages/core/skills/ui-sdk-create-component/SKILL.md). It builds a component ui-sdk doesn't ship from `@ui-sdk/core`.
