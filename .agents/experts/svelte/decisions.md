# Svelte expert: decisions

What's already decided about `@ui-sdk/svelte`, and what's known and open. The expert never re-raises a **Settled** item as a finding.

## Settled

- **Hand-written components on `useHandlePart`**, with `usePart` as the public wrapper, not generated by `createParts`. Drift between the two is tracked, not a finding.
- **`render` snippets** are the only way to render your own element and get the part's own content as `children`. No `as`.
- **Bindable props are controlled whenever defined**; a value passed without `bind:` only sets where the component starts.
- **Handlers go on the component**, not on the `render` snippet's element: Svelte's delegation runs markup handlers after the built-in one, so they can't cancel it. Not fixable without Svelte's private symbol.
- **Form component dropped.**
- **CSP nonce**: a page sets it with `<meta property="csp-nonce" nonce="…">`. A tag with no nonce switches injected styles to constructed sheets, and the page declares `@layer ui-sdk;` first. (Chosen for PR 17, 2026-10-28.)
- **Popups flip to the opposite side only**, never to a perpendicular one.
- **`tests/specs/position.spec.ts` runs once per engine**, on `react` in Chromium and `web` elsewhere: the placement math is core's and doesn't depend on the framework.
- **A half-typed date reads `null`.** Writing `null` back leaves its segments, so a controlled value can't empty them; `clear()` does. Same in every framework.

- **`web.css` lets parts inherit the page's font.** `--ui-font-sans` is a token a page opts into on `body`; parts never set `font-family` themselves, except `code` and `kbd`, which use `--ui-font-mono`.
- **`web.css` colors follow the page's `color-scheme` through `light-dark()`.** Builds that rewrite `light-dark()` (Lightning CSS in Next and Vite) read the `--lightningcss-light`/`--lightningcss-dark` defaults `web.css` sets, so they fall back to light unless the build also processes a `color-scheme`.
- **Button-like parts render `type`, `disabled` and `aria-disabled` together until they bind**, and no role, so server HTML is right for a `<button>` and an `<a>`. On an `<a>` or `<span>`, `type` and `disabled` are invalid but inert until then, and a disabled link still navigates before hydration, since only script can stop the click. Before bind they don't write `tabindex`, so a web component's author tabindex survives the first pass (PR 326, 2026-11-09).
- **Timeline's server markup holds the tab stop on the first event**, not the current one, until it hydrates. An earlier item can't know a later item is current, so a claim can't move it there without leaving some lists with no stop; the docs say so.

## Known and open (don't report again, check whether fixed)

- `bindScrollPicker`'s pointer listeners are on the list itself, so a delegated `onpointerdown` on `<Listbox>` runs after them. Page keys listen on the document and can be canceled.
- **A trigger connected through `controller` renders without `data-slot` or state attributes on the server**, so `web.css` leaves it unstyled until hydration (`select/controller`, PR 321).

- **Other outros**: portaled popups, separate `in:`/`out:` and custom components in `render` weren't probed.
- **Parts hear every change** unless `selects` narrows them.
- **`menu-trigger-binding.svelte`** calls `use(feature)` inside `$derived.by`. Idempotent, but not idiomatic.
- **Payload types**: a popup content's payload type is asserted by the user, not tied to the controller's type.
- **A Checkbox in its own Field inside a CheckboxGroup** is unnamed in server markup until hydration.
- **A popup stays shown when its anchor is clipped by a scroll container.** A marker like `data-anchor-hidden` is a public API and waits on discussion.
- **An anchor moved by the Web Animations API** is followed by positioning's 500ms slow check, not on the next frame.
- **A Combobox with `bind:value` records a relay on `query`** when the user types and presses Enter, from setting the input's text inside the handover (on main since `d9c0141`). No playground fixture binds a Combobox's value.
- **Data lists key separators and groups by index** (`command-items.svelte`, `listbox-items.svelte`), so a separator that comes back shifts the keys and a `CommandGroup` instance can be reused for another group.
- **Tabs with panels before the list** (a bottom tab bar) render the first tab selected and no panel on the server. A panel renders before its tab has props, so it can't tell it's the one shown. It appears once the tabs bind.
- **Select, Combobox, Autocomplete and TokenInput take no `readonly`**: they render no element and have no `...rest`, so `svelte-check` reports it. `readOnly` is the prop.
- **An author id on a control in a Field** (every control that joins one, like `NumberInputControl id`, `Checkbox id` or a range `Slider id`) isn't in the server HTML's label `for`, nor in a step button rendered before it: they can't read an id that renders after them. Putting the `id` on the `Field` works. It's right once the field binds.
- **A submit shortcut also submits a read-only Textarea.**
- **Holding Enter submits on every key repeat** with a submit shortcut: it doesn't skip `event.repeat`.
- **`submitShortcut="enter"` leaves phones no way to add a line**: a soft keyboard has no Shift+Enter, and the textarea sets no `enterkeyhint`.
- **A Slider in a Field without a FieldDescription** points the range input's `aria-describedby` at a description id that isn't rendered, in server markup until hydration. The server can't know which parts render after the control.
- **A Slider in a Field that switches between a range and one thumb** keeps the field's control it started with (`slider.svelte` decides `isRange` once). Range to one thumb gives the root and the thumb's input the same id and the label no `for`; one thumb to a range points the label at the last thumb's input. Same on main.
- **Timeline items have no name or feed position before hydration.** `aria-labelledby`, `aria-describedby`, `aria-posinset` and `aria-setsize` are live attributes written once the parts bind; pointing at a title id on the server would reference ids that may not exist.
- `waterfall-row.svelte` writes the `() => ({ value })` getter twice, for the row context and for `usePart`. Cosmetic.
