---
title: Dev Server
description: Let the agent building your app read and use its page while you develop.
---

An agent that writes your UI usually works from the code alone. Add ui-sdk to your dev server, and the agent can try the page too: open the dialog it just built, choose an option in a select, and read what changed.

It uses the same three tools as [Connect an Agent](./connect-an-agent): `snapshot`, `act` and `query`. Your dev server answers them at `/__ui-sdk/mcp`, an MCP server your agent connects to like any other. Each call runs in the page you have open in the browser, on the real components, and the result goes back to the agent.

## Set Up Your Framework

Each framework needs two things: the MCP server on its dev server, and a connection from the page. Both run only in development, so your production build stays the same.

### Next.js

Wrap your config with `withUiSdk`:

```ts title="next.config.ts"
import type { NextConfig } from "next"
import { withUiSdk } from "@ui-sdk/react/next"

const nextConfig: NextConfig = {}

export default withUiSdk(nextConfig)
```

Under `next dev`, it starts the server and serves it from your app's own port. Then connect the page from `instrumentation-client.ts`, which runs in the browser before your app starts:

```ts title="instrumentation-client.ts"
if (process.env.NODE_ENV === "development") import("@ui-sdk/core/dev")
```

### Vite

For React, Vue, Svelte, Solid and web components on Vite, add the plugin:

```ts title="vite.config.ts"
import { uiSdk } from "@ui-sdk/core/vite"
import { defineConfig } from "vite"

export default defineConfig({
  plugins: [uiSdk()],
})
```

The plugin adds the server and connects every page Vite serves. Keep your framework's own plugin in the list beside it.

### Nuxt

Add the module:

```ts title="nuxt.config.ts"
export default defineNuxtConfig({
  modules: ["@ui-sdk/vue/nuxt"],
})
```

Under `nuxt dev`, the module adds the server and connects every page.

### SvelteKit

Add the plugin beside `sveltekit()`:

```ts title="vite.config.ts"
import { sveltekit } from "@sveltejs/kit/vite"
import { uiSdk } from "@ui-sdk/core/vite"
import { defineConfig } from "vite"

export default defineConfig({
  plugins: [sveltekit(), uiSdk()],
})
```

### Other Frameworks on Vite

SolidStart, Astro and other frameworks built on Vite take the same plugin, even when they render their own pages. In Astro, it goes in the Vite plugins of your config:

```js title="astro.config.mjs"
import { uiSdk } from "@ui-sdk/core/vite"
import { defineConfig } from "astro/config"

export default defineConfig({
  vite: { plugins: [uiSdk()] },
})
```

## Connect Your Agent

Start your dev server and open the app in your browser. Then add the server to your agent with your dev server's address. For Claude Code:

```bash
claude mcp add --transport http ui-sdk http://localhost:3000/__ui-sdk/mcp
```

For fx:

```bash
fx mcp add ui-sdk http://localhost:3000/__ui-sdk/mcp
```

`fx mcp show ui-sdk` checks the connection and lists the three tools.

For Codex:

```bash
codex mcp add ui-sdk --url http://localhost:3000/__ui-sdk/mcp
```

Other agents take the same URL wherever they add an MCP server. Use your dev server's port: `3000` for Next.js and Nuxt, `5173` for Vite and SvelteKit.

## Try It

Ask the agent to build something small, then use it:

```text
Add a settings form with a Region select that offers North America,
Europe and Asia Pacific. Open it in the browser tab, use the ui-sdk
tools to choose Asia Pacific, then tell me what the form shows.
```

The agent builds the form, then calls `query` to find the Region select and its options, then `act` to choose one. The result lists every field's value after the change, so the agent can check its work in the same step. You see the select change in your browser as it happens.

With more than one tab open, the tab you opened last answers. A component marked with `data-agent-confirm` stays yours to change: the agent gets a note to ask you instead. [Permissions](./connect-an-agent/permissions) covers the marks.
