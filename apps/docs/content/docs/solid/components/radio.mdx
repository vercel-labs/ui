## Installation

```bash
npm install @ui-sdk/solid @ui-sdk/core
```

## Usage

Give each radio a `value` and put it inside a named `RadioGroup`. The group's value is the checked radio's value. Without `defaultValue`, nothing starts checked and Tab enters on the first enabled radio.

<span id="composition" />

```tsx
import { Radio, RadioGroup, RadioIndicator } from "@ui-sdk/solid/radio"

function Example() {
  return (
    <RadioGroup defaultValue="comfortable" aria-label="Density">
      <label>
        <Radio value="comfortable">
          <RadioIndicator />
        </Radio>{" "}
        Comfortable
      </label>
      <label>
        <Radio value="compact">
          <RadioIndicator />
        </Radio>{" "}
        Compact
      </label>
    </RadioGroup>
  )
}

export { Example }
```

Each radio renders a button with `role="radio"` and a hidden native radio that handles forms. Wrap a radio in a label, or connect a separate label with `for` and `id`.

## Behavior and Options

### Controlled

Pass `value` and update its signal in `onValueChange`. Call `details.cancel()` in the callback to keep the current value.

Create a controller with `createRadioGroupController` from `@ui-sdk/solid/radio` and pass it as `controller` to check a radio from another button. Create one controller per mounted group.

<ComponentExample
  name="radio/controlled"
  caption="Choose Starter, then Choose Team. The status shows the selected value and the reason for each change."
/>

See [State and Events](../state-and-events) for controlled state, cancellation and debugging.

### Read Only

Set `readOnly` on the group to keep the value fixed while letting users focus and read the options. Arrow keys still move focus. The current value still submits with a form.

<ComponentExample
  name="radio/read-only"
  caption="Move focus from Pro to Team, or click Team. Pro remains checked."
/>

### Form

Set `name` to submit the selected value. `required` blocks submission until there is a choice. A form reset returns to `defaultValue`.

The demo keeps the group outside its form and connects them with the form's `id` through the group's `form` prop.

<ComponentExample
  name="radio/form"
  caption="Choose Express and Submit to see the form value. Reset returns the choice to Standard."
/>

### Horizontal

Use your own layout classes to put radios in a row or column. There is no orientation option: arrow keys work on both axes, like native radios.

### Loop

Arrow keys wrap from the last radio to the first. Set `loop` to `false` to stop at the ends.

<ComponentExample
  name="radio/loop"
  caption="Focus Low and press Up, or focus High and press Down. Focus stays at that end of the group."
/>

### Indicator

The indicator is present while its radio is checked. It stays mounted during an exit animation, then unmounts. Set `keepMounted` to keep it present while unchecked too.

Use `data-starting-style` and `data-ending-style` for entry and exit animations. The demo also uses the kept indicator to preview an unchecked option on hover.

<ComponentExample
  name="radio/indicator"
  caption="Hover an unchecked theme to preview its dot, then choose it. Reduced-motion settings skip the transition."
/>

### Render Functions

Use `render` to choose a part's element and read its state. Spread the supplied props onto the element that handles the behavior. This demo makes each radio a full row with an icon, description and checked marker.

## Forms

The hidden native radios handle submission, reset and validation in a plain form. The group submits nothing without a `name` or a checked option. Enter on a radio submits its form; Space checks the focused option.

Use [Field](./field) for inline validation and the [Forms guide](../forms) for shared form behavior.
