## Installation

```bash
npm install @ui-sdk/svelte @ui-sdk/core
```

## Composition

Use the following composition to build a `Resizable`:

```text
Resizable
├── ResizablePanel
├── ResizableHandle
└── ResizablePanel
```

Put a handle between the panels you want to resize.

- **Resizable** is the group. It lays its panels out in a row, or a column with `orientation="vertical"`, so give it a size: a vertical group needs a height.
- **ResizablePanel** is one region. Its size is a percentage of the space panels share, written to `--resizable-panel-size` and used as its flex basis.
- **ResizableHandle** sits between two panels. It's a focusable separator whose value is the size of the panel before it, and dragging it or pressing arrow keys resizes the panels on either side.

A group nests inside a panel, for layouts like an editor beside a terminal. Name each handle with `aria-label`, like "Resize sidebar".

## Examples

### Vertical

Set `orientation="vertical"` to stack the panels. ArrowUp and ArrowDown move the handle. Every part gets `data-orientation`, and the handle's `aria-orientation` is the other direction, since it runs across the group, so style a horizontal handle with `aria-[orientation=horizontal]:`.

### Handle

Put anything inside a handle, like a grip that shows it can be dragged. The handle can stay a thin line: its hit area is at least 10 pixels across, centered on it, and 24 for touch, without any styles.

<ComponentExample
  name="resizable/handle"
  caption="Grab the visible grip or focus the handle and use the arrow keys."
/>

### Collapsible

`collapsible` lets a panel collapse below its `minSize` to `collapsedSize`, 0 by default: by dragging past the midpoint to its collapsed size, with Enter or a double-click on its handle, or through the controller. Dragging back past the same point opens it at its minimum, and Enter restores the size it had. A collapsed panel gets `data-collapsed`, and at size 0 its content leaves the tab order and the accessibility tree.

<ComponentExample
  name="resizable/collapsible"
  caption="Drag the sidebar closed, or focus its handle and press Enter to collapse and restore it."
/>

### Sizes in Pixels

Sizes are percentages as numbers, or strings with `%`, `px` or `rem`. Pixel and rem bounds hold as the group resizes, so a navigation with `minSize="160px"` never gets narrower, and a change they cause reports the `resize` reason.

`defaultLayout` sets every panel's size at once, in order. Panels without `defaultSize` share what's left evenly otherwise.

## Behavior and Options

### Controlled

Bind `layout` with `bind:layout` to control the group. `onLayoutChange` receives the details too.
`layout={x}` without `bind:` is a starting value the group may change until `x` changes. Bind it with
`bind:layout={x}` to keep them together, or with a function binding,
`bind:layout={() => x, (next) => (x = next)}`, to decide.
The layout is one percentage per panel, in order, adding up to 100. Every change carries a reason, like
`drag`, `step-key` or `collapse`, and `details.cancel()` keeps the current layout.

<ComponentExample
  name="resizable/controlled"
  caption="Resize a panel to see the layout values held by the application."
/>

### Saving on Complete

`onLayoutChange` runs on every frame of a drag. `onLayoutCommit` runs
once, when the interaction that changed the layout ends: the pointer lifts, the key comes up, or a panel
collapses. Save there.

<ComponentExample
  name="resizable/complete"
  caption="Resize a panel, then release the pointer or key. The saved layout updates when the interaction ends."
/>

### Persistence

`autoSaveId` saves the layout in `localStorage` when an interaction completes and restores it when the group attaches in the browser. Server markup starts with the default sizes. Each set of panels keeps its own layout, so a panel that comes and goes gets its sizes back. Give panels an `id` so the saved layout survives changes elsewhere on the page.

<ComponentExample
  name="resizable/persistence"
  caption="Resize the sidebar, then reload this page to restore its saved layout."
/>

### Storage

`storage` takes anything with `getItem` and `setItem`. A server can't read `localStorage`, so it renders each panel's `defaultSize` and the saved layout arrives when the page hydrates. To render the saved layout on the first paint, keep it in a cookie, named by `resizableStorageKey(autoSaveId)`, and pass the sizes back as each panel's `defaultSize`. This example keeps the layout for the tab's session instead:

### Controller

A controller, from `createResizableController()`, collapses, expands and resizes panels from anywhere, by id or index, and reads the layout with `getLayout()`. Changes it makes report the `imperative` reason.

<ComponentExample
  name="resizable/controller"
  caption="Use Collapse, Expand, 240px, and Read to operate the panels through their controller."
/>

### Keyboard

Focus a handle and press the arrow keys along the group's axis to move it by `step`, 1% by default, or with Shift by `largeStep`, 10%. Home and End move it as far as the panels allow, and Enter collapses or restores the panel beside it. A panel at its minimum passes the rest of a move on to the next one.

<ComponentExample
  name="resizable/keyboard"
  caption="Focus a handle and try arrows, Shift with an arrow, Home, and End."
/>

### Disabled

`disabled` on a handle fixes it in place. On the group it fixes every handle. Disabled handles leave the tab order, and their panels keep their sizes. A disabled `<fieldset>` around the group fixes every handle too.

<ComponentExample
  name="resizable/disabled"
  caption="The first handle stays fixed. Use the other handle to resize the remaining panels."
/>

### Render Functions

Every part takes a `render` snippet, which receives the props to spread and the
part's state, like a panel's `size` and whether it's `collapsed`, or whether a handle is `dragging` or
`hovering`, and the `children` snippet receives the state.

<ComponentExample
  name="resizable/render"
  caption="Resize Files or collapse it to see its size and state in the panel."
/>

The primitive writes drag sizes directly to panel styles. Reading `size` or `layout` in a render function, slot, or snippet also subscribes that part to updates during the drag.

## Styling

Parts are unstyled, apart from the layout they need: the group is a flex row or column, panels take their size as a flex basis, and handles don't shrink and take `touch-action: none`. While a handle is hovered or dragged, its cursor shows over the whole page, and points the only way it can go at a limit.

### Events

Callbacks get the new layout first, then the details. A bound `layout` only updates when `onLayoutChange` wasn't canceled.

| Prop             | On          | Receives                                                       |
| ---------------- | ----------- | -------------------------------------------------------------- |
| `bind:layout`    | `Resizable` | The layout: one percentage per panel                           |
| `onLayoutChange` | `Resizable` | `(layout, details)`: the new layout and the [reason](#reasons) |
| `onLayoutCommit` | `Resizable` | `(layout, details)`: the layout once the interaction ends      |

## Accessibility

Handles follow the [WAI-ARIA window splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/). Each is a focusable `separator` whose `aria-valuenow` is the size of the panel before it, with `aria-valuemin` and `aria-valuemax` as far as the panels allow, `aria-controls` pointing at that panel, and `aria-orientation` running across the group.
