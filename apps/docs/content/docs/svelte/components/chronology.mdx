Use a Chronology for a list of things that happened, or will: a project's activity, an order's status history, a release's milestones. It's a list for screen readers, with one tab stop for keyboards, and the arrow keys move between events.

<ComponentExample
  name="chronology/demo"
  caption="Tab into the activity, then use Up and Down to move between events. Home and End jump to the first and last."
/>

## Installation

```bash
npm install @ui-sdk/svelte @ui-sdk/core
```

## Composition

Use the following composition to build a `Chronology`:

```text
Chronology
├── ChronologyItem
│   ├── ChronologyMarker
│   ├── ChronologyConnector
│   ├── ChronologyTitle
│   ├── ChronologyTime
│   └── ChronologyDescription
└── ChronologyItem
```

Every part inside an item is optional. `ChronologyMarker` is the dot or icon on the line, and `ChronologyConnector` the line to the next event. Both are hidden from screen readers, so they're only for looks.

## Usage

Import the parts and put them together:

```svelte
<script lang="ts">
  import {
    Chronology,
    ChronologyConnector,
    ChronologyDescription,
    ChronologyItem,
    ChronologyMarker,
    ChronologyTime,
    ChronologyTitle,
  } from "@ui-sdk/svelte/chronology"
</script>

<Chronology aria-label="Activity">
  <ChronologyItem>
    <ChronologyMarker />
    <ChronologyConnector />
    <ChronologyTitle>Deployed to production</ChronologyTitle>
    <ChronologyTime datetime="2026-11-10T14:32">2:32 PM</ChronologyTime>
    <ChronologyDescription>Version 2.4.1 is live.</ChronologyDescription>
  </ChronologyItem>
</Chronology>
```

`Chronology` renders a `<div>` with the `list` role and each item a `<div>` with the `listitem` role, so the same markup can become a feed. Pass `datetime` to `ChronologyTime`, so the date is machine readable while the text stays friendly.

When focus lands on an event, screen readers read its title as its name, then its time and description. Links and buttons inside an event stay in the tab order: Tab moves from the event to them, and arrow keys pressed on them stay with them.

## Horizontal

Set `orientation="horizontal"` for a row, like a roadmap. Left and Right move between events instead of Up and Down, and they swap in right-to-left text. Set `loop={false}` to stop at either end.

## Status

Give each item a `status` of `"complete"`, `"current"` or `"upcoming"` for a process, like an order's progress. The current event gets `aria-current="step"`, and Tab lands on it first. Every part of an event shows its status with `data-complete`, `data-current` or `data-upcoming`.

Create a controller with `createChronologyController` and call its `focus()` with an item's `value` to move focus to it from anywhere.

<ComponentExample
  name="chronology/status"
  caption="Tab into the order status. Focus starts on Shipped, the current step. Move away, then choose Go to Current Step."
/>

A marker shows status only to sighted people. When the status matters, say it in the title or description too, like "Shipped, in progress".

## Details

Put a [Collapsible](./collapsible) inside an item for details that can open. Its trigger is a button inside the event, so Tab reaches it after the event, and arrow keys still move between events.

## Feed

Set `feed` for a timeline that loads more as people scroll, like a social feed. It follows the [WAI-ARIA feed pattern](https://www.w3.org/WAI/ARIA/apg/patterns/feed/): the root becomes a `feed` and each item an `article` with its position and the count, and Page Down and Page Up move between articles from anywhere inside one.

Set `busy` while you load or change articles. It sets `aria-busy`, so screen readers wait for the new articles before reading on.

<ComponentExample
  name="chronology/feed"
  caption="Tab into the updates and press Page Down. Choose Load More: the feed is busy until three more updates arrive. The console logs each load."
/>

Use a list for most timelines. A feed is for long lists that grow, where a screen reader's reading mode should flow from one article to the next.

## Custom Rendering

Render any part as another element with a `render` snippet, like a title as a heading so people can move between events by heading. The snippet must spread its `props` onto the element:

```svelte
<ChronologyTitle>
  {#snippet render({ props })}
    <h3 {...props}>Deployed to production</h3>
  {/snippet}
</ChronologyTitle>
```

[Parts and Composition](../parts-and-composition) explains the rendering contract.

## Styling

The parts have no styles. Lay an item out as a grid, with the marker in its own column and the connector positioned along it. `data-orientation` on every part says which way the events run.

Use `data-first` and `data-last` on items to hide the connector after the last event. They're written once the events are in the page; for markup rendered on the server, `:last-child` does the same before it hydrates.

Each part has a `data-slot`, such as `chronology-marker`, and its state attributes are listed under [Data Attributes](#data-attributes).

`Chronology` writes `--chronology-count`, how many events it holds, and each `ChronologyItem` writes `--chronology-index`, its place from 0. Use them for a horizontal row's grid columns, or to stagger an animation.

## Accessibility

A chronology is a `list` of `listitem`s, named with `aria-label`. With `feed`, it follows the [WAI-ARIA feed pattern](https://www.w3.org/WAI/ARIA/apg/patterns/feed/): a `feed` of `article`s, each with `aria-posinset` and `aria-setsize`, and `aria-busy` while it loads. Each event is named by its title through `aria-labelledby` and described by its time and description through `aria-describedby`. The current event has `aria-current="step"`.

### Keyboard

The events have one tab stop, a roving focus. Tab enters on the current event, else the first, then returns to the event focused last.

| Key                        | Action                                                     |
| -------------------------- | ---------------------------------------------------------- |
| `ArrowDown` / `ArrowUp`    | Move focus between events in a vertical chronology         |
| `ArrowRight` / `ArrowLeft` | Move focus between events in a horizontal chronology       |
| `Home` / `End`             | Focus the first or last event                              |
| `PageDown` / `PageUp`      | In a feed, focus the next or previous article, from inside |
| `Tab`                      | Move from an event to the links and buttons inside it      |

Arrow keys move only from an event itself, so controls inside keep them. In right-to-left text, Left and Right swap.
