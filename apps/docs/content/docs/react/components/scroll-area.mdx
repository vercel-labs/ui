
The examples use the shared [Example Theme](../styling-and-animation#example-theme).

## Anatomy

Put the content inside a viewport, then add a scrollbar for each axis you want to style.

```tsx
"use client"

import {
  ScrollArea,
  ScrollAreaViewport,
  ScrollAreaContent,
  ScrollAreaScrollbar,
  ScrollAreaThumb,
} from "@ui-sdk/react/scroll-area"

function ReleaseNotes() {
  return (
    <ScrollArea>
      <ScrollAreaViewport role="region" aria-label="Release notes">
        <ScrollAreaContent>Content to scroll</ScrollAreaContent>
      </ScrollAreaViewport>
      <ScrollAreaScrollbar orientation="vertical">
        <ScrollAreaThumb />
      </ScrollAreaScrollbar>
    </ScrollArea>
  )
}

export { ReleaseNotes }
```

The viewport is the real scroller. Give the root a size and the viewport `size-full`. Scrollbars sit over the viewport's edges. A thumb appears when its axis overflows; [`type`](#when-scrollbars-show) controls when the scrollbar is visible. Render only the scrollbars you want: with none, the browser's own scrollbars stay.

### Chat and Streaming

Set `stickToEnd` for a chat, a log, or a streamed answer. The scroll area starts at the bottom and keeps it in view while content grows: new messages, words streaming into the last one, and images that load late, whose size it watches.

- Scroll away from the end to stop following. This happens as soon as you wheel, press a scroll key, touch, or drag upward, so incoming content cannot pull you back in the same frame.
- Scroll to the bottom or press `ScrollAreaScrollToEnd` to follow again. The root has `data-sticking` while it follows.
- Following pauses while you hold a pointer in the viewport, including when selecting text, and catches up when you release it.

Following scrolls only this viewport, without flashing the scrollbars. Jump to latest animates toward the end as content grows and moves immediately when reduced motion is requested.

`ScrollAreaScrollToEnd`, follows again. `data-sticking` is on the root while it follows.

- **It never moves anything else.** It scrolls the viewport itself, never the page around it, and doesn't mark the scrollbars as scrolling, so they don't flash while text streams in.
- **It waits for you.** While a mouse button is down in the viewport, like while selecting text, or a finger is on it, growth doesn't move the content. It catches up when you let go.
- **Smooth scrolling.** `scroll-behavior: smooth` on the viewport doesn't slow it down. "Jump to latest" eases there, following content that keeps growing, and jumps at once for people who prefer reduced motion.

`ScrollAreaScrollToEnd` is a button that has `data-visible` while the view is away from the end, and is inert otherwise, so it can fade out without taking focus. Name it with its content. When it's pressed from the keyboard, focus moves to the viewport, since the button goes inert.

### Edge Fades

The root holds how far the content reaches past each edge, as `--scroll-area-overflow-y-start`, `--scroll-area-overflow-y-end` and their `x` versions, and how far along the view is, as `--scroll-area-progress-y` and `-x`. A fade as tall as `min(2rem, var(--scroll-area-overflow-y-start))` is gone at the top and full once there's more above. For a fade that only switches, use `data-at-y-start` and `data-at-y-end`.

These variables aren't inherited, so scrolling restyles the root and never the content. An element that reads one takes it from the root with `inherit`, like the fades here, which are children of the root: `[--scroll-area-overflow-y-start:inherit]`. The first scroll area registers the six names for the whole page with `CSS.registerProperty`. A page that needs them to inherit calls it first, with `inherits: true`. An `@property` rule can't, since a registration in script wins.

## Behavior and Options

### When Scrollbars Show

`type` decides when each scrollbar gets `data-visible`:

| `type`              | Shows                                                         |
| ------------------- | ------------------------------------------------------------- |
| `"hover"` (default) | While the pointer is over the scroll area, or while scrolling |
| `"scroll"`          | While its own axis scrolls, or its thumb is dragged           |
| `"auto"`            | Whenever the content overflows on its axis                    |
| `"always"`          | Always, even when the content fits, with no thumb then        |

Style the attribute, like `opacity-0 data-visible:opacity-100`. A hidden scrollbar ignores the pointer, so it never catches presses meant for the content under it.

### Hide Delay

With `"scroll"` and `"hover"`, `scrollHideDelay` keeps a scrollbar for a while after scrolling stops or the pointer leaves, in ms. It defaults to 600.

<ComponentExample
  name="scroll-area/hide-delay"

### Pointer

- **Dragging the thumb** moves the content as far along as the thumb moves along its track. Text doesn't get selected, scroll snapping pauses until the pointer lifts, and Escape puts the content back where the drag started.
- **Pressing the track** pages toward the pointer, by most of a viewport, like a native scrollbar, and keeps paging while it's held until the thumb reaches the pointer. With Alt (Option on a Mac), it jumps there and drags instead.
- **A wheel over a scrollbar** scrolls the viewport as far as it would over the content, and the page once the viewport can't scroll further.
- **Pressing a scrollbar** never moves focus.

### Keyboard and Screen Readers

The viewport scrolls natively, so arrow keys, Page Up and Down, Home, End and Space work once focus is inside it. A viewport that scrolls and holds nothing focusable is a tab stop itself, so keyboard users can reach it; one with links or fields inside isn't, since Tab reaches them and they scroll it. Scrollbars and the corner are hidden from screen readers, which scroll the viewport themselves. Make the viewport a landmark with `role="region"` and an `aria-label` when it's worth finding, or give a chat `role="log"`.

## Custom Rendering

Every part takes `render`, to render a different element or component in its place, like `render=
{<section />}`. `render`, `className`, `style` and `children` can be functions of the part's state:
`className={(state) => (state.atStart ? "" : "shadow-sm")}`.

Read a part's state to update its content or styles when that state changes. See [Parts and Composition](../parts-and-composition) for the rendering contract and [State](#state) for each part's fields.
