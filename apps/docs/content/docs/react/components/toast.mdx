## Installation

```bash
pnpm add @ui-sdk/react @ui-sdk/core
```

## Usage

Mount `OverlayHost` once near your app's root, then call `toast()` when an action finishes. The host renders the notification. This small example shows the connection:

```tsx
import { OverlayHost } from "@ui-sdk/react/overlays"
import { Toast, ToastTitle, toast } from "@ui-sdk/react/toast"

function App() {
  return (
    <>
      <button type="button" onClick={() => toast("Changes saved")}>
        Save
      </button>
      <OverlayHost
        toast={{
          expanded: true,
          className: "m-4 flex w-80 max-w-[calc(100vw-2rem)] flex-col gap-2 outline-none",
          children: () => (
            <Toast className="rounded-2xl bg-white p-4 text-sm text-neutral-950 shadow-lg ring-1 ring-neutral-950/5">
              <ToastTitle />
            </Toast>
          ),
        }}
      />
    </>
  )
}

export { App }
```

The `toast.children` function renders each toast. Put your classes directly on the returned parts.

You can also place a `ToastRegion` yourself. It takes over rendering for its toaster. Use `createToaster()` for an independent queue, as the demos below do.

## Composition

Use the following composition to build a `ToastRegion`:

```text
ToastRegion
└── Toast
    ├── ToastTitle
    ├── ToastDescription
    ├── ToastAction
    └── ToastClose
```

The region groups notifications. A toast gets its name from its title and its description from the description part. Empty title, description, and action parts show the corresponding text from the toast data.

Render the parts yourself to style them. A region without a custom renderer uses unstyled parts.

## Examples

### Types

`success`, `info`, `warning`, `error`, and `loading` set the toast's type. Types expose `data-type` for your renderer. Errors are announced immediately by default; loading toasts stay until updated or dismissed. You can override the announcement priority.

### Stacking

`max` limits how many notifications are visible; the rest wait in the queue. Their timers start when they become visible. Set `expanded` to keep the stack open, or let it expand while hovered or focused.

The demo uses `--toast-index`, `--toast-offset`, `--toast-front-height`, `data-front`, and `data-expanded` to arrange the stack.

### Duration

Set `duration` in milliseconds, or use `Infinity` for a notification that stays until dismissed. Timers pause while the pointer or focus is in the region and while the page is hidden or its window is inactive.

## Accessibility

Keep messages short and include an action when someone needs to respond. Use `duration: Infinity` when a message must remain available. Notifications use shared live regions, so they are announced once without making the whole toast region live.

The region remains reachable while a modal dialog is open. Tab moves through its controls, and focus returns when the last focused toast closes. Pair your transitions with `motion-reduce:` styles.

## API Reference

### Toast

<TypeTable path="../../packages/core/src/components/toast/toaster.ts" name="ToastOptions" events={false} />
