Parts render without styles. The component demos use Tailwind CSS, but the same state attributes and CSS variables work with any stylesheet.

## Style a Part

Every part has a `data-slot` attribute. State adds attributes such as `data-open`, `data-pressed`, or `data-disabled`:

```tsx
import { Toggle } from "@ui-sdk/react/toggle"

function Example() {
  return (
    <Toggle className="cursor-default rounded-2xl border border-input px-2.5 py-1.5 text-sm data-pressed:bg-muted data-disabled:opacity-50">
      Bold
    </Toggle>
  )
}

export { Example }
```

Most state attributes are present or absent. Others have values, such as `data-side="top"` or `data-orientation="vertical"`. Each component's Styling section lists its attributes and CSS variables. Use these rather than generated IDs, which can change.

## CSS Modules

Import a CSS Module and pass its class to the part. State selectors work the same way:

```tsx
import { Toggle } from "@ui-sdk/react/toggle"
import styles from "./toggle.module.css"

function Example() {
  return <Toggle className={styles.toggle}>Bold</Toggle>
}

export { Example }
```

```css title="toggle.module.css"
.toggle {
  cursor: default;
  border: 1px solid var(--input, #e5e5e5);
  border-radius: 1.125rem;
  background: transparent;
  padding: 0.375rem 0.625rem;
  color: inherit;
  font: inherit;
  font-size: 0.875rem;
}

.toggle[data-pressed] {
  background: var(--muted, #f5f5f5);
}

.toggle[data-disabled] {
  opacity: 0.5;
}

.toggle:focus-visible {
  outline: 2px solid var(--ring, #a3a3a3);
  outline-offset: 2px;
}
```

## Use State in React

`className` and `style` can be functions of the part's state:

```tsx
"use client"

import { Toggle } from "@ui-sdk/react/toggle"

function Example() {
  return <Toggle className={(state) => (state.pressed ? "font-bold" : "font-normal")}>Bold</Toggle>
}

export { Example }
```

With Tailwind, you can also use attribute variants, such as `data-pressed:font-bold`.

## Animate Opening and Closing

Popup content gets `data-starting-style` before it enters and `data-ending-style` while it exits. The content stays mounted until its exit transition or animation finishes.

```tsx
import { Popover, PopoverContent, PopoverTrigger } from "@ui-sdk/react/popover"

function Example() {
  return (
    <Popover>
      <PopoverTrigger>Details</PopoverTrigger>
      <PopoverContent
        aria-label="Project details"
        className="origin-(--transform-origin) transition-[opacity,scale] duration-150 data-starting-style:scale-96 data-starting-style:opacity-0 data-ending-style:scale-96 data-ending-style:opacity-0 motion-reduce:transition-none"
      >
        Last updated today.
      </PopoverContent>
    </Popover>
  )
}

export { Example }
```

Put exit styles on `data-ending-style`. `data-closed` describes the state, but doesn't keep the element around for an exit.

Popups also provide `--anchor-width` and `--available-height` for sizing. If an animation library needs closed content to stay mounted, use `keepMounted`. See [Popups](./popups) for placement and mounting options.

## Content Security Policy

A few behaviors need a little CSS, like keeping a closed popup hidden or dimming the page behind a sheet, so ui-sdk adds it to the page. It goes before your own styles, in a cascade layer named `ui-sdk`, so your styles win.

A Content Security Policy without `'unsafe-inline'` blocks styles added this way. Give ui-sdk your policy's nonce with a meta tag in the page's `<head>`. Vite reads the same tag for the styles it adds:

```html
<meta property="csp-nonce" nonce="your-nonce" />
```

If your policy has no nonce for styles, add the tag without the `nonce` attribute. ui-sdk then adds its CSS as constructed style sheets, which the browser places after yours, so declare its layer at the top of your stylesheet to keep your styles winning:

```css
@layer ui-sdk;
```
