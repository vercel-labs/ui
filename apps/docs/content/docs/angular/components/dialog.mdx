A dialog gives a task its own space: share a link, edit a record, or collect a few details. It manages focus, Escape, outside presses, and returning to where you started.

<ComponentExample
  name="dialog/basic"
  caption="Open Share, then close it with either Close button, Escape, or a press outside. Focus returns to Share."
/>

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build Dialog:

```text
uiDialog
├── uiDialogTrigger
├── uiDialogBackdrop
└── uiDialogContent
    ├── uiDialogTitle
    ├── uiDialogDescription
    └── uiDialogClose
```

The title names the dialog; the description gives it context. A dialog can have several Close parts. Give an icon-only close button an accessible name, as the first example does.

The backdrop is optional. Without one, style the content’s `::backdrop`. For a question that requires an explicit answer, use [Alert Dialog](./alert-dialog).

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import {
  Dialog,
  DialogBackdrop,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogTitle,
  DialogTrigger,
} from "@ui-sdk/angular/dialog"

@Component({
  selector: "app-example",
  imports: [
    Dialog,
    DialogBackdrop,
    DialogClose,
    DialogContent,
    DialogDescription,
    DialogTitle,
    DialogTrigger,
  ],
  template: `
    <ng-container uiDialog>
      <button uiDialogTrigger>Open</button>
      <div *uiDialogBackdrop></div>
      <div *uiDialogContent>
        <h2 uiDialogTitle>Project details</h2>
        <p uiDialogDescription>Review the details before continuing.</p>
        <button uiDialogClose>Close</button>
      </div>
    </ng-container>
  `,
})
class Example {}

export { Example }
```

## Build Your Own

`@ui-sdk/angular/dialog` comes with a ready-made Dialog. If you'd like to build your own, with your own names, start from the `dialog` primitive in `@ui-sdk/core`:

```ts title="share.ts"
import { Directive, inject } from "@angular/core"
import { dialog } from "@ui-sdk/core/dialog"
import { usePart, usePrimitive } from "@ui-sdk/angular/primitive"

@Directive({ selector: "[appShare]" })
class Share {
  readonly handle = usePrimitive(dialog, () => ({}))
}

@Directive({ selector: "[appShareTrigger]" })
class ShareTrigger {
  readonly state = usePart(inject(Share).handle, "trigger").state
}

@Directive({ selector: "[appShareBackdrop]" })
class ShareBackdrop {
  readonly state = usePart(inject(Share).handle, "backdrop").state
}

@Directive({ selector: "[appSharePanel]" })
class SharePanel {
  readonly state = usePart(inject(Share).handle, "content").state
}

@Directive({ selector: "[appShareTitle]" })
class ShareTitle {
  readonly state = usePart(inject(Share).handle, "title").state
}

@Directive({ selector: "[appShareDescription]" })
class ShareDescription {
  readonly state = usePart(inject(Share).handle, "description").state
}

@Directive({ selector: "[appShareClose]" })
class ShareClose {
  readonly state = usePart(inject(Share).handle, "close").state
}

export {
  Share,
  ShareBackdrop,
  ShareClose,
  ShareDescription,
  SharePanel,
  ShareTitle,
  ShareTrigger,
}
```

```ts
import { Component } from "@angular/core"
import {
  Share,
  ShareBackdrop,
  ShareClose,
  ShareDescription,
  SharePanel,
  ShareTitle,
  ShareTrigger,
} from "./share"

@Component({
  selector: "app-share-example",
  imports: [
    Share,
    ShareBackdrop,
    ShareClose,
    ShareDescription,
    SharePanel,
    ShareTitle,
    ShareTrigger,
  ],
  template: `
    <ng-container appShare>
      <button appShareTrigger>Share</button>
      <div appShareBackdrop></div>
      <div appSharePanel>
        <h2 appShareTitle>Share this page</h2>
        <p appShareDescription>Anyone with the link can view it.</p>
        <button appShareClose>Done</button>
      </div>
    </ng-container>
  `,
})
export class ShareExample {}
```

Connect the other slots the same way, each with `usePart`. Each part keeps the behavior, state and data attributes of its ready-made counterpart: the content opens in the top layer, traps focus and makes the page inert. See [Rendering Primitives](../rendering) and [Custom Parts](../custom-parts) for more.

## Scrollable Content

Keep the header and actions outside the scrolling area. A viewport height limit, a shrinking middle grid row, and `overflow-y: auto` keep long content usable. `initialFocus="content"` focuses the dialog itself so reading starts at the top.

## Forms

A form with `method="dialog"` closes the dialog on a valid submission. The submit button’s `value` becomes the `returnValue`, just like a Close part’s `value`. An ordinary form stays open until you close the dialog yourself.

## Focus

Use `initialFocus` to pick where focus starts, and `finalFocus` to choose where it goes after closing. Each takes a selector, an element, like a template reference, or a function returning one. The default returns to the trigger, or to the element focused before a controller opened the dialog. See [popup focus](../popups#focus) for the shared focus rules.

```angular-html
<div *uiDialogContent="{ initialFocus: '#invite-email', finalFocus: nextStep }">
  …
</div>
<button #nextStep type="button">Next Step</button>
```

## Controlled

Use `[(open)]` to keep the dialog's state in your component. Cancel a proposed change with `$event.cancel()` in `(beforeOpenChange)`. `(openChangeComplete)` reports when opening or closing has finished; see [state and events](../state-and-events) for the common change contract.

## Animation

The content and backdrop have `data-starting-style` while they open and `data-ending-style` while they close. Transition from those states, and the dialog stays mounted until the exit finishes. `(openChangeComplete)` runs after the transition, and `keepMounted` keeps the closed content in the page, hidden.

<StyleTabs>

```css
[data-slot="dialog-content"] {
  transition:
    opacity 0.2s,
    translate 0.25s cubic-bezier(0.22, 1, 0.36, 1),
    scale 0.25s cubic-bezier(0.22, 1, 0.36, 1);

  &:is([data-starting-style], [data-ending-style]) {
    opacity: 0;
    translate: 0 16px;
    scale: 0.96;
  }

  &[data-ending-style] {
    transition-duration: 0.15s;
  }
}
```

## Modal

`modal` controls how the dialog shares the page:

- `true`, the default, makes the page inert, locks scrolling, and keeps Tab inside.
- `"trap-focus"` keeps Tab inside while the page can still scroll and receive clicks. A click on the page also closes the dialog, unless `closeOnOutsidePress` is false.
- `false` puts the dialog beside the page and lets focus leave it. Escape closes it while focus is inside; outside presses close it only when `closeOnOutsidePress` is enabled.

To keep a small part of the page usable while a modal dialog is open, like a chat launcher, pass it to `persistentElements`: an array of elements or selectors, or a function returning elements when the dialog opens. Persistent elements don't change stacking on their own.

Dialogs render where you put them and use the browser's top layer. Set `container` when their DOM needs to live elsewhere, like a shadow root. The [popup guide](../popups#mounting-and-containers) covers containers and iframes.

## Inside a Frame

A dialog opens above the whole page. Set `inline` on the content to keep it and its backdrop where they are in the page, like inside an app preview. Your CSS sizes and places them in their frame. Pair it with `modal="trap-focus"` so the page around the frame stays usable.

## Warn Before Closing a Dirty Form

Set `dismissible` to false while there are unsaved changes. Escape, an outside press, or a back gesture then keeps the dialog open and reports `(dismissAttempt)`. Explicit Close parts and controller calls still work, so you can offer a deliberate way out.

## Nested Dialogs

A dialog opened inside another joins its stack. Escape closes the topmost dialog and returns focus to its trigger. Closing the parent also closes its children. `data-nested-open` and `--dialog-stack` let you show which layer is active.

## Opening from Anywhere

Connect several triggers to one `createDialogController<Payload, Result>()`. Each trigger passes a `payload`; the content reads it from its state, `*uiDialogContent="let content"`, as `content.payload`. In a template the payload is `unknown`, so give it its type in a method, like the example's `payloadOf()`. `controller.open({ payload })` opens it from code and returns a promise that resolves when it closes, with the reason and any `returnValue`. Each trigger remains the return-focus target for the dialog it opened. See [controllers](../controllers) for the shared controller pattern.

## Presentation

`presentation="sheet"` presents the same task as a sheet. Use `"auto"` to choose a sheet on small touch screens and a centered dialog elsewhere, decided each time it opens. A swipe down closes a dismissible sheet; a protected one springs back and reports a dismissal attempt.

Style `data-presentation` to support both layouts. The sheet manages its own position and movement, so do not apply the centered dialog’s translation to it. `--sheet-backdrop` styles the dimmed page when no Backdrop part is present.

### Events

A `before` output emits `{ value, reason, event, cancel() }` before the change, and its plain output follows with the value alone. A bound `open` only updates when `(beforeOpenChange)` wasn't canceled.

| Binding                 | On         | Receives                                                                                   |
| ----------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `[(open)]`              | `uiDialog` | Whether the dialog is open                                                                 |
| `(beforeOpenChange)`    | `uiDialog` | `{ value, reason, cancel() }`: the new state, the [reason](#reasons) and any `returnValue` |
| `(openChangeComplete)`  | `uiDialog` | `$event`, whether it's open, after the animation                                           |
| `(beforePayloadChange)` | `uiDialog` | `{ value, reason, cancel() }`: the content's new payload, and the [reason](#reasons)       |
| `(dismissAttempt)`      | `uiDialog` | `{ reason, event }`, when a dismissal was refused                                          |

## Accessibility

The trigger is a button that opens a dialog, and the dialog follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): `aria-modal` while it's modal, labelled by its title, described by its description only while one is rendered. Every line below is an automated test.

### Keyboard

| Key                  | Does                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| Enter, Space         | On the trigger, opens the dialog                                     |
| Tab, Shift+Tab       | Moves through the dialog's controls, staying inside while it's modal |
| Escape               | Closes the topmost dialog and returns focus to its trigger           |
| A trigger's shortcut | Opens its dialog from anywhere on the page                           |
