Use an Accordion for content people can explore one section at a time, such as answers, settings, or a course outline. Each heading is a button that opens its panel.

<ComponentExample
  name="accordion/basic"
  caption="Press “What is your return policy?”. Its answer opens and the shipping answer closes. Press the same heading again to close it."
/>

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build Accordion:

```text
uiAccordion
├── uiAccordionItem
│   ├── uiAccordionHeader
│   │   └── uiAccordionTrigger
│   └── uiAccordionPanel
└── uiAccordionItem
    ├── uiAccordionHeader
    │   └── uiAccordionTrigger
    └── uiAccordionPanel
```

Give every item a unique `value`. Put its trigger inside a heading, then add the panel it opens. The accordion's value is always an array of open item values, even when only one can be open.

`uiAccordionHeader` renders an `h3` by default. Use a heading level that fits the surrounding document. Tab moves between triggers; Enter or Space opens and closes their panels. Arrow keys, Home and End do nothing here: the APG removed them from the pattern, and a screen reader’s heading navigation already reaches each trigger.

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import {
  Accordion,
  AccordionHeader,
  AccordionItem,
  AccordionPanel,
  AccordionTrigger,
} from "@ui-sdk/angular/accordion"

@Component({
  selector: "app-example",
  imports: [
    Accordion,
    AccordionHeader,
    AccordionItem,
    AccordionPanel,
    AccordionTrigger,
  ],
  template: `
    <div uiAccordion>
      <div uiAccordionItem value="shipping">
        <h3 uiAccordionHeader>
          <button uiAccordionTrigger>Shipping</button>
        </h3>
        <div uiAccordionPanel>Orders arrive in five to seven days.</div>
      </div>
    </div>
  `,
})
class Example {}

export { Example }
```

## Build Your Own

`@ui-sdk/angular/accordion` comes with a ready-made Accordion. If you'd like to build your own, with your own names, start from the `accordion` primitive in `@ui-sdk/core`:

```ts title="faq.ts"
import { Directive, inject, input } from "@angular/core"
import { accordion } from "@ui-sdk/core/accordion"
import { usePart, usePrimitive } from "@ui-sdk/angular/primitive"

@Directive({ selector: "[appFaqList]" })
class FaqList {
  readonly handle = usePrimitive(accordion, () => ({}))
  readonly state = usePart(this.handle, "root").state
}

@Directive({ selector: "[appFaqItem]" })
class FaqItem {
  readonly value = input.required<string>()
  readonly handle = inject(FaqList).handle
  readonly state = usePart(this.handle, "item", () => ({ value: this.value() }))
    .state
}

@Directive({ selector: "[appFaqHeading]" })
class FaqHeading {
  readonly #item = inject(FaqItem)
  readonly state = usePart(this.#item.handle, "header", () => ({
    value: this.#item.value(),
  })).state
}

@Directive({ selector: "[appFaqQuestion]" })
class FaqQuestion {
  readonly #item = inject(FaqItem)
  readonly state = usePart(this.#item.handle, "trigger", () => ({
    value: this.#item.value(),
  })).state
}

@Directive({ selector: "[appFaqAnswer]" })
class FaqAnswer {
  readonly #item = inject(FaqItem)
  readonly state = usePart(this.#item.handle, "panel", () => ({
    value: this.#item.value(),
  })).state
}

export { FaqAnswer, FaqHeading, FaqItem, FaqList, FaqQuestion }
```

```ts
import { Component } from "@angular/core"
import { FaqAnswer, FaqHeading, FaqItem, FaqList, FaqQuestion } from "./faq"

@Component({
  selector: "app-faq-example",
  imports: [FaqAnswer, FaqHeading, FaqItem, FaqList, FaqQuestion],
  template: `
    <div appFaqList>
      <div appFaqItem value="shipping">
        <h3 appFaqHeading>
          <button appFaqQuestion>What are your shipping options?</button>
        </h3>
        <div appFaqAnswer>Standard, express and overnight.</div>
      </div>
    </div>
  `,
})
export class FaqExample {}
```

Connect the other slots the same way, each with `usePart`. Each part keeps the behavior, state and data attributes of its ready-made counterpart. See [Rendering Primitives](../rendering) and [Custom Parts](../custom-parts) for more.

Set `disabled` on an item or on a single trigger to prevent changes, or on the accordion to disable every item. Disabled triggers stay in the tab order so people can still discover them. A disabled `<fieldset>` around the accordion disables it too.

## Collapsible

Set `[collapsible]="false"` when the open item should stay open until another item replaces it. Pair it with `defaultValue={["overview"]}` so a panel starts open.

The open trigger reports `aria-disabled="true"` because pressing it leaves its panel open.

```angular-html
<div uiAccordion [collapsible]="false" [defaultValue]="['overview']"></div>
```

## Controlled

Use `[(value)]` to own the open items. [State and Events](../state-and-events) covers the shared pattern.

An item can refuse a change: call `$event.cancel()` in its `(beforeOpenChange)` callback. Item callbacks run before the accordion's `(beforeValueChange)`, including the item that would close when another opens. Canceling any one of them cancels the whole change. `(beforeValueChange)` also gets the [reason](#reasons) for the change.

  name="accordion/controlled"

## Animation

Each part has a `data-slot`, such as `accordion-panel`. The panel exposes its measured height as `--accordion-panel-height`. Animate that height to or from zero with `data-starting-style` and `data-ending-style`:

<StyleTabs>

```css
[data-slot="accordion-panel"] {
  height: var(--accordion-panel-height);
  overflow: hidden;
  transition: height 0.15s;

  &:is([data-starting-style], [data-ending-style]) {
    height: 0;
  }
}
```

```angular-html
<div
  uiAccordionPanel
  class="h-(--accordion-panel-height) overflow-hidden transition-[height] data-starting-style:h-0 data-ending-style:h-0"
></div>
```

</StyleTabs>

The panel stays mounted until its exit animation finishes. An item's `(openChangeComplete)` runs afterward with the open state. A panel that starts open appears right away, with no animation and no completion callback.

## URL Hash

<span id="open-the-item-in-the-url-hash" />

A hash can name an item's `value` instead of an element inside its panel. Read it after mount and on `hashchange`, then open and focus the matching item through your controller:

```ts
const value = decodeURIComponent(location.hash.slice(1))
if (items.some((item) => item.value === value)) {
  accordion.open(value)
  accordion.focus(value)
}
```

Check the value against your items first. A controller can hold a value even when no item renders it. Remove the `hashchange` listener when the component unmounts.

## Query String

<span id="keep-open-items-in-the-query-string" />

Use `open` query parameters when several items should be shareable. Read the initial values from your router on the server, then write accepted changes back to the URL:

```ts
function saveOpenItems(value: string[]) {
  const url = new URL(location.href)
  url.searchParams.delete("open")
  for (const item of value) url.searchParams.append("open", item)
  history.replaceState(null, "", url)
}
```

Call this from `(beforeValueChange)` after updating your state. If your app already has a router, use its navigation API instead.

## Scroll into View

<span id="scroll-an-item-into-view" />

Scroll after `(openChangeComplete)`, when the panel has its full height. Scrolling in `(beforeOpenChange)` would measure it before it opens. The [Expand All example](#expand-all) shows the full setup and scrolls only when someone opens a single item.

triggers and panels take their item's value from the item.

### Events

A `before` output emits `{ value, reason, event, cancel() }` before the change, and its plain output follows with the value alone. A bound `value` only updates when `(beforeValueChange)` wasn't canceled.

| Binding                | On                | Receives                                                                  |
| ---------------------- | ----------------- | ------------------------------------------------------------------------- |
| `[(value)]`            | `uiAccordion`     | The open items                                                            |
| `(beforeValueChange)`  | `uiAccordion`     | `{ value, reason, cancel() }`: the open items, and the [reason](#reasons) |
| `(beforeOpenChange)`   | `uiAccordionItem` | `{ value, reason, cancel() }`, before `(beforeValueChange)`               |
| `(openChangeComplete)` | `uiAccordionItem` | `$event`, whether it's open, after the panel's animation                  |
