Start with a trigger and a few actions. Add groups, checkboxes, radio choices, or submenus as the task grows. The menu handles focus, arrow keys, typeahead, and dismissal.

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build Menu:

```text
uiMenu
├── uiMenuTrigger
└── uiMenuContent
    ├── uiMenuItem
    └── uiMenuItem
```

Give items a `value` and handle `(action)` on the menu to run the selected command. A Group and GroupLabel can organize related actions; a Separator divides them without becoming a focus stop.

Pass a promise to `$event.waitUntil()` in `(action)` or an item’s `(select)` to keep the item pending. It gets `data-pending`, `aria-busy` and `aria-disabled`, the menu stays open, and choosing it again does nothing until the promise settles. The menu closes once it resolves. A rejection keeps it open and puts the reason in the item’s `error` state until the next try. After a second, screen readers hear `pendingAnnouncement`, “Loading” by default.

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import { Menu, MenuContent, MenuItem, MenuTrigger } from "@ui-sdk/angular/menu"

@Component({
  selector: "app-example",
  imports: [Menu, MenuContent, MenuItem, MenuTrigger],
  template: `
    <ng-container uiMenu>
      <button uiMenuTrigger>Actions</button>
      <div *uiMenuContent>
        <div uiMenuItem value="rename">Rename</div>
        <div uiMenuItem value="duplicate">Duplicate</div>
      </div>
    </ng-container>
  `,
})
class Example {}

export { Example }
```

## Submenus

Nest a Sub, SubTrigger, and SubContent to add another level. Hover or press the arrow key toward a submenu to open it. The menu lets a pointer travel diagonally into the submenu without accidentally choosing an item it passes over. Escape closes only the submenu and returns focus to its trigger, as the menu pattern asks.

## Shortcuts

An item’s `shortcut` displays a platform-specific hint and sets `aria-keyshortcuts`. `mod+s` reads as Command+S on Apple platforms and Control+S elsewhere.

In markup, this is a hint: your app owns the key handler. [Data menus](#menus-as-data) also register their shortcuts while closed. Letters and digits match physical keys, including combinations such as Option+N.

## Icons

Put decorative icons in ItemIcon so screen readers and typeahead ignore them. `mirror` flips a directional icon in right-to-left text. An icon-only item still needs an `aria-label`.

`data-has-icon` on items and `data-has-icons` on the menu let text line up when only some items have icons.

## Checkboxes

Checkbox items toggle independently and stay open by default. Use `[(checked)]`, or `defaultChecked` for an uncontrolled item. `*uiMenuItemIndicator` renders the check; `keepMounted` preserves its space while unchecked. Style `data-checked` and `data-unchecked` for each state.

Radio items choose one value in their group and stay open by default. Use `[(value)]`, or `defaultValue` for an uncontrolled group. Give the group a `name` when it should identify itself in the menu’s `(valueChange)` output.

## Context Menu

A ContextTrigger opens at a right-click or long press. Give the area a tab stop so Shift+F10 and the context-menu key can open it from the keyboard. Right-clicking elsewhere in the same area repositions an open menu.

Set `disabled` to leave that area’s native browser menu available. Context triggers can pass a payload too.

## Placement

`side` and `align` choose the starting position. The menu flips or shifts when it does not fit; `data-side` reports where it ended up. Logical alignment and submenu keys follow the surrounding text direction. See the shared [popup guide](../popups) for the positioning contract.

```angular-html
<div *uiMenuContent="{ side: 'right', align: 'start' }"></div>
```

## Offsets and Collision Padding

`sideOffset` sets the gap, `alignOffset` shifts along the anchor, and `collisionPadding` leaves room around the viewport. Use `--anchor-width` to match the trigger's width and `--available-height` to scroll a long list.

```angular-html
<div
  *uiMenuContent="{ sideOffset: 8, alignOffset: -4, collisionPadding: 24 }"
></div>
```

## Modal

The default `modal="pointer"` consumes an outside press while closing the menu. `true` also locks scrolling and makes the page inert. `false` lets the outside press reach its target after closing.

```angular-html
<ng-container uiMenu [modal]="false">
  <button uiMenuTrigger>Actions</button>
  <div *uiMenuContent></div>
</ng-container>
```

## Submenu Delay

`delay` is the hover wait in milliseconds, 100 by default. It applies to the submenus directly inside that menu. Set it on a Sub to change the delay for the next level.

```angular-html
<ng-container uiMenu [delay]="300">
  <button uiMenuTrigger>File</button>
  <div *uiMenuContent>
    <ng-container uiMenuSub [delay]="0">
      <div uiMenuSubTrigger>Open recent</div>
      <div *uiMenuSubContent></div>
    </ng-container>
  </div>
</ng-container>
```

## Keyboard Navigation

Arrow keys wrap by default; `loop` false stops at the ends. Typing finds an item by name. If an item has extra descriptive text, set `label` to the text typeahead should match. `label` does not replace its accessible name; use `aria-label` for that.

```angular-html
<ng-container uiMenu [loop]="false">
  <button uiMenuTrigger>Status</button>
  <div *uiMenuContent>
    <div uiMenuItem value="busy" label="Do not disturb">
      Do not disturb
      <span>Notifications are muted</span>
    </div>
  </div>
</ng-container>
```

A menu holds items, groups and separators. For a text field beside a list of choices, like a search box or a rename field, use a [Popover](./popover). The field keeps its keys there, while in a menu the pointer moves focus from item to item.

## Focus After Closing

When the menu closes with focus inside it, focus returns to the trigger. If an action removes the trigger or moves people on to something else, set `finalFocus` on the content to a selector, an element or a function returning one, or to `"none"` to leave focus where the action put it. See [popup focus](../popups#focus) for the shared focus rules.

```angular-html
<div *uiMenuContent="{ finalFocus: '#file-list' }"></div>
```

## Disabled Items

Disabled items remain focusable so people can discover them, but cannot run or open a submenu. A disabled Trigger is a native disabled button and cannot receive focus. Add `focusableWhenDisabled` to keep it in the tab order, so it can host a tooltip that says why; presses still do nothing.

## Keeping the Menu Open

Plain items close when selected; checkbox and radio items stay open. `closeOnSelect` changes either default. A selection handler can also prevent the default event to keep it open for one action.

```angular-html
<div uiMenuItem [closeOnSelect]="false" (select)="zoom += 10">Zoom in</div>
<div uiMenuCheckboxItem value="fit" closeOnSelect>Fit to window</div>
```

## Container

Menus render in place and use the top layer. `container` moves the popup to another element; submenus remain inside their parent popup. Pass the actual element after it exists, as the [popup guide](../popups) explains.

```angular-html
<div *uiMenuContent="{ container: panel }"></div>
```

## Animation

The menu stays mounted through an exit animation. `data-starting-style`, `data-ending-style`, `data-side`, and `--transform-origin` describe the transition. `keepMounted` leaves the closed content hidden afterward; `(openChangeComplete)` reports when it finishes.

## Presentation

`presentation="auto"` uses a sheet on small touch screens and a popover elsewhere; `"sheet"` always requests a sheet. The sheet keeps menu roles and keys. Submenus replace the current level, and Escape or the arrow toward the parent goes back. Context menus and menus in a menubar remain popovers.

Use `data-presentation` or the content’s `presentation` state for the two layouts. Leave a sheet’s translation to the SDK. `--sheet-backdrop` sets its dimming color, and the sheet is modal unless `modal` is false. The [popup guide](../popups) covers shared presentation behavior.

  name="menu/presentation"

/>

## Controlled

Use `[(open)]`, or pass `open` and update it in `(beforeOpenChange)`. A change carries a reason, and `$event.cancel()` can refuse it. A controller can open the menu from another control; see [state and events](../state-and-events) and [controllers](../controllers) for that shared pattern.

```ts
import { Component, signal } from "@angular/core"
import { Menu, MenuContent, MenuTrigger } from "@ui-sdk/angular/menu"

@Component({
  selector: "app-example",
  imports: [Menu, MenuContent, MenuTrigger],
  template: `
    <ng-container uiMenu [(open)]="open">
      <button uiMenuTrigger>Actions</button>
      <div *uiMenuContent></div>
    </ng-container>
  `,
})
class Example {
  readonly open = signal(false)
}

export { Example }
```

## Triggers Outside the Menu

Connect external triggers and one menu to a `createMenuController<File>()`. Each trigger passes its row as `payload`, which the content reads from its state. Only the active trigger is expanded and receives focus back. Code can also open with a `payload` and `anchor`; the Promise resolves when the menu closes.

## Menus as Data

`items` accepts `MenuData`: actions, groups, checkboxes, radio groups, and submenus. A string is shorthand for an item whose label and value match. Put `uiMenuItems` inside the content to render them as bare parts. Data menus register their shortcuts even while closed; set `itemShortcuts` to false to turn that off.

The menu's `(checkedChange)` emits the checkbox's `value` and whether it's `checked`; its `(valueChange)` emits the radio group's name in `group` and its new `value`. Either change can be canceled with `$event.cancel()`. You can also render your own parts from the same data while `items` keeps the shortcuts registered. The [lists and menus guide](../lists-and-menus) covers the data shape.

```ts
import { Component } from "@angular/core"
import {
  Menu,
  MenuContent,
  type MenuData,
  MenuItems,
  MenuTrigger,
} from "@ui-sdk/angular/menu"

@Component({
  selector: "app-example",
  imports: [Menu, MenuContent, MenuItems, MenuTrigger],
  template: `
    <ng-container uiMenu [items]="fileMenu" (action)="run($event.value)">
      <button uiMenuTrigger>File</button>
      <div *uiMenuContent>
        <div uiMenuItems></div>
      </div>
    </ng-container>
  `,
})
class Example {
  readonly fileMenu: MenuData = [
    { value: "open", label: "Open…", shortcut: "mod+o" },
    { type: "separator" },
    {
      type: "checkbox",
      value: "toolbar",
      label: "Toolbar",
      defaultChecked: true,
    },
    {
      type: "radio-group",
      name: "sort",
      label: "Sort by",
      defaultValue: "name",
      items: [
        { value: "name", label: "Name" },
        { value: "date", label: "Date modified" },
      ],
    },
    { type: "submenu", label: "Share", items: ["Copy link", "Email"] },
  ]

  run(command: string) {
    console.log(command)
  }
}

export { Example }
```

### Controller

Create one with `createMenuController<Payload>()` and pass it to `[controller]`, on the menu and on any triggers outside it. `Payload` is the type of the data triggers and `open()` pass.

Every write method takes an optional `{ reason, event }`, passed to `(beforeOpenChange)`. `open()` also takes `focus`: `"first"`, `"last"`, `"popup"` or `"none"`.

### Events

A `before` output emits `{ value, reason, event, cancel() }` before the change, and its plain output follows with the value alone. A bound `open`, `checked` or `value` only updates when its change isn't canceled.

| Binding                 | On                   | Receives                                                                                        |
| ----------------------- | -------------------- | ----------------------------------------------------------------------------------------------- |
| `[(open)]`              | `uiMenu`             | Whether the menu is open                                                                        |
| `(beforeOpenChange)`    | `uiMenu`             | `{ value, reason, cancel() }`: the new state, and the [reason](#reasons)                        |
| `(openChangeComplete)`  | `uiMenu`             | `$event`, whether it's open, after the animation                                                |
| `(beforePayloadChange)` | `uiMenu`             | `{ value, reason, cancel() }`: the content's new payload, and the [reason](#reasons)            |
| `(action)`              | `uiMenu`             | `{ value, event, waitUntil() }` for every plain item, including items in submenus               |
| `(checkedChange)`       | `uiMenu`             | `{ value, checked, reason, cancel() }` for any checkbox item. For data menus                    |
| `(valueChange)`         | `uiMenu`             | `{ group, value, reason, cancel() }` for any radio group. For data menus                        |
| `(dismissAttempt)`      | `uiMenu`             | `{ reason, event }`, when a dismissal was refused                                               |
| `[(open)]`              | `uiMenuSub`          | Whether the submenu is open                                                                     |
| `(select)`              | `uiMenuItem`         | `{ event, waitUntil() }`, before the menu closes. `$event.event.preventDefault()` keeps it open |
| `[(checked)]`           | `uiMenuCheckboxItem` | Whether the item is checked. `(beforeCheckedChange)` has the details                            |
| `[(value)]`             | `uiMenuRadioGroup`   | The selected value. `(beforeValueChange)` has the details                                       |
