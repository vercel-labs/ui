Command puts a search field over a list of actions. The list stays open while someone searches. You can use it on its own, or put it in a dialog to build a command palette.

<ComponentExample
  name="command/demo"
  caption="Type “bil” to find Billing. Arrow keys move the highlight; Escape clears the search."
/>

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build Command:

```text
uiCommand
├── uiCommandInput
├── uiCommandEmpty
└── uiCommandList
    ├── uiCommandItem
    └── uiCommandItem
```

Give the input an accessible name and each command a unique value. Keep empty and status messages outside the list, which holds commands and groups. `(action)` reports the value of the command that ran; use it to perform the action.

Use `uiCommandGroup` and `uiCommandGroupLabel` to name related commands, with a `uiCommandSeparator` between groups. Groups and separators disappear when filtering leaves them empty.

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import {
  Command,
  CommandEmpty,
  CommandInput,
  CommandItem,
  CommandList,
} from "@ui-sdk/angular/command"

@Component({
  selector: "app-example",
  imports: [Command, CommandEmpty, CommandInput, CommandItem, CommandList],
  template: `
    <div uiCommand>
      <input uiCommandInput aria-label="Search commands" />
      <div uiCommandEmpty>No commands found.</div>
      <div uiCommandList>
        <div uiCommandItem value="new-file">New file</div>
        <div uiCommandItem value="new-folder">New folder</div>
      </div>
    </div>
  `,
})
class Example {}

export { Example }
```

## Build Your Own

`@ui-sdk/angular/command` comes with a ready-made Command. If you'd like to build your own, with your own names, start from the `command` primitive in `@ui-sdk/core`:

```ts title="palette.ts"
import { Directive, inject, input } from "@angular/core"
import { command } from "@ui-sdk/core/command"
import { usePart, usePrimitive } from "@ui-sdk/angular/primitive"

@Directive({ selector: "[appPalette]" })
class Palette {
  readonly handle = usePrimitive(command, () => ({}))
}

@Directive({ selector: "[appPaletteSearch]" })
class PaletteSearch {
  readonly state = usePart(inject(Palette).handle, "input").state
}

@Directive({ selector: "[appPaletteEmpty]" })
class PaletteEmpty {
  readonly state = usePart(inject(Palette).handle, "empty").state
}

@Directive({ selector: "[appPaletteList]" })
class PaletteList {
  readonly state = usePart(inject(Palette).handle, "list").state
}

@Directive({ selector: "[appPaletteAction]" })
class PaletteAction {
  readonly value = input.required<string>()
  readonly state = usePart(inject(Palette).handle, "item", () => ({
    value: this.value(),
  })).state
}

export { Palette, PaletteAction, PaletteEmpty, PaletteList, PaletteSearch }
```

```ts
import { Component } from "@angular/core"
import {
  Palette,
  PaletteAction,
  PaletteEmpty,
  PaletteList,
  PaletteSearch,
} from "./palette"

@Component({
  selector: "app-palette-example",
  imports: [Palette, PaletteAction, PaletteEmpty, PaletteList, PaletteSearch],
  template: `
    <ng-container appPalette>
      <input appPaletteSearch aria-label="Search actions" />
      <div appPaletteEmpty>No actions found.</div>
      <div appPaletteList>
        <div appPaletteAction value="new-file">New file</div>
        <div appPaletteAction value="new-folder">New folder</div>
      </div>
    </ng-container>
  `,
})
export class PaletteExample {}
```

Connect the other slots the same way, each with `usePart`. Each part keeps the behavior, state and data attributes of its ready-made counterpart: typing filters the commands, arrow keys move the highlight and Enter runs it. See [Rendering Primitives](../rendering) and [Custom Parts](../custom-parts) for more.

## Shortcuts

An item’s `shortcut` can run it while the command list is mounted, even when the search or current page hides it. `uiCommandShortcut` displays the keys for the current platform, and the item gets `aria-keyshortcuts`. Shortcuts inside a dialog run while it is open.

## Filter and Keywords

`"fuzzy"` is the default: `nf` matches New file. `"contains"` and `"startsWith"` match the text itself. A custom function returns a boolean or a score; zero hides a command and higher scores rank first.

Data commands are sorted by score. Commands written directly in markup keep their order, even though the best match can be highlighted.

`keywords` adds search terms without changing the command's label. Use it for synonyms or names someone might type instead.

## Pages

Set an item’s `page` to the value of a `uiCommandPage` to open it. An unnamed page holds the first set of commands. The `pages` array records the stack of pages that have been opened.

Backspace in an empty search goes back and restores the previous page’s query. Escape clears the query first, then goes back. A Go back command can call `pop()` on a controller.

## Items as Data

Pass `items` to provide commands, groups, separators, and pages as `CommandData`. A data command with its own `items` opens a page. Its shortcut still works when another page or filter hides it.

`uiCommandItems` inside the list renders bare parts from the data. For styled commands, render from the list’s `state().items`, which follows the current page and ranked results. The example handles groups and separators as well as commands. [Lists and Menus](../lists-and-menus) covers the shared data format.

Pass `emptyItems` alongside `items` to show suggested or recent commands while the first page's search is empty. Once someone types, the full collection is searched.

```angular-html
<div
  uiCommand
  [items]="commands"
  [emptyItems]="[{ type: 'group', label: 'Suggested', items: recent }]"
></div>
```

## Async Results

Use [async options](../utilities/async-options) to wait for typing to pause and discard stale results. Send query changes to `setQuery()`, render the returned items, and pass `status`. Set `filter` to `false` to keep the server’s order.

`uiCommandStatus` describes loading and failures, and the list gets `aria-busy` while loading. `(loadMore)` can request another page when scrolling or highlighting reaches the last command. Without a status part, `announcement` controls the result-count message after typing pauses.

## Pending Actions

Pass a promise to `$event.waitUntil()` in `(action)` or an item’s `(select)`. The command gets `data-pending`, `aria-busy` and `aria-disabled` until it settles; further presses do not start another run. A rejection becomes the command’s `error` state, which clears when it runs again.

An item’s `(select)` runs before `(action)`. Call `preventDefault()` on its event to stop the action.

## Controlled

The highlighted command, search text, and page stack are separate:

| Value   | Shape                               | Change Notification   |
| ------- | ----------------------------------- | --------------------- |
| `value` | A command’s string value or `null`. | `(beforeValueChange)` |
| `query` | The search text.                    | `(beforeQueryChange)` |
| `pages` | An array of page values.            | `(beforePagesChange)` |

Bind them with `[(value)]`, `[(query)]` and `[(pages)]`, or use `defaultValue`, `defaultQuery`, and `defaultPages` for starting state. The `before` outputs receive the details; call `$event.cancel()` to reject a change. `value` is the highlighted command, not a chosen one, and it changes as the highlight moves. `(action)` reports activation, so moving the highlight alone does not run a command. [State and Events](../state-and-events) covers the shared binding pattern.

## Controller

Create a `createCommandController()` for one instance and pass it as `controller`. It can read and set the highlight, query, and page stack. Use `push()` and `pop()` to navigate pages, `run()` to run the highlighted command or a named one, and `focus()` to focus the search. See [Controllers](../controllers) for setup and lifecycle.

## Styling

Each part has a `data-slot`, such as `command-item`, and shows its state through the attributes listed under [Data Attributes](#data-attributes).

Use `data-highlighted` for the active command and `data-pending` for an action in progress. Give the list a height limit and `overflow-y: auto` for long lists; keyboard navigation scrolls the highlighted command into view. When mixing commands with and without icons, `data-has-icons` on the list and `data-has-icon` on each item let you reserve matching space with logical padding.

### Events

A `before` output emits `{ value, reason, event, cancel() }` before the change, and its plain output follows with the value alone. A bound `value`, `query` or `pages` only updates when its change isn't canceled.

| Binding               | On              | Receives                                                                                               |
| --------------------- | --------------- | ------------------------------------------------------------------------------------------------------ |
| `[(value)]`           | `uiCommand`     | The highlighted command                                                                                |
| `[(query)]`           | `uiCommand`     | The search text                                                                                        |
| `[(pages)]`           | `uiCommand`     | The stack of pages                                                                                     |
| `(beforeValueChange)` | `uiCommand`     | `{ value, reason, cancel() }`: the highlighted command, the [reason](#reasons) and its `index`         |
| `(beforeQueryChange)` | `uiCommand`     | `{ value, reason, cancel() }`: the new text, the [reason](#reasons) and whether it's still `composing` |
| `(beforePagesChange)` | `uiCommand`     | `{ value, reason, cancel() }`: the new stack, and the [reason](#reasons)                               |
| `(action)`            | `uiCommand`     | `{ value, event, waitUntil() }`: the command that ran. `waitUntil(promise)` marks it pending           |
| `(loadMore)`          | `uiCommand`     | `()`, when the last command is reached                                                                 |
| `(select)`            | `uiCommandItem` | `{ event, waitUntil() }`: before `(action)`. `$event.event.preventDefault()` skips it                  |

## Accessibility

The command list follows the [WAI-ARIA combobox pattern](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/) with a listbox that's always shown. Focus stays in the input, which points to the highlighted command with `aria-activedescendant`. Every line below is an automated test.

### Keyboard

| Key                | Does                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| Typing             | Filters the commands and highlights the best match                    |
| ArrowDown, ArrowUp | Moves the highlight. Wraps unless `[loop]="false"`                    |
| Enter              | Runs the highlighted command, or follows it when it renders as a link |
| Escape             | Clears the search, then goes back a page                              |
| Backspace          | In an empty search, goes back a page and restores its query           |
| An item's shortcut | Runs it while the list is mounted, even when hidden by the search     |

The first available command is highlighted by default. Set `autoHighlight` to `false` to wait for an arrow key or pointer movement.
