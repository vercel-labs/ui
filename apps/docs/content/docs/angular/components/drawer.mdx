A drawer gives a task its own sheet without leaving the page. It shares [Dialog’s](./dialog) focus and dismissal behavior, then adds dragging, snap points, and a handle you can use with the keyboard.

<ComponentExample
  name="drawer/basic"
  caption="Open the drawer, adjust the daily goal, then Submit or Cancel. You can also press Escape, press outside, or drag the sheet toward its edge to close it."
/>

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build Drawer:

```text
uiDrawer
├── uiDrawerTrigger
├── uiDrawerBackdrop
└── uiDrawerContent
    ├── uiDrawerTitle
    ├── uiDrawerDescription
    └── uiDrawerClose
```

The content is the sheet. The drawer positions it inside a full-screen viewport and moves it with `translate`. Give it a size, a surface, and corners; leave positioning and translation to the drawer. Give the backdrop a color, such as `bg-black/30`; the drawer manages its opacity.

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import {
  Drawer,
  DrawerBackdrop,
  DrawerClose,
  DrawerContent,
  DrawerDescription,
  DrawerTitle,
  DrawerTrigger,
} from "@ui-sdk/angular/drawer"

@Component({
  selector: "app-example",
  imports: [
    Drawer,
    DrawerBackdrop,
    DrawerClose,
    DrawerContent,
    DrawerDescription,
    DrawerTitle,
    DrawerTrigger,
  ],
  template: `
    <ng-container uiDrawer>
      <button uiDrawerTrigger>Filters</button>
      <div *uiDrawerBackdrop></div>
      <div *uiDrawerContent>
        <h2 uiDrawerTitle>Filters</h2>
        <p uiDrawerDescription>Narrow down the results.</p>
        <button uiDrawerClose>Done</button>
      </div>
    </ng-container>
  `,
})
class Example {}

export { Example }
```

## Scrollable Content

Put long content in an inner `min-h-0 flex-1 overflow-y-auto` area. A downward drag scrolls that area first; when it reaches the top, the same gesture can move the drawer. `initialFocus="content"` starts focus on the sheet itself.

<ComponentExample
  name="drawer/scrollable"
  caption="Open the long sheet and scroll its text. At the top, drag downward to move the sheet; on a keyboard, Tab reaches the controls and Escape closes it."
/>

Fields, sliders and color areas inside the sheet keep their own drags. For a drag surface of your own, like a canvas or a map, add `data-drawer-no-drag` to it, and a drag that starts there won't move the drawer.

## Sides

`side` chooses bottom, top, left, or right. Logical `start` and `end` follow text direction. The content’s `data-side` tells you which physical edge to style.

Side drawers can opt into `preventEdgeSwipe` to keep an edge gesture from starting iOS Safari’s back or forward navigation. It also prevents clicks right at those edges, so use it only when you need that tradeoff.

## Snap Points

`snapPoints` are the places the drawer can rest. It opens at the first, or at `defaultSnapPoint`, and settles at another after a drag. A fast fling can skip intermediate points.

| Value              | Size                                       |
| ------------------ | ------------------------------------------ |
| `0.5`              | Half the viewport along the drawer’s axis. |
| `320` or `"320px"` | Pixels; numbers above 1 are pixel values.  |
| `"20rem"`          | A multiple of the root font size.          |
| `"50%"`            | A percentage of the viewport.              |
| `"content"`        | The sheet’s own size, the default.         |

The sheet’s CSS size is the limit: `1` cannot make a short sheet fill the screen. Use a height such as `h-[calc(100dvh-3rem)]` when the largest point should nearly fill it. The drawer measures again when content or available space changes; a moved resting point reports `content-resize`.

A Handle is a button with an accessible name. Pressing it moves to the next larger snap point, then wraps to the smallest. Arrow keys along the drawer’s axis move one point without wrapping; Home and End move to the ends. `canExpand` and `canCollapse` let the example show which moves remain.

For a sheet with one snap point, use a decorative bar instead of an inactive button.

<ComponentExample

## Controlled

Use `[(open)]`, or `[(snapPoint)]`, to keep the drawer's state in your component. You can control opening and snap points independently. Cancel a proposed change with `$event.cancel()` in `(beforeOpenChange)` or `(beforeSnapPointChange)`; a canceled swipe springs back. `(openChangeComplete)` runs after the sheet settles.

```ts
import { Component, signal } from "@angular/core"
import { Drawer, type SnapPoint } from "@ui-sdk/angular/drawer"

@Component({
  selector: "app-example",
  imports: [Drawer],
  template: `
    <ng-container
      uiDrawer
      [(open)]="open"
      [snapPoints]="[0.25, 0.5, 1]"
      [(snapPoint)]="snapPoint"
    >
      <!-- … -->
    </ng-container>
  `,
})
class Example {
  readonly open = signal(false)

  readonly snapPoint = signal<SnapPoint>(0.5)
}

export { Example }
```

## Not Dismissible

With `dismissible` false, Escape, outside presses, back gestures, and swipes leave the drawer open. `(dismissAttempt)` tells you what was tried, so you can offer a way to discard unsaved work. Close parts, triggers, and controllers can still close it deliberately.

```angular-html
<ng-container
  uiDrawer
  [dismissible]="false"
  (dismissAttempt)="attempt = $event.reason"
>
  <button uiDrawerTrigger>Write a Post</button>
  <div *uiDrawerBackdrop></div>
  <div *uiDrawerContent>
    @if (attempt) {
      <button uiDrawerClose>Discard</button>
    }
    <button uiDrawerClose value="post">Post</button>
  </div>
</ng-container>
```

## Modal

Set `modalAbove` when the page should stay usable beside a small sheet. At or below that point there is no dim, inert page, scroll lock, or `aria-modal`. Above it, `modal` applies. The switch happens when the drawer settles and does not move focus; `data-interactive` exposes the usable-page state.

`modal` has the same choices as [Dialog](./dialog#modal): `true` blocks the page, `"trap-focus"` keeps Tab inside while leaving the page usable, and `false` allows focus to leave. A click on the page also closes a `"trap-focus"` drawer, while a non-modal drawer closes on an outside press only when `closeOnOutsidePress` is enabled.

## Nested Drawers

A drawer opened inside another joins its stack. Escape and outside presses affect the topmost one; closing a parent closes its children. `--drawer-stack` follows the sheets above it as they open and drag, so a parent can scale back with `[scale:calc(1-var(--drawer-stack)*0.04)]`.

## Forms

A Close part’s `(action)` can wait on a Promise with `$event.waitUntil()`. The sheet stays open while it runs, including through Escape or a swipe. A rejection leaves the action’s error state available for a retry. See [Alert Dialog’s async action](./alert-dialog#async-action) for the shared pending and error contract.

`keepMounted` preserves unfinished fields, and `finalFocus` returns focus to the updated profile.

```angular-html
<div *uiDrawerContent="{ keepMounted: true, finalFocus: summary }">
  <form #form><!-- fields --></form>
  <button
    uiDrawerClose
    #close="uiDrawerClose"
    (action)="$event.waitUntil(save(form))"
  >
    {{
      close.state().pending
        ? "Saving…"
        : close.state().error
          ? "Try Again"
          : "Save Changes"
    }}
  </button>
</div>
```

## Opening from Anywhere

Connect external triggers and the drawer to one `createDrawerController<Payload, Result>()`. Each trigger passes a `payload`; the content reads it from its state, `*uiDrawerContent="let content"`, as `content.payload`. In a template the payload is `unknown`, so give it its type in a method, like the example's `payloadOf()`. This lets one sheet serve every row, including disabled triggers for unavailable actions.

Calling `open({ payload })` on the controller returns a Promise with the closing `reason` and `returnValue`. `getSnapPoint()` and `setSnapPoint()` also let code read or move the sheet. The [controller guide](../controllers) covers the shared result and payload flow.

```ts
import { Component } from "@angular/core"
import {
  createDrawerController,
  Drawer,
  DrawerBackdrop,
  DrawerContent,
  DrawerTitle,
  DrawerTrigger,
} from "@ui-sdk/angular/drawer"

type SharedFile = { name: string; uploading: boolean }

@Component({
  selector: "app-example",
  imports: [Drawer, DrawerBackdrop, DrawerContent, DrawerTitle, DrawerTrigger],
  template: `
    <button
      uiDrawerTrigger
      [controller]="share"
      [payload]="file"
      [disabled]="file.uploading"
    >
      Share
    </button>

    <ng-container uiDrawer [controller]="share">
      <div *uiDrawerBackdrop></div>
      <div *uiDrawerContent="let content">
        <h2 uiDrawerTitle>Share {{ payloadOf(content)?.name }}</h2>
      </div>
    </ng-container>
  `,
})
class Example {
  readonly file: SharedFile = { name: "Roadmap.pdf", uploading: false }
  readonly share = createDrawerController<SharedFile, "copy" | "email">()

  async shareFile() {
    const { reason, returnValue } = await this.share.open({
      payload: this.file,
    })
  }

  payloadOf(state: { payload?: unknown }) {
    return state.payload as SharedFile | undefined
  }
}

export { Example }
```

## Responsive

This recipe uses a media query to choose a Drawer on a narrow screen and a Dialog on a wide screen. It replaces the component tree at the breakpoint, so an open sheet closes and local field edits reset. Lift the open and field values above that branch if they must survive the switch.

```ts
import { Component, afterNextRender, signal } from "@angular/core"
import {
  Dialog,
  DialogBackdrop,
  DialogContent,
  DialogTrigger,
} from "@ui-sdk/angular/dialog"
import {
  Drawer,
  DrawerBackdrop,
  DrawerContent,
  DrawerTrigger,
} from "@ui-sdk/angular/drawer"
import { ProfileForm } from "./profile-form"

@Component({
  selector: "app-edit-profile",
  imports: [
    Dialog,
    DialogBackdrop,
    DialogContent,
    DialogTrigger,
    Drawer,
    DrawerBackdrop,
    DrawerContent,
    DrawerTrigger,
    ProfileForm,
  ],
  template: `
    @if (isDesktop()) {
      <ng-container uiDialog>
        <button uiDialogTrigger>Edit Profile</button>
        <div *uiDialogBackdrop></div>
        <div *uiDialogContent>
          <app-profile-form />
        </div>
      </ng-container>
    } @else {
      <ng-container uiDrawer>
        <button uiDrawerTrigger>Edit Profile</button>
        <div *uiDrawerBackdrop></div>
        <div *uiDrawerContent>
          <app-profile-form />
        </div>
      </ng-container>
    }
  `,
})
class EditProfile {
  readonly isDesktop = signal(false)

  constructor() {
    afterNextRender(() => {
      const query = matchMedia("(min-width: 768px)")
      this.isDesktop.set(query.matches)
      query.addEventListener("change", () => this.isDesktop.set(query.matches))
    })
  }
}

export { EditProfile }
```

## Driver and Physics

`driver` picks how the sheet moves. `"scroll-snap"` uses native scrolling and CSS snap points for a bottom sheet; `"pointer"` uses pointer dragging and spring motion on every side. The default `"auto"` chooses native scrolling for a bottom sheet on a touch screen, and pointer dragging for mouse and pen, other sides, `modalAbove`, or `expandOnScroll` false. `data-driver` reports the active choice.

Override part of `sheetPhysics.ios` with `physics` to tune the pointer driver: `response` changes spring timing, `dampingRatio` changes settling, `momentumDampingRatio` affects flings, and `rubberBand` changes resistance past the largest point.

```angular-html
<ng-container
  uiDrawer
  driver="pointer"
  [physics]="{ response: 0.3, dampingRatio: 0.9 }"
></ng-container>
```

## Page Integration

`themeColor` dims an existing `<meta name="theme-color">` with the backdrop, so the browser's toolbars can follow it; pages without that tag are left alone. `persistentElements` keeps selected elements usable while the drawer is modal: an array of elements or selectors, or a function returning elements. Something that must stay above the backdrop also needs its own top-layer surface.

Drawers render in place and use the top layer. `container` moves the backdrop and viewport elsewhere, for example into a shadow root or out of a surrounding form. See the shared [popup guide](../popups#mounting-and-containers).

```angular-html
<ng-container uiDrawer themeColor [persistentElements]="['#chat-launcher']">
  <div *uiDrawerContent="{ container: shadowRoot }"></div>
</ng-container>
```

## Custom Rendering

Each directive goes on an element you write. Read a part's state from a template reference, like `#trigger="uiDrawerTrigger"` and then `trigger.state().open`, and the content's from `*uiDrawerContent="let content"`.

```angular-html
<button uiDrawerTrigger #drawerTrigger="uiDrawerTrigger" shortcut="mod+j">
  {{ drawerTrigger.state().open ? "Viewing" : "View Details" }}
</button>
<div *uiDrawerContent="let content">
  <h3 uiDrawerTitle>Quarterly report</h3>
  <p uiDrawerDescription>

</div>
```

### Events

A `before` output emits `{ value, reason, event, cancel() }` before the change, and its plain output follows with the value alone. A bound `open` or `snapPoint` only updates when its change isn't canceled.

| Binding                   | On         | Receives                                                                                   |
| ------------------------- | ---------- | ------------------------------------------------------------------------------------------ |
| `[(open)]`                | `uiDrawer` | Whether the drawer is open                                                                 |
| `[(snapPoint)]`           | `uiDrawer` | The snap point it rests on                                                                 |
| `(beforeOpenChange)`      | `uiDrawer` | `{ value, reason, cancel() }`: the new state, the [reason](#reasons) and any `returnValue` |
| `(openChangeComplete)`    | `uiDrawer` | `$event`, whether it's open, once it has settled                                           |
| `(beforePayloadChange)`   | `uiDrawer` | `{ value, reason, cancel() }`: the content's new payload, and the [reason](#reasons)       |
| `(beforeSnapPointChange)` | `uiDrawer` | `{ value, reason, cancel() }`: the new snap point and the [reason](#reasons)               |
| `(dismissAttempt)`        | `uiDrawer` | `{ reason, event }`, when a dismissal was refused                                          |

## Accessibility

The trigger is a button that opens a dialog, and the drawer follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/) while it's modal: `aria-modal`, focus trapped inside, the page inert, labelled by its title and described by its description. Escape closes it. The handle is a button that controls the drawer: a press moves to the next snap point, arrow keys along the drawer's axis step, and Home and End go to the ends. Every line below is an automated test.

### Keyboard

| Key                       | Does                                                                          |
| ------------------------- | ----------------------------------------------------------------------------- |
| Enter, Space              | On the trigger, opens the drawer; on the handle, moves to the next snap point |
| Arrow keys along the axis | On the handle, moves one snap point without wrapping                          |
| Home, End                 | On the handle, moves to the smallest or largest snap point                    |
| Tab, Shift+Tab            | Moves through the sheet's controls, staying inside while it's modal           |
| Escape                    | Closes the topmost drawer when it's dismissible                               |

It shares [Dialog’s focus behavior](./dialog#focus): focus moves inside on open and returns when it closes. A touch open focuses the content so a field does not summon the keyboard immediately, unless you set `initialFocus`. When the on-screen keyboard opens, the viewport shrinks and the focused field can scroll into view inside the sheet.
