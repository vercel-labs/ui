Use an alert dialog when someone needs to answer a question before an action continues, such as deleting a project.

<ComponentExample
  name="alert-dialog/basic"
  caption="Open the dialog with Enter to start on Cancel. Tab stays inside, clicking outside leaves it open, and Escape closes it and returns focus to the trigger."
/>

## Installation

```bash
npm install @ui-sdk/angular @ui-sdk/core
```

## Composition

Use the following composition to build AlertDialog:

```text
uiAlertDialog
├── uiAlertDialogTrigger
├── uiAlertDialogBackdrop
└── uiAlertDialogContent
    ├── uiAlertDialogTitle
    ├── uiAlertDialogDescription
    ├── uiAlertDialogClose
    └── uiAlertDialogClose
```

Put the question in `uiAlertDialogTitle`, explain what happens in `uiAlertDialogDescription`, and use `uiAlertDialogClose` for each answer. Add `uiAlertDialogBackdrop` to dim the page.

A Close part reports its `value` when it closes. `value="confirm"` is the agreeing answer that the [confirm helper](#confirm) recognizes.

## Usage

Import the parts and put them together:

```ts
import { Component } from "@angular/core"
import {
  AlertDialog,
  AlertDialogClose,
  AlertDialogContent,
  AlertDialogDescription,
  AlertDialogTitle,
  AlertDialogTrigger,
} from "@ui-sdk/angular/alert-dialog"

@Component({
  selector: "app-example",
  imports: [
    AlertDialog,
    AlertDialogClose,
    AlertDialogContent,
    AlertDialogDescription,
    AlertDialogTitle,
    AlertDialogTrigger,
  ],
  template: `
    <ng-container uiAlertDialog>
      <button uiAlertDialogTrigger>Delete Project</button>
      <div *uiAlertDialogContent>
        <h2 uiAlertDialogTitle>Delete this project?</h2>
        <p uiAlertDialogDescription>
          The project and its files will be deleted for everyone.
        </p>
        <button uiAlertDialogClose>Cancel</button>
        <button uiAlertDialogClose value="confirm">Delete</button>
      </div>
    </ng-container>
  `,
})
class Example {}

export { Example }
```

## Build Your Own

`@ui-sdk/angular/alert-dialog` comes with a ready-made Alert Dialog. If you'd like to build your own, with your own names, start from the `alertDialog` primitive in `@ui-sdk/core`:

```ts title="confirm.ts"
import { Directive, inject } from "@angular/core"
import { alertDialog } from "@ui-sdk/core/alert-dialog"
import { usePart, usePrimitive } from "@ui-sdk/angular/primitive"

@Directive({ selector: "[appConfirm]" })
class Confirm {
  readonly handle = usePrimitive(alertDialog, () => ({}))
}

@Directive({ selector: "[appConfirmTrigger]" })
class ConfirmTrigger {
  readonly state = usePart(inject(Confirm).handle, "trigger").state
}

@Directive({ selector: "[appConfirmBackdrop]" })
class ConfirmBackdrop {
  readonly state = usePart(inject(Confirm).handle, "backdrop").state
}

@Directive({ selector: "[appConfirmContent]" })
class ConfirmContent {
  readonly state = usePart(inject(Confirm).handle, "content").state
}

@Directive({ selector: "[appConfirmTitle]" })
class ConfirmTitle {
  readonly state = usePart(inject(Confirm).handle, "title").state
}

@Directive({ selector: "[appConfirmDescription]" })
class ConfirmDescription {
  readonly state = usePart(inject(Confirm).handle, "description").state
}

@Directive({ selector: "[appConfirmClose]" })
class ConfirmClose {
  readonly state = usePart(inject(Confirm).handle, "close").state
}

export {
  Confirm,
  ConfirmBackdrop,
  ConfirmClose,
  ConfirmContent,
  ConfirmDescription,
  ConfirmTitle,
  ConfirmTrigger,
}
```

```ts
import { Component } from "@angular/core"
import {
  Confirm,
  ConfirmBackdrop,
  ConfirmClose,
  ConfirmContent,
  ConfirmDescription,
  ConfirmTitle,
  ConfirmTrigger,
} from "./confirm"

@Component({
  selector: "app-confirm-example",
  imports: [
    Confirm,
    ConfirmBackdrop,
    ConfirmClose,
    ConfirmContent,
    ConfirmDescription,
    ConfirmTitle,
    ConfirmTrigger,
  ],
  template: `
    <ng-container appConfirm>
      <button appConfirmTrigger>Delete Project</button>
      <div appConfirmBackdrop></div>
      <div appConfirmContent>
        <h2 appConfirmTitle>Delete this project?</h2>
        <p appConfirmDescription>This permanently deletes the project.</p>
        <button appConfirmClose>Cancel</button>
        <button appConfirmClose value="confirm">Delete</button>
      </div>
    </ng-container>
  `,
})
export class ConfirmExample {}
```

Connect the other slots the same way, each with `usePart`. Each part keeps the behavior, state and data attributes of its ready-made counterpart: the content opens in the top layer, traps focus and makes the page inert. See [Rendering Primitives](../rendering) and [Custom Parts](../custom-parts) for more.

## Animation

The content has `data-starting-style` while it opens and `data-ending-style` while it closes. Transition from those states, and the dialog stays mounted until the exit finishes:

## Nested

An alert dialog opened inside another joins its stack, such as a second confirmation before something can't be undone. Escape closes the topmost one and returns focus to its trigger. The dialog underneath gets `data-nested-open`, so you can show which layer is active. To close both once the last question is answered, control the outer dialog with `[(open)]` and close it when the inner one's `(beforeOpenChange)` reports `returnValue` `"confirm"`.

## Async Action

An `(action)` on a Close part runs before it closes the dialog. Pass a Promise to `$event.waitUntil()` to keep the dialog open until the work finishes. A resolved Promise closes it with the reason `action`; a rejection keeps it open and puts the error in that part's state.

<ComponentExample
  name="alert-dialog/async-action"
  caption="Choose Delete Project, then Delete. The first attempt fails so you can try again. While Deleting… is shown, Cancel and Escape leave the dialog open. A successful retry closes it."
/>

While the action runs, its button stays focusable and gets `data-pending`, `aria-busy`, and `aria-disabled`. Other Close parts get `aria-disabled` and `data-disabled`, and neither they nor dismissals can close the dialog until it settles. `(dismissAttempt)` reports refused dismissals; a controller can still close it.

The root's `pendingAnnouncement` sets what screen readers hear after a second of waiting. The error clears on the next attempt or when the dialog opens again. The action also receives `{ source }` after its event argument; [Changes After an Await](./button#changes-after-an-await) explains when to use it.

## Confirm

Use `createConfirm<Payload>()` to ask a question from an event handler and await the answer. Create it once, then pass its `controller` to your alert dialog. The content reads the question's data from its state, `*uiAlertDialogContent="let content"`, as `content.payload`. In a template the payload is `unknown`, so give it its type in a method, like the example's `payloadOf()`.

`await confirm({ name })` resolves `true` when the Close part with `value="confirm"` closes the dialog. Cancel, Escape, and other answers resolve `false`. This lets several rows share one dialog:

<ComponentExample
  name="alert-dialog/confirm"
  caption="Delete a project. Cancel or Escape keeps it; Delete removes it and focuses a neighboring row's button. Reset Projects brings the list back."
/>

When the action removes the button that opened the dialog, choose a useful place for focus to go. This example focuses a neighboring row, or Reset Projects when the list is empty.

## Accessibility

Give the dialog a title and a description, and put the least destructive answer first. It follows the [WAI-ARIA alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/).

The dialog uses the `alertdialog` role and keeps the rest of the page inert while it's open. Screen readers announce its title and description. Opening it focuses the first Close part, so put Cancel first. A touch open focuses the content instead, so no on-screen keyboard appears, unless you set `initialFocus`. Escape closes the dialog, but pressing outside never does. [Dialog](./dialog#focus) covers other initial and final focus targets.
