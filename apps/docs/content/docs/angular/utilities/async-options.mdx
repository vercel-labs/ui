`useAsyncOptions` loads items as someone types. It waits for typing to pause, cancels requests that are replaced, and keeps the previous results visible while loading.

## Load Results

Pass a loader to the helper in a field initializer. This example expects `/api/movies` to return an array of movie titles:

```ts
import { Component } from "@angular/core"
import { useAsyncOptions } from "@ui-sdk/angular/async-options"
import {
  Combobox,
  ComboboxContent,
  ComboboxInput,
  ComboboxItems,
} from "@ui-sdk/angular/combobox"

@Component({
  selector: "app-movie-search",
  imports: [Combobox, ComboboxContent, ComboboxInput, ComboboxItems],
  template: `
    <ng-container
      uiCombobox
      [items]="movies.state().items"
      [filter]="false"
      [status]="movies.state().status"
      (queryChange)="movies.setQuery($event)"
    >
      <input uiComboboxInput aria-label="Movie" placeholder="Search movies…" />
      <div *uiComboboxContent>
        <div uiComboboxItems></div>
      </div>
    </ng-container>
  `,
})
export class MovieSearch {
  readonly movies = useAsyncOptions<string>(async (query, { signal }) => {
    const response = await fetch(`/api/movies?q=${encodeURIComponent(query)}`, {
      signal,
    })
    if (!response.ok) throw new Error("Couldn't load movies")
    return response.json()
  })
}
```

`movies.state` is a signal, so the template follows each load. Pass `signal` to `fetch` so a newer search can cancel the request. The helper cancels when the component is destroyed. `[filter]="false"` leaves matching and ordering to the server.

Use `uiComboboxStatus` and `uiComboboxEmpty` to show loading, error, and empty messages, as in the demo. The same pattern works with [Select](../components/select#async-search), [Autocomplete](../components/autocomplete#async-suggestions), and [Command](../components/command#async-results).

## Choose When to Load

The second argument sets the starting behavior:

| Option      | What It Does                                                                    | Default |
| ----------- | ------------------------------------------------------------------------------- | ------- |
| `debounce`  | Milliseconds typing must pause before a request starts.                         | `200`   |
| `query`     | The starting search text.                                                       | `""`    |
| `immediate` | Loads that text as soon as the component renders in the browser.                | `false` |
| `minLength` | Characters the text needs before anything loads. Shorter text clears the items. | `0`     |

For initial choices, add `{ immediate: true, debounce: 300 }` after the loader. Until that first load starts, `status` is already `"loading"`, so the list never flashes an empty state. If you set `query`, use the same starting text for the component's `defaultQuery`.

## Load More

For paged results, the loader receives `page`, starting at `0`. Return `{ items, hasMore }`:

```ts
import type { AsyncOptionsContext } from "@ui-sdk/angular/async-options"

async function loadMoviePages(
  query: string,
  { signal, page }: AsyncOptionsContext
) {
  const response = await fetch(
    `/api/movies?q=${encodeURIComponent(query)}&page=${page}`,
    { signal }
  )
  if (!response.ok) throw new Error("Couldn't load movies")
  const data: { titles: string[]; next: number | null } = await response.json()
  return { items: data.titles, hasMore: data.next !== null }
}

export { loadMoviePages }
```

Pass `loadMoviePages` to `useAsyncOptions` in place of the inline loader above.

Connect `(loadMore)="movies.loadMore()"` on the combobox. It asks for another page when scrolling or keyboard navigation reaches the last item. The helper appends the new items.

## Retry a Search

`status` is `"loading"` during a request, `"error"` after a failure, and `"idle"` otherwise. `error` holds the failure, and the previous items stay available.

Call `movies.reload()` from a retry button to load the current query again, starting at page `0`. `movies.state().hasMore` tells you whether another page is available.
