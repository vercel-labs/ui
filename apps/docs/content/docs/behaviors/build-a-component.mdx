## Install

Start by installing `@ui-sdk/core`.

```
npm add @ui-sdk/core
```

## Define the Button

The button has one piece of state: `muted`, which is `true` when mute is on.

A **primitive** keeps that state, the functions that change it, and the parts that use it together. Ours has just one part: the button.

```ts title="lib/mute-button.ts"
import { definePrimitive } from "@ui-sdk/core"

const muteButton = definePrimitive({
  name: "mute-button",
  state: () => ({ muted: false }),
  api: (context) => ({
    toggle: () => context.store.set({ muted: !context.store.get().muted }),
  }),
  slots: (slot) => ({
    root: slot({
      attrs: (state) => ({ type: "button", "aria-pressed": String(state.muted) }),
      press: ({ api }) => api.toggle(),
    }),
  }),
})

export { muteButton }
```

- `state` starts `muted` at `false`.
- `api` defines `toggle`, which switches `muted` between `true` and `false`.
- `slots` describes the component's parts. Our only **slot** is `root`, the button.
- `attrs` turns state into HTML attributes. When `muted` is `true`, the button gets `aria-pressed="true"`.
- `press` calls `toggle` when the button is activated.

That's the whole behavior. Now let's put it on the page.

Because we use a native `<button>`, clicks, Enter and Space all reach the primitive's `press` handler. Screen readers get its pressed state from `aria-pressed`.

The behavior stays in `mute-button.ts`. Changing frameworks changes how you render it, but the behavior stays the same.

### CSS

You can target the same attribute in a stylesheet:

```css
[data-slot="mute-button-root"][aria-pressed="true"] {
  background: #171717;
  color: white;
}
```

`data-slot` identifies the part. `aria-pressed` says whether it's on. These attributes are the same in every framework, so this CSS works for all five versions.

## Control the State

So far, the button manages its own state. Let's control it from a parent component and use that state to change its icon and label.

We'll use another helper from `@ui-sdk/core`: `createChange`. Update `lib/mute-button.ts` with the highlighted changes:

```ts title="lib/mute-button.ts" {1,5-19,22-23}
import { createChange, definePrimitive } from "@ui-sdk/core"

const muteButton = definePrimitive({
  name: "mute-button",
  options: { muted: "boolean", onMutedChange: "callback" },
  controlled: ["muted"],
  state: (options: { muted?: boolean; onMutedChange?: (muted: boolean) => void }) => ({
    muted: options.muted ?? false,
  }),
  sync: (options) => (options.muted === undefined ? {} : { muted: options.muted }),
  api: (context) => {
    const change = createChange(context)

    return {
      toggle: (event?: Event) => {
        change("muted", !context.store.get().muted, { reason: "press", event })
      },
    }
  },
  slots: (slot) => ({
    root: slot({
      attrs: () => ({ type: "button" }),
      press: ({ api }, event) => api.toggle(event),
    }),
  }),
})

export { muteButton }
```

- `options` adds the value and callback. `controlled` marks `muted` as a state value that can be controlled.
- `state` sets the initial value. `sync` keeps it up to date when a new `muted` value comes in.
- `createChange` calls `onMutedChange` with the next value and waits for it to come back through `muted`. If you leave out `muted`, it updates the button's own state.

The label now describes the next action, so this version doesn't need `aria-pressed`.

### Connect the State

Now use `muted` for the button, its icon and its label:

<FrameworkContent value="react">

```tsx title="pages/index.tsx"
"use client"

import * as React from "react"
import { Volume2Icon, VolumeXIcon } from "lucide-react"
import { MuteButton } from "@/components/ui/mute-button"

function Example() {
  const [muted, setMuted] = React.useState(false)

  return (
    <MuteButton muted={muted} onMutedChange={setMuted}>
      {muted ? <VolumeXIcon aria-hidden="true" /> : <Volume2Icon aria-hidden="true" />}
      {muted ? "Unmute" : "Mute"}
    </MuteButton>
  )
}

export { Example }
```

Then listen for `mutedchange` from your browser entry point, after the button's markup is on the page:

```ts title="main.ts"
import "@/components/ui/mute-button"

let muted = false
const button = document.querySelector("mute-button")
const icon = button?.querySelector("[data-volume]")
const label = button?.querySelector("[data-label]")

if (button && icon && label) {
  button.addEventListener("mutedchange", (event) => {
    muted = (event as CustomEvent<{ value: boolean }>).detail.value
    button.setAttribute("muted", String(muted))
    icon.setAttribute("d", muted ? "m16 9 6 6m0-6-6 6" : "M16 9a5 5 0 0 1 0 6m3-9a9 9 0 0 1 0 12")
    label.textContent = muted ? "Unmute" : "Mute"
  })
}
```

The adapter reads `muted="false"` as the boolean `false`. Each event updates the value, icon and label together.
