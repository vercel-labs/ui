A file input holds the files someone chooses, drops, or pastes, checks them against your rules, and submits them with a form. Uploading them to a server is up to your app.

<ComponentExample

/>

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `FileInput`:

```text
FileInput
├── FileInputTrigger
├── FileInputDropzone
└── FileInputList
    └── FileInputItem
        └── FileInputItemRemove
```

The trigger opens the system file picker. The drop zone takes files that are dropped on it or pasted while focus is inside it; keep a trigger beside it for people using a keyboard. The list renders its item once for each file, and an item's slot state has its `file` and `index`. A remove button removes its item's file.

## Usage

Import the parts and put them together:

```vue
<script setup lang="ts">
import { XIcon } from "@lucide/vue"
import {
  FileInput,
  FileInputDropzone,
  FileInputItem,
  FileInputItemRemove,
  FileInputList,
  FileInputTrigger,
  formatFileSize,
} from "@ui-sdk/vue/file-input"
</script>

<template>
  <FileInput name="attachments" multiple>
    <FileInputDropzone>
      <p>Drag and drop files here</p>
      <FileInputTrigger>Browse Files</FileInputTrigger>
    </FileInputDropzone>
    <FileInputList aria-label="Files">
      <FileInputItem v-slot="{ state }">
        <span>{{ state.file.name }}</span>
        <span>{{ formatFileSize(state.file.size) }}</span>
        <FileInputItemRemove>
          <XIcon aria-hidden="true" />
        </FileInputItemRemove>
      </FileInputItem>
    </FileInputList>
  </FileInput>
</template>
```

## Upload Button

A trigger is enough when you only need the system file picker. Read the chosen file from the root's slot state to show its name beside the button.

```vue
<FileInput v-slot="{ state }" name="resume">
  <FileInputTrigger>Upload Resume</FileInputTrigger>
  <span>{{ state.value[0]?.name ?? "No file chosen" }}</span>
</FileInput>
```

## Accepted Types

`accept` takes MIME types, wildcards, and extensions, such as `image/*` and `.pdf`. It checks files from the picker, drops, and pastes. An extension matches the filename, even when the operating system reports an unexpected MIME type.

A rejected file never joins the value. `@reject` receives each one with its `reasons`, such as `file-type`, so you can say why it was left out. While files are dragged over a drop zone, `data-drag-reject` shows when their types won't be accepted.

```vue
<FileInput multiple :accept="['image/*', '.pdf']" @reject="(next) => (rejected = next)">
```

## Limits

Use `max-files` to limit the total count, and `min-size` or `max-size` for bytes per file. When too many files arrive, the component accepts the first ones that pass the other checks until the list is full, and rejects the rest with `too-many-files`.

```vue
<FileInput multiple :max-files="3" :min-size="1" :max-size="5_000_000">
```

## One File

Without `multiple`, a new file replaces the current one. A rejected file leaves the current value unchanged. With `multiple`, accepted files join the list.

```vue
<FileInput v-slot="{ state }" accept=".pdf">
  <FileInputTrigger>{{ state.value[0] ? "Replace PDF" : "Choose a PDF" }}</FileInputTrigger>
</FileInput>
```

## Validation

Add `validate` for checks of your own. Return a reason string to reject a file, or `null` to accept it. It runs after the built-in type and size checks, and its reason reaches `@reject` like theirs. Validate uploads on your server too.

```vue
<script setup lang="ts">
const files = createFileInputController()
</script>

<FileInput
  multiple
  :controller="files"
  :validate="(file: File) => (files.getValue().some((other) => other.name === file.name) ? 'duplicate' : null)"
  @reject="(next) => (rejected = next)"
>
```

## File List

The list has one Tab stop. Arrow keys, Home, and End move between files; Delete or Backspace removes the focused file. Remove buttons are named for their file and stay outside the Tab order.

For an image preview, create an object URL for the file and revoke it when the item goes away:

```vue
<FileInputItem v-slot="{ state }">
  <Preview :file="state.file" />
  <span>{{ state.file.name }}</span>
  <FileInputItemRemove>
    <XIcon aria-hidden="true" />
  </FileInputItemRemove>
</FileInputItem>
```

```vue
<!-- Preview.vue -->
<script setup lang="ts">
import { ref, watchEffect } from "vue"

const props = defineProps<{ file: File }>()
const url = ref<string>()

watchEffect((onCleanup) => {
  const next = URL.createObjectURL(props.file)
  url.value = next
  onCleanup(() => URL.revokeObjectURL(next))
})
</script>

<template>
  <img v-if="url" :src="url" alt="" />
</template>
```

## Attachments

Put a textarea inside a drop zone to attach files to a message. `paste-target` takes file pastes from the textarea too; text pastes keep their normal behavior. It can also be another element, a CSS selector, or `"document"`.

```vue
<script setup lang="ts">
const message = ref<HTMLTextAreaElement | null>(null)
</script>

<template>
  <FileInput multiple>
    <FileInputDropzone :paste-target="() => message">
      <FileInputList aria-label="Attachments">
        <FileInputItem v-slot="{ state }">{{ state.file.name }}</FileInputItem>
      </FileInputList>
      <textarea ref="message" aria-label="Message" />
      <FileInputTrigger aria-label="Attach Files">
        <PlusIcon aria-hidden="true" />
      </FileInputTrigger>
    </FileInputDropzone>
  </FileInput>
</template>
```

## Page-Wide Drop

Set `target="document"` to take files dropped anywhere on the page. The zone shows `data-dragging` while a file is over the window, so it can be a full-page overlay. A drop on another zone stays with that zone.

<ComponentExample
  name="file-input/page"
  caption="Drag a file over this page to see the overlay, then drop it. The file joins the Attachments list; a drop on the first example's zone stays there."
/>

While a drop zone is mounted, dropping a file outside every zone doesn't navigate away from the page. Drops onto native file inputs and ordinary text drops keep their behavior.

## Folders

`directory` picks a whole folder and turns on `multiple`. Dropped folders are read recursively, up to 1,000 files, skipping system files such as `.DS_Store`. `relativePath(file)` returns the path inside the folder.

```vue
<FileInput directory>
  <FileInputTrigger>Choose a Folder</FileInputTrigger>
  <FileInputList aria-label="Files">
    <FileInputItem v-slot="{ state }">{{ relativePath(state.file) }}</FileInputItem>
  </FileInputList>
</FileInput>
```

## Camera

Use `capture="environment"` to request the rear camera, or `"user"` for the front camera. The picker offered depends on the device and browser; a desktop browser opens a file picker.

```vue
<FileInput accept="image/*" capture="environment">
  <FileInputTrigger>Take a Photo</FileInputTrigger>
</FileInput>
```

## Controlled

Pass `value` and update it in `@value-change`, or bind it with `v-model:value`. `details` has the `reason` and the `added`, `removed`, and `rejected` files. Call `details.cancel()` to keep the current value. `@reject` reports rejected files even when none were accepted.

```vue
<script setup lang="ts">
const files = ref<File[]>([])
</script>

<FileInput multiple :value="files" @value-change="(value) => (files = value)">
```

## Opening from Anywhere

Create a controller with `createFileInputController()` and pass it to `FileInput`. Use it to open the picker, add or remove files, clear the value, or read the files. Open the picker from a user action, such as a button press, so the browser allows it. A `FileInputTrigger` outside the file input connects through the same `controller` prop.

```vue
<script setup lang="ts">
const attachments = createFileInputController()
</script>

<template>
  <button type="button" @click="attachments.open()">Choose Files</button>
  <button type="button" @click="attachments.clear()">Clear</button>
  <FileInput multiple :controller="attachments" />
</template>
```

## Announcements

The component announces accepted, removed, and rejected files through a polite live region. Use `announcement` to change the message, or return `null` to skip it.

```vue
<FileInput
  multiple
  :announcement="
    ({ added, removed }) =>
      added.length
        ? `Added ${added.map((file) => file.name).join(', ')}.`
        : removed.length
          ? `Removed ${removed.map((file) => file.name).join(', ')}.`
          : null
  "
>
```

## Forms

With `name`, the component submits its files through a native file input, which can submit before hydration. A form reset returns to `default-value`. `form` connects the file input to a form elsewhere on the page. Rejected files never submit, and `disabled` leaves the value out of the submission as well as stopping picks, drops, and pastes.

```vue
<form method="post" enctype="multipart/form-data">
  <FileInput name="attachments" multiple :default-value="[coverLetter]">
    <FileInputTrigger>Attach Files</FileInputTrigger>
  </FileInput>
  <button type="submit">Send</button>
  <button type="reset">Reset</button>
</form>
```

## Fields

Wrap the file input in a [Field](./field) to connect its label, description, and validation message. The trigger becomes the field's control, and pressing the label opens the picker. `required` stops the form from submitting with no file.

```vue
<Field>
  <FieldLabel>Proof of address</FieldLabel>
  <FileInput name="proof" required :accept="['image/*', '.pdf']">
    <FileInputTrigger>Choose a File</FileInputTrigger>
  </FileInput>
  <FieldDescription>A utility bill or bank statement from the last 3 months.</FieldDescription>
  <FieldError match="valueMissing">Add a scan to continue.</FieldError>
</Field>
```

## Custom Rendering

Every part takes a `render` slot, to render a different element in its place. It receives the props to bind and the part's state. The default slot of the root, the drop zone, and an item receives the part's state too, as `v-slot="{ state }"`:

```vue
<FileInputDropzone>
  <template #render="{ props, state }">
    <section v-bind="props" aria-label="Gallery upload">
      {{ state.dragReject ? "Images only" : state.dragAccept ? "Release to add" : "Drag images here" }}
    </section>
  </template>
</FileInputDropzone>
<FileInputList aria-label="Images">
  <template #render="{ props, children }">
    <ul v-bind="props">
      <component :is="children" />
    </ul>
  </template>
  <FileInputItem>
    <template #render="{ props, state }">
      <li v-bind="props">{{ state.index + 1 }}. {{ state.file.name }}</li>
    </template>
  </FileInputItem>
</FileInputList>
```

See [Parts and Composition](../parts-and-composition) for more on `render`.

## Styling

Use `data-dragging`, `data-drag-accept`, and `data-drag-reject` on the drop zone to show what a drop would do. Drag acceptance reflects the file information the browser exposes before a drop. Inside a Field, the trigger also gets the field's attributes, such as `data-invalid`.

Each part has a `data-slot`, such as `file-input-dropzone`, and its state attributes are listed under [Data Attributes](#data-attributes).
