Use a toggle for a button that stays on until you press it again, like starring a document or turning on Bold. Put several in a toggle group to share one value, as a text editor's formatting buttons or a view switcher do.

<ComponentExample
  name="toggle/basic"
  caption="Press the star beside Q3 Roadmap, or focus it and press Enter or Space. It fills in while pressed, and its accessible name stays Star."
/>

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Toggle`:

```text
Toggle
└── ToggleIcon
```

And a `ToggleGroup`:

```text
ToggleGroup
├── Toggle
│   └── ToggleIcon
└── Toggle
    └── ToggleIcon
```

`Toggle` renders a native button that reports its state with `aria-pressed`. `ToggleIcon` is optional: it holds an icon and hides it from screen readers. In a group, give each toggle a `value`; the group's value lists the pressed ones.

## Usage

Import the parts and put them together:

```vue
<script setup lang="ts">
import { StarIcon } from "@lucide/vue"
import { Toggle, ToggleIcon } from "@ui-sdk/vue/toggle"
</script>

<template>
  <Toggle aria-label="Star">
    <ToggleIcon>
      <StarIcon />
    </ToggleIcon>
  </Toggle>
</template>
```

Keep the label the same in both states: screen readers announce whether the button is pressed. An icon-only toggle needs an `aria-label`, as above. Set `default-pressed` to start pressed. The toggle always uses `type="button"`, so pressing it never submits a form.

## Group

Put toggles in a `ToggleGroup`, from the same `@ui-sdk/vue/toggle` entry, to share a value and arrow-key navigation. Give the group an accessible name and each toggle a `value`. Set `multiple` to let several toggles stay pressed.

<ComponentExample
  name="toggle/group"
  caption="Press Bold and Italic to keep both pressed. Left and Right move focus without changing either."
/>

The group owns which toggles are pressed, so a toggle's own `pressed` and `default-pressed` don't apply inside it. Its value is always an array, in the toggles' document order.

## Single Selection

Without `multiple`, pressing a toggle unpresses the others. Pressing the pressed toggle again clears the selection, unless you set `deselectable` to `false`, as this alignment group does. `deselectable` doesn't choose an initial value for you, so pair it with `default-value`.

<ComponentExample
  name="toggle/group-single"
  caption="Press Align center to replace Align start, then press Align center again. One alignment always stays pressed."
/>

`mirror` on Align start and Align end flips their icons in right-to-left text. Use [Radio](./radio) instead when the arrow keys should select an option as they move; a toggle group moves focus first and waits for a press.

## Icon and Label

Put an icon beside the label with `ToggleIcon`. The icon is hidden from screen readers, so the text alone names the button.

```vue
<Toggle>
  <ToggleIcon>
    <PinIcon />
  </ToggleIcon>
  Pin
</Toggle>
```

## Disabled

Set `disabled` on a toggle or a group to prevent presses. A disabled toggle can still start pressed, and a disabled `<fieldset>` around it disables it too.

```vue
<Toggle disabled default-pressed>Pin</Toggle>
```

A disabled toggle on its own leaves the tab order. In a group, disabled toggles stay reachable with the arrow keys and report `aria-disabled`, but ignore presses.

```vue
<ToggleGroup multiple aria-label="Text formatting">
  <Toggle value="bold">Bold</Toggle>
  <Toggle value="italic">Italic</Toggle>
  <Toggle value="underline" disabled>Underline</Toggle>
</ToggleGroup>
```

## Focusable When Disabled

Set `focusable-when-disabled` to keep a disabled toggle focusable. It uses `aria-disabled` and still ignores presses. Use `aria-describedby` to explain why it's unavailable:

```vue
<Toggle disabled focusable-when-disabled aria-describedby="pin-hint">Pin</Toggle>
<p id="pin-hint">Only owners can pin messages.</p>
```

## Controlled

Bind `v-model:pressed`, or pass `pressed` and update it in `@pressed-change`. Call `details.cancel()` in the handler to keep the current state. A [controller](#toggle-controller) from `createToggleController()` presses the toggle from anywhere, such as a keyboard shortcut. Create one controller per mounted toggle.

```vue
<script setup lang="ts">
import { StarIcon } from "@lucide/vue"
import { createToggleController, Toggle, ToggleIcon } from "@ui-sdk/vue/toggle"
import { ref } from "vue"

const starred = ref(false)
const star = createToggleController()
</script>

<template>
  <Toggle v-model:pressed="starred" aria-label="Star" :controller="star">
    <ToggleIcon>
      <StarIcon />
    </ToggleIcon>
  </Toggle>
  <button type="button" @click="star.toggle()">Toggle Star</button>
</template>
```

`@pressed-change` receives the new state and `details`, whose `reason` is `"press"` or `"imperative"`.

## Controlled Group

Bind `v-model:value`, or pass `value` and update it in `@value-change`, to own the group's value, or to show it somewhere else. A toggle's own `@pressed-change` runs before the group's, and calling `details.cancel()` in either cancels the change. A [controller](#togglegroup-controller) from `createToggleGroupController()` changes the value from anywhere: `setValue([])` clears it.

```vue
<script setup lang="ts">
import { createToggleGroupController, Toggle, ToggleGroup } from "@ui-sdk/vue/toggle"
import { ref } from "vue"

const formats = ref(["bold"])
const editor = createToggleGroupController()
</script>

<template>
  <ToggleGroup v-model:value="formats" multiple aria-label="Text formatting" :controller="editor">
    <Toggle value="bold">Bold</Toggle>
    <Toggle value="italic">Italic</Toggle>
  </ToggleGroup>
  <button type="button" @click="editor.setValue([])">Clear Formatting</button>
</template>
```

See [State and Events](../state-and-events) for controlled state, cancellation and debugging.

## Vertical

Set `orientation="vertical"` to move with Up and Down instead of Left and Right. The group and its toggles get `data-orientation`.

```vue
<ToggleGroup orientation="vertical" aria-label="Tool">
  ...
</ToggleGroup>
```

## Loop

Arrow keys wrap from the last toggle to the first. Set `loop` to `false` to stop at the ends.

```vue
<ToggleGroup multiple :loop="false" aria-label="Text formatting">
  ...
</ToggleGroup>
```

## Forms

Toggles don't submit values. Use [Checkbox](./checkbox) for several form choices or [Radio](./radio) for one. If you keep a toggle group in a form, copy its value into hidden inputs yourself.

## Custom Rendering

Every part takes a `#render` slot, which receives the props to bind and the part's state. A toggle's state has `pressed`, and a group's has `value`, its pressed values. Keep the part's props on the button, so its `aria-pressed` and keyboard behavior stay connected. See [Parts and Composition](../parts-and-composition) for the rendering contract.

## Styling

Style the pressed state with `data-pressed`, and use `data-disabled` for unavailable toggles. A toggle with a `ToggleIcon` gets `data-has-icon`, and its group gets `data-has-icons` while any toggle has one, which helps align icon and text content. `data-orientation` tells a group's toggles which way it runs.

Each part has a `data-slot`, such as `toggle-root`, and its state attributes are listed under [Data Attributes](#data-attributes).

### Events

Events get the new state or value first, then the details. `@value-change` never runs on mount, and `v-model` only updates when the change event wasn't canceled.

| Binding           | On            | Receives                                                                                                                     |
| ----------------- | ------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `v-model:pressed` | `Toggle`      | Whether the toggle is pressed                                                                                                |
| `@pressed-change` | `Toggle`      | `(pressed, details)`: the new state, and the [reason](#reasons). In a group, it runs first and can cancel the group's change |
| `v-model:value`   | `ToggleGroup` | The pressed toggles' values                                                                                                  |
| `@value-change`   | `ToggleGroup` | `(value, details)`: the pressed toggles' values, and the [reason](#reasons)                                                  |

## Accessibility

A toggle follows the toggle button in the [WAI-ARIA button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/): a native button with `aria-pressed`. A group follows the keyboard of the [WAI-ARIA toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/), with one tab stop and arrow keys between toggles. It has the `group` role, not `toolbar`, so it can sit inside a [Toolbar](./toolbar), and not `radiogroup`, since its toggles are buttons.

### Keyboard

A group is one tab stop. Tab first enters on its first enabled pressed toggle, or its first enabled toggle, and later returns to the last focused one.

| Key          | Does                                                    |
| ------------ | ------------------------------------------------------- |
| Enter, Space | Presses or unpresses the focused toggle                 |
| Tab          | Moves into or out of a group                            |
| Left, Right  | Move focus in a horizontal group, swapped right to left |
| Up, Down     | Move focus in a vertical group                          |
| Home, End    | Move focus to the first or last toggle                  |
