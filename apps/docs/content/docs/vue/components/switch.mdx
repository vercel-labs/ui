A switch changes a setting between on and off. Keep its label the same in both states: “Airplane Mode” tells you what changes; the switch tells you whether it is on.

<ComponentExample
  name="switch/basic"
  caption="Click Airplane Mode, or focus it and press Space, to turn it on and off."
/>

## Installation

```package-install
npm install @ui-sdk/vue
```

## Composition

Use the following composition to build a `Switch`:

```text
Switch
└── SwitchThumb
```

`Switch` renders a button with `role="switch"`. `SwitchThumb` stays mounted and reflects the checked state, so CSS can slide it. The switch adds a hidden native checkbox for form submission, validation, and reset.

### Controlled

Use `v-model:checked` when your component owns the value. Use `default-checked` when the switch should own it. Pass a controller from `createSwitchController()` when another control needs to toggle it. The [state and events guide](../state-and-events) covers the shared change callback contract.

<ComponentExample
  name="switch/controlled"
  caption="Change Wi-Fi directly or press Toggle from outside. The readout shows the value and what caused the change."
/>

### Read Only

`readOnly` keeps the switch focusable and included in form submissions, while preventing changes. It works well for a setting managed elsewhere.

<ComponentExample
  name="switch/read-only"
  caption="Focus or click Encrypt backups. It stays on because the organization manages this setting."
/>

<span id="forms" />

### Form

Give each switch a `name`. An on switch submits its `value`, which defaults to `"on"`; an off switch submits nothing. Use `form` to connect a switch outside the form, and Reset to restore the defaults. See [forms](../forms) for the shared validation and reset behavior.

<ComponentExample
  name="switch/form"
  caption="Change the email settings and Join the beta, then press Save to inspect the submitted values. Reset restores the defaults and clears the result."
/>

### Saving on Toggle

Call `details.cancel()` synchronously in the change callback to keep the current value while a save runs. On success, call `controller.setChecked(next, { reason: "imperative" })`. Let that reason through in the callback so the saved value can commit.

This example blocks repeated changes while saving and announces the result. `aria-busy` describes the pending work; the callback is what prevents another change.

<ComponentExample
  name="switch/async"
  caption="Toggle Automatic backups. The switch keeps its value while Saving… is shown, then changes after the save finishes."
/>

## Styling

<span id="size" />
<span id="right-to-left" />

Style the track and thumb with `data-checked`, `data-unchecked`, `data-disabled`, and `data-readonly`. Validation adds `data-invalid` and `aria-invalid` to the control. The thumb receives the switch state, not the field’s validation state.

The examples reverse the thumb’s translation under `dir="rtl"` and disable transitions for reduced motion. See [styling and animation](../styling-and-animation) for the shared styling contract.

### Events

Events get the new state first, then the details. `v-model` only updates when the change event wasn't canceled.

| Binding           | On       | Receives                                                        |
| ----------------- | -------- | --------------------------------------------------------------- |
| `v-model:checked` | `Switch` | Whether the switch is on                                        |
| `@checked-change` | `Switch` | `(checked, details)`: the new state, and the [reason](#reasons) |
