A dialog gives a task its own space: share a link, edit a record, or collect a few details. It manages focus, Escape, outside presses, and returning to where you started.

<ComponentExample
  name="dialog/basic"
  caption="Open Share, then close it with either Close button, Escape, or a press outside. Focus returns to Share."
/>

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Dialog`:

```text
Dialog
├── DialogTrigger
├── DialogBackdrop
└── DialogContent
    ├── DialogTitle
    ├── DialogDescription
    └── DialogClose
```

The title names the dialog; the description gives it context. A dialog can have several Close parts. Give an icon-only close button an accessible name, as the first example does.

The backdrop is optional. Without one, style the content’s `::backdrop`. For a question that requires an explicit answer, use [Alert Dialog](./alert-dialog).

## Usage

Import the parts and put them together:

```vue
<script setup lang="ts">
import {
  Dialog,
  DialogBackdrop,
  DialogClose,
  DialogContent,
  DialogDescription,
  DialogTitle,
  DialogTrigger,
} from "@ui-sdk/vue/dialog"
</script>

<template>
  <Dialog>
    <DialogTrigger>Open</DialogTrigger>
    <DialogBackdrop />
    <DialogContent>
      <DialogTitle>Project details</DialogTitle>
      <DialogDescription>Review the details before continuing.</DialogDescription>
      <DialogClose>Close</DialogClose>
    </DialogContent>
  </Dialog>
</template>
```

## Build Your Own

`@ui-sdk/vue/dialog` comes with a ready-made Dialog. If you'd like to build your own, with your own names, start from the `dialog` primitive in `@ui-sdk/core`:

```ts title="share.ts"
import { dialog } from "@ui-sdk/core/dialog"
import { createParts } from "@ui-sdk/vue/primitive"

const {
  Root: Share,
  Trigger: ShareTrigger,
  Backdrop: ShareBackdrop,
  Content: SharePanel,
  Title: ShareTitle,
  Description: ShareDescription,
  Close: ShareClose,
} = createParts(dialog, {
  trigger: "button",
  backdrop: "div",
  content: "div",
  title: "h2",
  description: "p",
  close: "button",
})

export { Share, ShareBackdrop, ShareClose, ShareDescription, SharePanel, ShareTitle, ShareTrigger }
```

```vue
<template>
  <Share>
    <ShareTrigger>Share</ShareTrigger>
    <ShareBackdrop />
    <SharePanel>
      <ShareTitle>Share this page</ShareTitle>
      <ShareDescription>Anyone with the link can view it.</ShareDescription>
      <ShareClose>Done</ShareClose>
    </SharePanel>
  </Share>
</template>
```

Each part keeps the behavior, state and data attributes of its ready-made counterpart: the content opens in the top layer, traps focus and makes the page inert. See [Rendering](../rendering) and [Custom Parts](../custom-parts) for more.

## Scrollable Content

Keep the header and actions outside the scrolling area. A viewport height limit, a shrinking middle grid row, and `overflow-y: auto` keep long content usable. `initial-focus="content"` focuses the dialog itself so reading starts at the top.

## Forms

A form with `method="dialog"` closes the dialog on a valid submission. The submit button’s `value` becomes the `returnValue`, just like a Close part’s `value`. An ordinary form stays open until you close the dialog yourself.

## Focus

Use `initial-focus` to pick where focus starts, and `final-focus` to choose where it goes after closing. Each takes a selector, an element or a function returning one. The default returns to the trigger, or to the element focused before a controller opened the dialog. See [popup focus](../popups#focus) for the shared focus rules.

```vue
<DialogContent initial-focus="#invite-email" :final-focus="() => nextStep" />
```

## Controlled

Use `v-model:open` to keep the dialog's state in your component. Cancel a proposed change with `details.cancel()` in `@open-change`. `@open-change-complete` reports when opening or closing has finished; see [state and events](../state-and-events) for the common change contract.

## Animation

The content and backdrop have `data-starting-style` while they open and `data-ending-style` while they close. Transition from those states, and the dialog stays mounted until the exit finishes. `@open-change-complete` runs after the transition, and `keep-mounted` keeps the content in the page while closed.

<StyleTabs>

```css
[data-slot="dialog-content"] {
  transition:
    opacity 0.2s,
    translate 0.25s cubic-bezier(0.22, 1, 0.36, 1),
    scale 0.25s cubic-bezier(0.22, 1, 0.36, 1);

  &:is([data-starting-style], [data-ending-style]) {
    opacity: 0;
    translate: 0 16px;
    scale: 0.96;
  }

  &[data-ending-style] {
    transition-duration: 0.15s;
  }
}
```

```vue
<DialogContent
  class="transition-[opacity,translate,scale] duration-250 ease-[cubic-bezier(0.22,1,0.36,1)] data-starting-style:translate-y-4 data-starting-style:scale-96 data-starting-style:opacity-0 data-ending-style:translate-y-4 data-ending-style:scale-96 data-ending-style:opacity-0 data-ending-style:duration-150"
/>
```

## Modal

`modal` controls how the dialog shares the page:

- `true`, the default, makes the page inert, locks scrolling, and keeps Tab inside.
- `"trap-focus"` keeps Tab inside while the page can still scroll and receive clicks. A click on the page also closes the dialog, unless `close-on-outside-press` is false.
- `false` puts the dialog beside the page and lets focus leave it. Escape closes it while focus is inside; outside presses close it only when `close-on-outside-press` is enabled.

To keep a small part of the page usable while a modal dialog is open, like a chat launcher, pass it to `persistent-elements`: an array of elements or selectors, or a function returning elements when the dialog opens. Persistent elements don't change stacking on their own.

Dialogs render where you put them and use the browser's top layer. Set `container` when their DOM needs to live elsewhere, like a shadow root. The [popup guide](../popups#mounting-and-containers) covers containers and iframes.

## Warn Before Closing a Dirty Form

## Nested Dialogs

A dialog opened inside another joins its stack. Escape closes the topmost dialog and returns focus to its trigger. Closing the parent also closes its children. `data-nested-open` and `--dialog-stack` let you show which layer is active.

## Opening from Anywhere

Connect several triggers to one `createDialogController<Payload, Result>()`. Each trigger passes a `payload`; a typed content alias, such as `DialogContent<Invoice>`, reads it from `state.payload` in its default slot. `controller.open({ payload })` opens it from code and returns a promise that resolves when it closes, with the reason and any `returnValue`. Each trigger remains the return-focus target for the dialog it opened. See [controllers](../controllers) for the shared controller pattern.

  name="dialog/payload"

## Presentation

`presentation="sheet"` presents the same task as a sheet. Use `"auto"` to choose a sheet on small touch screens and a centered dialog elsewhere, decided each time it opens. A swipe down closes a dismissible sheet; a protected one springs back and reports a dismissal attempt.

Style `data-presentation` to support both layouts. The sheet manages its own position and movement, so do not apply the centered dialog’s translation to it. `--sheet-backdrop` styles the dimmed page when no Backdrop part is present.

### Events

Events get the new state first, then the details. `v-model` only updates when `@open-change` wasn't canceled.

| Binding                 | On       | Receives                                                                       |
| ----------------------- | -------- | ------------------------------------------------------------------------------ |
| `v-model:open`          | `Dialog` | Whether the dialog is open                                                     |
| `@open-change`          | `Dialog` | `(open, details)`: the new state, the [reason](#reasons) and any `returnValue` |
| `@open-change-complete` | `Dialog` | `(open)`, after the animation                                                  |
| `@payload-change`       | `Dialog` | `(payload, details)`: the content's new payload, and the [reason](#reasons)    |
| `@dismiss-attempt`      | `Dialog` | `({ reason, event })`, when a dismissal was refused                            |

## Accessibility

The trigger is a button that opens a dialog, and the dialog follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): `aria-modal` while it's modal, labelled by its title, described by its description only while one is rendered. Every line below is an automated test.

### Keyboard

| Key                  | Does                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| Enter, Space         | On the trigger, opens the dialog                                     |
| Tab, Shift+Tab       | Moves through the dialog's controls, staying inside while it's modal |
| Escape               | Closes the topmost dialog and returns focus to its trigger           |
| A trigger's shortcut | Opens its dialog from anywhere on the page                           |
