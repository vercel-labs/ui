## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Pagination`:

```text
Pagination
└── PaginationList
    ├── PaginationItem
    │   └── PaginationPrevious
    ├── PaginationItem
    │   └── PaginationLink
    ├── PaginationItem
    │   └── PaginationEllipsis
    ├── PaginationItem
    │   └── PaginationLink
    └── PaginationItem
        └── PaginationNext
```

Name the navigation with `aria-label`, then put the page links and steps in a list.

`items` contains page numbers and the strings `"ellipsis-start"` and `"ellipsis-end"`. Render a link for each number and an ellipsis for each gap. Key entries by the item itself so a page link keeps its element as the range moves.

`PaginationLink` shows its page number unless you supply children. The current link gets `aria-current="page"` and `data-active`. `PaginationEllipsis` shows “…” and is hidden from screen readers.

Give Previous, Next, First, and Last text or an `aria-label`. At an end, a step gets `aria-disabled="true"` and `data-disabled` and stops changing the page. As a button, it stays in the tab order.

### Links

Pass `get-href`, a function from a page to its URL, and every part becomes a link.

Server-rendered anchors work before JavaScript loads. A normal click changes the page and follows the URL. Modifier clicks and middle clicks leave pagination state alone so the browser can open the link elsewhere.

A step at its end loses its `href` and leaves the tab order, but keeps focus if it already had it. During navigation, its original `href` stays in place so Next cannot accidentally follow the next page's URL.

### Router Links

Render your router's link to page on the client. The pagination's click handler runs first: when a change is canceled or a step is at its end, it calls `preventDefault()`, and the router leaves the link alone.

Here the page comes from the URL, like your router's search params, so the pagination is
[controlled](#controlled) by the route.

Render the router's link with the `render` slot. With Vue Router, use `RouterLink`'s `custom` form and bind the part's props to your own `<a>`, then its `navigate` after them. The pagination's click handler then runs first, and the link only marks the current page.

```vue
<PaginationLink :page="item">
  <template #render="{ props, children }">
    <RouterLink :to="props.href" custom v-slot="{ href, navigate }">
      <a v-bind="props" :href="href" @click="navigate"><component :is="children" /></a>
    </RouterLink>
  </template>
</PaginationLink>
```

## Behavior and Options

### Controlled

Bind `v-model:page` to control the pagination, and listen to `@page-change` for the reason.

Every change carries a [reason](#reasons): `item-press` for a page, `previous-press`, `next-press`, `first-press` or `last-press` for a step, and `imperative` from a [controller](#controller). Call `details.cancel()` to keep the page, like while a form has unsaved changes. A canceled change also stops a link from navigating.

### Default Page

`default-page` is the page it starts on, when uncontrolled. It's 1 by default.

### Siblings

`siblings` is how many pages show on each side of the current one, 1 by default. Near an end, the window slides over instead of shrinking, keeping the range length stable. A gap of one page shows that page instead of an ellipsis.

### Boundaries

`boundaries` is how many pages always show at each end, 1 by default.

### Total and Page Size

Instead of `page-count`, pass `total`, how many items there are, and `page-size`, how many fit on a page (10
by default). Pagination calculates the page count, with a minimum of one. This example resets to page 1 when the page size changes.

A page past the end, like after the count shrinks, reads as the last page.

## Focus

Steps rendered as buttons stay focusable at the ends. A clicked page link keeps focus as the range moves; the primitive also tries to restore focus to that page or step if rendering replaces its element. Key range entries by their value rather than their index.

## Styling

Parts are unstyled. Style them through the attributes they render, which are the same in every framework: `aria-current="page"` or `data-active` on the current page's link, and `aria-disabled` or `data-disabled` on a step at its end.

```vue
<PaginationLink :page="3" class="aria-[current=page]:border data-active:font-medium" />
<PaginationNext class="aria-disabled:opacity-50">Next</PaginationNext>
```

## Accessibility

There's no WAI-ARIA pattern for pagination. It follows the common practice: a `navigation` landmark named with `aria-label`, a list of links or buttons, and `aria-current="page"` on the current one.
