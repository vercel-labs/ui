## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Tooltip`:

```text
Tooltip
├── TooltipTrigger
└── TooltipContent
```

Wrap the trigger and its hint in a tooltip.

The content has the `tooltip` role. It names its trigger when the trigger has no name of its own, like an icon button, and describes it otherwise, as shown in [Icon Buttons](#icon-buttons). Keep it to plain text: a tooltip can't be focused, so links or buttons inside it can't be reached. For anything interactive, use a [Popover](./popover) or a [Hover Card](./hover-card).

## Examples

### Side

`side` picks where the tooltip opens: `top` by default. It flips to the other side when there isn't room, and shifts along the trigger to stay on screen.

<ComponentExample name="tooltip/side" caption="Hover each trigger to compare the four preferred sides." />

### Icon Buttons

A trigger without a name of its own, like a button with only an icon, gets its name from the tooltip, so screen readers hear "Bold, button". A trigger with text, an `aria-label` or a `title` is described by the tooltip instead: "Share, button, Anyone with the link can view". The tooltip's text is in the page from the start, hidden, so the name is there before focus reaches the trigger.

`type` overrides the guess. `type="label"` names a trigger whose text isn't a real name, like a symbol, and `type="description"` describes one that's named some other way.

### Keyboard Shortcut

`shortcut` on the tooltip, like `"mod+s"`, is a hint for what the trigger's action is bound to, where `mod` is Command on Apple platforms and Control elsewhere. `TooltipShortcut` shows the keys for the platform, `⌘S` or `Ctrl+S`, hidden from screen readers, and the trigger gets `aria-keyshortcuts` so they hear it instead. A `TooltipShortcut` can show other keys with its own `shortcut`.

The tooltip doesn't bind the keys. Register the shortcut yourself with [`registerShortcut`](../utilities/shortcuts), as the example does, or use the `shortcut` of a component that binds keys, like a [Dialog](./dialog#keyboard-shortcut) trigger.

### Disabled Buttons

A natively disabled button cannot receive focus, and some browsers send it no pointer events. Use a focusable disabled control when the tooltip explains why an action is unavailable.

Use `aria-disabled="true"` instead, and ignore the button's presses yourself. The button stays in the Tab order, screen readers announce it as dimmed, and the tooltip explains what's missing. `disabled` on the tooltip turns the explanation off once the button works.

Style the dimmed state with `aria-disabled:` variants.

### Touch

Touch screens have no hover. A tap on a plain tooltip's trigger only presses it, and the tooltip stays closed. Don't hide anything important in a tooltip.

For an info button whose only job is the tip, add `toggleable`: pressing the trigger opens and closes the tooltip, with a finger, a mouse or the keyboard, and its text is announced when a press opens it. An outside press or Escape closes it too.

<ComponentExample
  name="tooltip/toggleable"

### Keep Open on Press

Pressing the trigger closes the tooltip, so it doesn't cover what the press changed, and it stays closed until the pointer leaves. `:close-on-press="false"` keeps it open, like for a copy button whose tooltip turns into "Copied".

<ComponentExample name="tooltip/copy" caption="Press Copy to change the hint to Copied without closing it." />

### Delay and Grouping

`delay` is how long the pointer rests on the trigger before the tooltip opens, 600 milliseconds by default. `closeDelay` is how long it stays once the pointer leaves the trigger and the tooltip, 0 by default. Keyboard focus opens it at once.

Tooltips group without a provider. Once one is open, or was a moment ago, hovering the next opens it at once, and only one is open at a time, so moving along a toolbar reads like one tooltip that follows the pointer. A tooltip that opened at once gets `data-instant`, so it can skip its animation with `data-instant:transition-none`.

`disabled` stops a tooltip from opening, while its trigger keeps working.

### Truncated Text

To show a tooltip only when text is cut off, cancel the open in `@open-change` when the text fits. Compare `scrollWidth` with `clientWidth` in the callback. The name stays the same, so `type="label"` avoids repeating it to screen readers.

### Offsets

`sideOffset` is the gap to the trigger, 4 pixels by default. `alignOffset` shifts along it, `align` lines it up with the start, center or end of the trigger, and `collisionPadding` is the space kept from the edges of the window.

### Arrow

The arrow follows the side the tooltip actually lands on, including after it flips away from an edge, and gets the same `data-side`. It points at the middle of the trigger, even after the tooltip shifts, and keeps `arrowPadding` away from the corners. Check "Keep open" and change the side to watch it move.

<ComponentExample
  name="tooltip/arrow"
  caption="Keep the tooltip open and change its side to watch the arrow follow its placement."
/>

Without an Arrow part, the content's `::before` can be the arrow, positioned with `--arrow-offset`, the same way as a [Popover's](./popover#arrow).

### Anchor

Position the tooltip against something other than the trigger with `anchor`: an element, a CSS selector, a point like `{ x, y }`, or anything with `getBoundingClientRect()`. Here a small help button inside a field shows its tooltip along the whole field.

### Controlled

Bind `v-model:open` to control the tooltip.

Every change carries a [reason](#reasons), like `trigger-hover`, `trigger-focus`, `trigger-press`, `escape-key` or `outside-press`. Call `details.cancel()` to stop it. A [controller](#controller), from `createTooltipController()`, opens the tooltip from anywhere, like a step in a guided tour.

### One Tooltip for Many Triggers

A grid of days, a chart or a long list can share one tooltip instead of rendering one per item. Put the triggers anywhere on the page and connect them to the tooltip with its controller. Each trigger passes a `payload`, like its day, and the content reads it from its state. Only the trigger that opened the tooltip is described by it. The content renders before the first open, so handle an `undefined` payload before reading its fields.

A template can't pass a type argument, so `TooltipContent<Day>` in the script makes a content part that types the payload in its state.

The controller's `open()` takes a payload too, and an `anchor`. On an open tooltip, `open({ payload })` replaces the payload, like another trigger taking it over, and `@payload-change` fires with the reason `imperative`.

<ComponentExample
  name="tooltip/payload"
  caption="Move between days. One tooltip updates to describe the active day."

### Container

Tooltips render in place and show in the top layer, so no ancestor clips or covers them. `container` renders the tooltip somewhere else, for iframes, shadow roots or a specific stacking context.

### Animation

`@open-change-complete` runs once the tooltip has finished opening or closing, after any
animation, with the new open state. Skip the animation for tooltips that open at once, as the next one in a
group does, with `data-instant`. See [Styling](#styling) for the attributes to animate.

On the tooltip, it's the `@open-change-complete` event.

## Styling

Parts are unstyled. Style them through the attributes they render, which are the same in every framework. The trigger gets no state attributes of its own, since it's often another component's trigger too, like a menu's, and those are that component's.

<DataAttributes component="tooltip" />

The content also gets `data-instant` when it opened without its delay, because another tooltip was open a moment ago.

Open tooltips also set CSS variables for sizing and animation, listed under [TooltipContent](#tooltipcontent).

Animate with `data-starting-style` and `data-ending-style`. The tooltip stays mounted until its exit animation finishes.

```css
[data-slot="tooltip-content"] {
  transition:
    opacity 150ms,
    scale 150ms;
  transform-origin: var(--transform-origin);
}

[data-slot="tooltip-content"]:is([data-starting-style], [data-ending-style]) {
  opacity: 0;
  scale: 0.96;
}

[data-slot="tooltip-content"][data-instant] {
  transition: none;
}
```

### Events

Events get the new state first, then the details. `v-model` only updates when `@open-change` wasn't canceled.

| Binding                 | On        | Receives                                                                    |
| ----------------------- | --------- | --------------------------------------------------------------------------- |
| `v-model:open`          | `Tooltip` | Whether the tooltip is open                                                 |
| `@open-change`          | `Tooltip` | `(open, details)`: the new state, and the [reason](#reasons)                |
| `@open-change-complete` | `Tooltip` | `(open)`, after the animation                                               |
| `@payload-change`       | `Tooltip` | `(payload, details)`: the content's new payload, and the [reason](#reasons) |

## Accessibility

The trigger is named or described by the tooltip, following the [WAI-ARIA tooltip pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tooltip/). It opens on hover and on keyboard focus, stays open while the pointer moves onto it, and Escape closes only the tooltip, not a dialog or menu around it. Every line below is an automated test.
