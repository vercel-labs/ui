Use a resizable group to let people size the panes of a layout, like a file list beside an editor, by dragging the handle between them or with the keyboard.

<ComponentExample
  name="resizable/basic"
  caption="Drag the handle beside Files, then the one between page.tsx and Terminal."
/>

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Resizable`:

```text
Resizable
├── ResizablePanel
├── ResizableHandle
└── ResizablePanel
```

Put a handle between the panels you want to resize, and name it with `aria-label`, like "Resize files". The group lays its panels out in a row, so give it a size, and each panel's size is a percentage of the space the panels share. A group can sit inside a panel, like an editor above a terminal.

## Usage

Import the parts and put them together:

```vue
<script setup lang="ts">
import { Resizable, ResizableHandle, ResizablePanel } from "@ui-sdk/vue/resizable"
</script>

<template>
  <Resizable>
    <ResizablePanel :default-size="30">Files</ResizablePanel>
    <ResizableHandle aria-label="Resize files" />
    <ResizablePanel>Editor</ResizablePanel>
  </Resizable>
</template>
```

The panel without `default-size` takes what's left, here 70%.

## Build Your Own

`@ui-sdk/vue/resizable` comes with a ready-made Resizable. If you'd like to build your own, with your own names, start from the `resizable` primitive in `@ui-sdk/core`:

```ts title="split-view.ts"
import { resizable } from "@ui-sdk/core/resizable"
import { createParts } from "@ui-sdk/vue/primitive"

const {
  Root: SplitView,
  Panel: SplitViewPane,
  Handle: SplitViewDivider,
} = createParts(resizable, { root: "div", panel: "div", handle: "div" })

export { SplitView, SplitViewDivider, SplitViewPane }
```

```vue
<template>
  <SplitView>
    <SplitViewPane :default-size="30">Files</SplitViewPane>
    <SplitViewDivider aria-label="Resize files" />
    <SplitViewPane>Editor</SplitViewPane>
  </SplitView>
</template>
```

Each part keeps the behavior, state and data attributes of its ready-made counterpart: the root lays the panels out, each pane writes its size to `--resizable-panel-size`, and the divider is the focusable separator. See [Rendering](../rendering) and [Custom Parts](../custom-parts) for more.

## Handle

Put anything inside a handle, like a grip that shows it can be dragged. The handle can stay a thin line: its hit area is at least 10 pixels across, centered on it, and 24 for touch, without any styles.

## Collapsible

`collapsible` lets a panel collapse below its `min-size` to `collapsed-size`, 0 by default: by dragging past the midpoint to its collapsed size, with Enter or a double-click on its handle, or through the controller. Dragging back past the same point opens it at its minimum, and Enter restores the size it had. A collapsed panel gets `data-collapsed`, and at size 0 its content leaves the tab order and the accessibility tree.

<ComponentExample

## Sizes in Pixels

Sizes are percentages as numbers, or strings with `%`, `px` or `rem`. Pixel and rem bounds hold as the group resizes, so a navigation with `min-size="160px"` never gets narrower, and a change they cause reports the `resize` reason.

## Default Layout

`default-layout` sets every panel's size at once, in order. Otherwise panels without `default-size` share what's left evenly.

## Controlled

Bind `v-model:layout` to control the group, and listen to `@layout-change` for the reason. The layout is one percentage per panel, in order, adding up to 100. Every change carries a [reason](#reasons), like `drag`, `step-key` or `collapse`, and `details.cancel()` keeps the current layout.

<ComponentExample
  name="resizable/controlled"
  caption="Resize Files to log the layout and its reason. Split Evenly and Reset set the layout from outside."
/>

## Saving on Complete

`@layout-change` runs on every frame of a drag. `@layout-commit` runs once, when the interaction that changed the layout ends: the pointer lifts, the key comes up, or a panel collapses. Save there.

<ComponentExample
  name="resizable/complete"

## Persistence

`auto-save-id` saves the layout in `localStorage` when an interaction completes and restores it when the group attaches in the browser. Server markup starts with the default sizes. Each set of panels keeps its own layout, so a panel that comes and goes gets its sizes back. Give panels an `id` so the saved layout survives changes elsewhere on the page.

It's the same idea as [Preferences](./preferences), which saves one choice between visits, like a theme. Resizable saves the whole layout, under its `auto-save-id`.

  name="resizable/persistence"

## Storage

`storage` takes anything with `getItem` and `setItem`, like `sessionStorage` or a cookie. That's the browser's storage shape, not the [storage](./preferences#save-the-value) helpers Preferences takes, such as `createLocalStorage`, which each keep one value. Choose between local storage, session storage and a cookie as you would for a preference, under [Remember the Choice](../../core/behaviors/preferences#remember-the-choice).

This example keeps the layout in `sessionStorage`, for the tab's session:

<ComponentExample
  name="resizable/storage"
  caption="Resize Messages, then reload. The width comes back in this tab, but not in a new one."
/>

A server can't read `localStorage`, so it renders each panel's `default-size` and the saved layout arrives when the page hydrates. To render the saved layout on the first paint, keep it in a cookie and pass the sizes back as each panel's `default-size`. Here a Nuxt page reads the cookie with `useCookie`, which also parses its JSON. It imports `resizableStorageKey`, which names the cookie:

```vue title="pages/index.vue"
<script setup lang="ts">
import { resizableStorageKey } from "@ui-sdk/vue/resizable"

const saved = useCookie<Record<string, number[]>>(resizableStorageKey("editor"), { default: () => ({}) })
const [sidebar = 25, main = 75] = saved.value["sidebar,main"] ?? []
</script>

<template>
  <Editor :sidebar="sidebar" :main="main" />
</template>
```

```vue title="components/Editor.vue"
<script setup lang="ts">
import { Resizable, ResizableHandle, ResizablePanel, type ResizableStorage } from "@ui-sdk/vue/resizable"

defineProps<{ sidebar: number; main: number }>()

const cookieStorage: ResizableStorage = {
  getItem: (key) => {
    const value = document.cookie.match(new RegExp(`(?:^|; )${key}=([^;]*)`))?.[1]
    return value === undefined ? null : decodeURIComponent(value)
  },
  setItem: (key, value) => {
    document.cookie = `${key}=${encodeURIComponent(value)}; path=/; max-age=31536000`
  },
}
</script>

<template>
  <Resizable auto-save-id="editor" :storage="cookieStorage">
    <ResizablePanel id="sidebar" :default-size="sidebar" />
    <ResizableHandle aria-label="Resize sidebar" />
    <ResizablePanel id="main" :default-size="main" />
  </Resizable>
</template>
```

## Step Size

`step` sets how far an arrow key moves a handle, 1% by default, and `large-step` how far Shift with an arrow moves it, 10% by default.

## Disabled

`disabled` on a handle fixes it in place. On the group it fixes every handle. Disabled handles leave the tab order, and their panels keep their sizes. A disabled `<fieldset>` around the group fixes every handle too.

The `#render` slot and the default slot receive the part's state, like a panel's `size` and whether it's `collapsed`, or whether a handle is `dragging` or `hovering`. See [Parts and Composition](../parts-and-composition) for the rendering contract.

## Styling

Parts are unstyled, apart from the layout they need: the group is a flex row or column, panels take their size as a flex basis, and handles don't shrink and take `touch-action: none`. Give the group a size, the handle a width or height and a background, and style it with `data-hovering`, `data-dragging` and `:focus-visible`. While a handle is hovered or dragged, its cursor shows over the whole page, and points the only way it can go at a limit.

Each part has a `data-slot`, such as `resizable-handle`, and its state attributes are listed under [Data Attributes](#data-attributes).

| `@layout-commit` | `Resizable` | `(layout, details)`: the layout once the interaction ends      |

## Accessibility

Handles follow the [WAI-ARIA window splitter pattern](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/). Each is a focusable `separator` whose `aria-valuenow` is the size of the panel before it, with `aria-valuemin` and `aria-valuemax` as far as the panels allow, `aria-controls` pointing at that panel, and `aria-orientation` running across the group. Name each handle with `aria-label`.

### Keyboard

Focus a handle and press the arrow keys along the group's axis to move it by `step`, or with Shift by `large-step`. Home and End move it as far as the panels allow, and Enter collapses or restores a collapsible panel beside it. A panel at its minimum passes the rest of a move on to the next one. Disabled handles leave the tab order.
