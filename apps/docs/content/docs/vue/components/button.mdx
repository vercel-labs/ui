---
title: Button
description: Run an action, show that it's working, and keep it reachable when disabled.

Button renders a native `button` and adds what it doesn't do on its own: it stays pending while an async action runs, so a form can't submit twice, announces slow actions to screen readers, can stay focusable while disabled, and keeps the same behavior when it renders a link. For a plain click handler, a native `button` is enough.

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Usage

Use `@click` to run an action. Button renders a native `<button>` with `type="button"` by default.

```vue
<script setup lang="ts">
import { Button } from "@ui-sdk/vue/button"
</script>

<template>
  <Button @click="save()">Save</Button>
</template>
```

## Pending

Return a Promise from `@click` to keep the button pending until it settles. `@click` binds to a prop, so Button receives the handler's return value. The button keeps focus and ignores further presses while it waits.

```vue
<script setup lang="ts">
import { Button } from "@ui-sdk/vue/button"

const save = () => new Promise((resolve) => setTimeout(resolve, 1500))
</script>

<template>
  <Button @click="save" pending-announcement="Saving">Save</Button>
</template>
```

After one second, it announces "Loading" to screen readers. Set `pending-announcement` to change that message, as above, or use an empty string to silence it.

## Pending Content

To change what the button shows while it waits, mark content with `data-show="idle"` or `data-show="pending"` and hide it in the other state with one CSS rule each, or use Tailwind's `in-data-pending` variant:

<StyleTabs>

```css
[data-slot="button-root"]:not([data-pending]) [data-show="pending"],
[data-slot="button-root"][data-pending] [data-show="idle"] {
  display: none;
}
```

```vue
<Button @click="save">
  <ArrowDownToLineIcon class="in-data-pending:hidden" />
  <LoaderCircleIcon class="not-in-data-pending:hidden" />
  Save
</Button>
```

</StyleTabs>

<ComponentExample
  name="button/pending-content"
  caption="Press Save. Its arrow turns into a spinner while it saves."
/>

Keep the label and change only the visual, as above. If the text has to change too, swap it the same way, without an `aria-label`. [Pending Buttons](#pending-buttons) explains why:

```vue
<Button @click="save">
  <span data-show="idle">Save</span>
  <span data-show="pending">Saving…</span>
</Button>
```

## Handling Errors

If the handler throws or its Promise rejects, `state.error` holds the error. Use it to show a message or a retry label. The next press clears the error and runs the handler again.

The demo uses a [`#render` slot](/docs/vue/parts-and-composition#read-the-state) to show the error beside the button. The default slot receives the state too.

## Changes After an Await

`@click` receives the event and `{ source }`, which says how the button was pressed. If the handler changes another ui-sdk component after an `await`, wrap that change in `withSource` to keep the original source. Otherwise, the later change is reported as `"programmatic"`.

Here `save()` is your request and `status` is an Input's [controller](/docs/vue/controllers):

```vue
<script setup lang="ts">
import { Button, type ButtonActionDetails } from "@ui-sdk/vue/button"
import { withSource } from "@ui-sdk/vue/observe"

async function onSave(event: MouseEvent, { source }: ButtonActionDetails) {
  await save()
  withSource(source, () => status.setValue("Saved"))
}
</script>

<template>
  <Button @click="onSave">Save</Button>
</template>
```

[Observe](/docs/core/observe#keep-the-source-after-an-await) explains source tracking. Preserving `"agent"` lets [`undoSource("agent")`](/docs/agents/connect-an-agent/history-and-undo#undo-the-agents-changes) include that later change.

## Disabled

Set `disabled` to prevent presses and remove the button from the tab order. A disabled `<fieldset>` around the button disables it too.

```vue
<Button disabled>Disabled</Button>
```

## Focusable When Disabled

Add `focusable-when-disabled` when people should still be able to focus a disabled button. It uses `aria-disabled` instead of the native `disabled` attribute. Presses still do nothing.

Use `aria-describedby` to explain why the action is unavailable:

```vue
<Button
  disabled
  focusable-when-disabled
  aria-describedby="publish-hint"
>Publish</Button>
<p id="publish-hint">Add a title to publish.</p>
```

<ComponentExample
  name="button/focusable-when-disabled"
  caption="Focus Title, then press Tab to reach Publish while it is disabled. Enter a title to enable it, then choose Publish. The console logs what was published."
/>

## Links

Use the `#render` slot to render an `<a>`, and bind the supplied `props` to it. It keeps its `href` and link semantics, including opening in a new tab. A disabled link cannot navigate and leaves the tab order.

```vue
<Button>
  <template #render="{ props }">
    <a v-bind="props" href="/docs/vue">Get started</a>
  </template>
</Button>
```

<ComponentExample
  name="button/link"
  caption="Choose Get Started to jump to Installation on this page. Changelog is disabled and does not navigate."
/>

For your own components, see [Parts and Composition](/docs/vue/parts-and-composition).

## Forms

Set `type="submit"` to submit a form or `type="reset"` to restore its default values. The default, `type="button"`, does neither.

```vue
<Button type="submit">Subscribe</Button>
<Button type="reset">Reset</Button>
```

<ComponentExample
  name="button/form"
  caption="Edit the email and choose Subscribe, or press Enter in the field. The console logs each submission, and Reset restores the original email."
/>

Button tracks the Promise returned by its own `@click`, not one from the form’s submit handler. For an async submit handler, keep your own pending flag and set `disabled` on the button while it runs, with [`focusable-when-disabled`](#focusable-when-disabled) so the button keeps focus while it waits.

## Styling

Use `data-pending` to show a spinner or waiting cursor, and `data-disabled` to style an unavailable action. The button's `data-slot` is `button-root`, and its attributes are listed under [Data Attributes](#data-attributes).

## Accessibility

Give the button a clear text label. If it contains only an icon, add an `aria-label`. Native buttons respond to Enter and Space; links respond to Enter.

### Pending Buttons

While its action runs, the button tells assistive technology it's busy, so you don't need to add anything:

- It sets `aria-busy="true"` and `aria-disabled="true"`, and ignores presses until the action settles. It keeps focus the whole time.
- After a second, it announces `pending-announcement` ("Loading" by default) through a polite live region. Quick actions stay silent. This is a status message: people hear it without focus moving.

To show progress, keep the label and change only the visual, like a spinner. Changing the text renames the button while it has focus: screen readers don't reliably announce a new name on the focused element, so the change mostly helps sighted users, and the button's width shifts as the text changes length. The announcement already tells everyone it's working.

```vue title="Do"
<Button @click="save" pending-announcement="Saving">
  <ArrowDownToLineIcon data-show="idle" aria-hidden="true" />
  <LoaderCircleIcon data-show="pending" aria-hidden="true" />
  Save
</Button>
```

```vue title="Don't"
<Button @click="save" aria-label="Save">
  {{ saving ? "Saving…" : "Save" }}
  <span aria-live="polite">{{ saving ? "Saving" : "" }}</span>
</Button>
```

The second button tracks `saving` itself, shows text its accessible name doesn't contain, and announces the same state twice. If the text has to change anyway, swap it with `data-show` and leave out `aria-label`, so the button's name always contains the text on screen. See [Pending Content](#pending-content) for the markup.
