Start with a trigger and a few actions. Add groups, checkboxes, radio choices, or submenus as the task grows. The menu handles focus, arrow keys, typeahead, and dismissal.

/>

## Installation

```bash
npm install @ui-sdk/vue @ui-sdk/core
```

## Composition

Use the following composition to build a `Menu`:

```text
Menu
├── MenuTrigger
└── MenuContent
    ├── MenuItem
    └── MenuItem
```

Give items a `value` and handle `@action` on the menu to run the selected command. A Group and GroupLabel can organize related actions; a Separator divides them without becoming a focus stop.

Return a promise from `@action` or an item’s `@select` to keep the item pending. It gets `data-pending`, `aria-busy` and `aria-disabled`, the menu stays open, and choosing it again does nothing until the promise settles. The menu closes once it resolves. A rejection keeps it open and puts the reason in the item’s `error` state until the next try. After a second, screen readers hear `pending-announcement`, “Loading” by default.

## Usage

Import the parts and put them together:

```vue
<script setup lang="ts">
import { Menu, MenuContent, MenuItem, MenuTrigger } from "@ui-sdk/vue/menu"
</script>

<template>
  <Menu>
    <MenuTrigger>Actions</MenuTrigger>
    <MenuContent>
      <MenuItem value="rename">Rename</MenuItem>
      <MenuItem value="duplicate">Duplicate</MenuItem>
    </MenuContent>
  </Menu>
</template>
```

## Submenus

Nest a Sub, SubTrigger, and SubContent to add another level. Hover or press the arrow key toward a submenu to open it. The menu lets a pointer travel diagonally into the submenu without accidentally choosing an item it passes over. Escape closes only the submenu and returns focus to its trigger, as the menu pattern asks.

## Shortcuts

An item’s `shortcut` displays a platform-specific hint and sets `aria-keyshortcuts`. `mod+s` reads as Command+S on Apple platforms and Control+S elsewhere.

In markup, this is a hint: your app owns the key handler. [Data menus](#menus-as-data) also register their shortcuts while closed. Letters and digits match physical keys, including combinations such as Option+N.

## Icons

Put decorative icons in ItemIcon so screen readers and typeahead ignore them. `mirror` flips a directional icon in right-to-left text. An icon-only item still needs an `aria-label`.

`data-has-icon` on items and `data-has-icons` on the menu let text line up when only some items have icons.

## Checkboxes

Checkbox items toggle independently and stay open by default. Use `v-model:checked`, or `default-checked` for an uncontrolled item. An ItemIndicator renders the check; `keep-mounted` preserves its space while unchecked. Style `data-checked` and `data-unchecked` for each state.

## Radio Group

Radio items choose one value in their group and stay open by default. Use `v-model:value`, or `default-value` for an uncontrolled group. Give the group a `name` when it should identify itself in the menu’s value-change callback.

## Context Menu

A ContextTrigger opens at a right-click or long press. Give the area a tab stop so Shift+F10 and the context-menu key can open it from the keyboard. Right-clicking elsewhere in the same area repositions an open menu.

Set `disabled` to leave that area’s native browser menu available. Context triggers can pass a payload too.

## Placement

`side` and `align` choose the starting position. The menu flips or shifts when it does not fit; `data-side` reports where it ended up. Logical alignment and submenu keys follow the surrounding text direction. See the shared [popup guide](../popups) for the positioning contract.

```vue
<MenuContent side="right" align="start" />
```

## Offsets and Collision Padding

`side-offset` sets the gap, `align-offset` shifts along the anchor, and `collision-padding` leaves room around the viewport. Use `--anchor-width` to match the trigger's width and `--available-height` to scroll a long list.

```vue
<MenuContent :side-offset="8" :align-offset="-4" :collision-padding="24" />
```

## Modal

The default `modal="pointer"` consumes an outside press while closing the menu. `true` also locks scrolling and makes the page inert. `false` lets the outside press reach its target after closing.

```vue
<Menu :modal="false">
  <MenuTrigger>Actions</MenuTrigger>
  <MenuContent />
</Menu>
```

## Submenu Delay

`delay` is the hover wait in milliseconds, 100 by default. It applies to the submenus directly inside that menu. Set it on a Sub to change the delay for the next level.

```vue
<Menu :delay="300">
  <MenuTrigger>File</MenuTrigger>
  <MenuContent>
    <MenuSub :delay="0">
      <MenuSubTrigger>Open recent</MenuSubTrigger>
      <MenuSubContent />
    </MenuSub>
  </MenuContent>
</Menu>
```

## Keyboard Navigation

Arrow keys wrap by default; `loop` false stops at the ends. Typing finds an item by name. If an item has extra descriptive text, set `label` to the text typeahead should match. `label` does not replace its accessible name; use `aria-label` for that.

```vue
<Menu :loop="false">
  <MenuTrigger>Status</MenuTrigger>
  <MenuContent>
    <MenuItem value="busy" label="Do not disturb">
      Do not disturb
      <span>Notifications are muted</span>
    </MenuItem>
  </MenuContent>
</Menu>
```

## Disabled Items

Disabled items remain focusable so people can discover them, but cannot run or open a submenu. A disabled Trigger is a native disabled button and cannot receive focus.

## Keeping the Menu Open

Plain items close when selected; checkbox and radio items stay open. `close-on-select` changes either default. A selection handler can also prevent the default event to keep it open for one action.

```vue
<MenuItem :close-on-select="false" @select="zoom += 10">Zoom in</MenuItem>
<MenuCheckboxItem value="fit" close-on-select>Fit to window</MenuCheckboxItem>
```

## Container

Menus render in place and use the top layer. `container` moves the popup to another element; submenus remain inside their parent popup. Pass the actual element after it exists, as the [popup guide](../popups) explains.

```vue
<MenuContent :container="panel" />
```

## Animation

The menu stays mounted through an exit animation. `data-starting-style`, `data-ending-style`, `data-side`, and `--transform-origin` describe the transition. `keep-mounted` leaves the closed content hidden afterward; `@open-change-complete` reports when it finishes.

<ComponentExample

/>

## Presentation

`presentation="auto"` uses a sheet on small touch screens and a popover elsewhere; `"sheet"` always requests a sheet. The sheet keeps menu roles and keys. Submenus replace the current level, and Escape or the arrow toward the parent goes back. Context menus and menus in a menubar remain popovers.

Use `data-presentation` or the content’s `presentation` state for the two layouts. Leave a sheet’s translation to the SDK. `--sheet-backdrop` sets its dimming color, and the sheet is modal unless `modal` is false. The [popup guide](../popups) covers shared presentation behavior.

<ComponentExample
  name="menu/presentation"
  caption="Open Options as a sheet, enter Move to, then go back or choose a destination. You can drag downward to dismiss the sheet."
/>

## Controlled

Use `v-model:open`, or pass `open` and listen for `@open-change`. A change carries a reason, and `details.cancel()` can refuse it. A controller can open the menu from another control; see [state and events](../state-and-events) and [controllers](../controllers) for that shared pattern.

```vue
<script setup lang="ts">
const open = ref(false)
</script>

<template>
  <Menu v-model:open="open">
    <MenuTrigger>Actions</MenuTrigger>
    <MenuContent />
  </Menu>
</template>
```

## Triggers Outside the Menu

Connect external triggers and one menu to a `createMenuController<File>()`. Each trigger passes its row as `payload`, which the content reads from its state. Only the active trigger is expanded and receives focus back. Code can also open with a `payload` and `anchor`; the Promise resolves when the menu closes.

## Menus as Data

`items` accepts `MenuData`: actions, groups, checkboxes, radio groups, and submenus. A string is shorthand for an item whose label and value match. Data menus register their shortcuts even while closed; set `item-shortcuts` to false to turn that off.

`@checked-change` reports the checkbox’s value in `details.value`; `@value-change` reports the radio group’s name in `details.group`. Either change can be canceled. You can also render your own parts from the same data while `items` keeps the shortcuts registered. The [lists and menus guide](../lists-and-menus) covers the data shape.

```vue
<script setup lang="ts">
const fileMenu: MenuData = [
  { value: "open", label: "Open…", shortcut: "mod+o" },
  { type: "separator" },
  {
    type: "checkbox",
    value: "toolbar",
    label: "Toolbar",
    defaultChecked: true,
  },
  {
    type: "radio-group",
    name: "sort",
    label: "Sort by",
    defaultValue: "name",
    items: [
      { value: "name", label: "Name" },
      { value: "date", label: "Date modified" },
    ],
  },
  { type: "submenu", label: "Share", items: ["Copy link", "Email"] },
]
</script>

<template>
  <Menu :items="fileMenu" @action="(value) => run(value)">
    <MenuTrigger>File</MenuTrigger>
    <MenuContent />
  </Menu>
</template>
```

### Controller

Create one with `createMenuController<Payload>()` and pass it as `controller`, to the menu and to any
triggers outside it. `Payload` is the type of the data triggers and `open()` pass.

Every write method takes an optional `{ reason, event }`, passed to `@open-change`. `open()` also takes `focus`: `"first"`, `"last"`, `"popup"` or `"none"`.

### Events

Events get the new state first, then the details. `v-model` only updates when the change event wasn't canceled.

| Binding                 | On                 | Receives                                                                                                 |
| ----------------------- | ------------------ | -------------------------------------------------------------------------------------------------------- |
| `v-model:open`          | `Menu`             | Whether the menu is open                                                                                 |
| `@open-change`          | `Menu`             | `(open, details)`: the new state, and the [reason](#reasons)                                             |
| `@open-change-complete` | `Menu`             | `(open)`, after the animation                                                                            |
| `@payload-change`       | `Menu`             | `(payload, details)`: the content's new payload, and the [reason](#reasons)                              |
| `@action`               | `Menu`             | `(value, { event })` for every plain item, a function prop. A Promise marks it pending                   |
| `@checked-change`       | `Menu`             | `(checked, details)`, with the item's value in `details.value`. For data menus                           |
| `@value-change`         | `Menu`             | `(value, details)`, with the group's name in `details.group`. For data menus                             |
| `@dismiss-attempt`      | `Menu`             | `({ reason, event })`, when a dismissal was refused                                                      |
| `v-model:open`          | `MenuSub`          | Whether the submenu is open                                                                              |
| `@select`               | `MenuItem`         | `(event)`, a function prop. `event.preventDefault()` keeps the menu open, and a Promise marks it pending |
| `v-model:checked`       | `MenuCheckboxItem` | Whether the item is checked. `@checked-change` has the details                                           |
| `v-model:value`         | `MenuRadioGroup`   | The selected value. `@value-change` has the details                                                      |
