Parts render without styles. The component demos use Tailwind CSS, but the same state attributes and CSS variables work with any stylesheet.

## Style a Part

Style the element that receives the behavior. For a toggle, that is the button inside its wrapper. Import `@ui-sdk/web/toggle` on this page:

```html
<ui-toggle>
  <button
    class="cursor-default rounded-2xl border border-input px-2.5 py-1.5 text-sm data-pressed:bg-muted data-disabled:opacity-50"
  >
    Bold
  </button>
</ui-toggle>
```

State attributes such as `data-pressed` and `data-disabled` are present or absent. Others have values, such as `data-side="top"`. Each component's Styling section lists its attributes and CSS variables.

## CSS Modules

CSS Modules need a bundler that imports a class-name map. With plain CSS, use an ordinary class name and load the stylesheet instead. Import the module and pass its class to the button:

```html
<ui-toggle id="bold"><button>Bold</button></ui-toggle>
```

```ts
import "@ui-sdk/web/toggle"
import styles from "./toggle.module.css"

const button = document.querySelector("#bold button")!
button.classList.add(styles.toggle)
```

```css title="toggle.module.css"
.toggle {
  cursor: default;
  border: 1px solid var(--input, #e5e5e5);
  border-radius: 1.125rem;
  background: transparent;
  padding: 0.375rem 0.625rem;
  color: inherit;
  font: inherit;
  font-size: 0.875rem;
}

.toggle[data-pressed] {
  background: var(--muted, #f5f5f5);
}

.toggle[data-disabled] {
  opacity: 0.5;
}

.toggle:focus-visible {
  outline: 2px solid var(--ring, #a3a3a3);
  outline-offset: 2px;
}
```

Import the stylesheet once from your app's entry file. Add `class="dark"` to `<html>` to use the dark values.

For a stylesheet without Tailwind, use the `:root`, `.dark`, and `body` rules directly and omit the Tailwind directives.

Inside your own shadow root, the elements add their default rules, such as keeping closed parts hidden, to the root's `adoptedStyleSheets`. If your code replaces or changes that list, the rules come back at the component's next state change, so a closed part can show until then.

## Animate Opening and Closing

Import `@ui-sdk/web/popover`, then style `data-starting-style` for entry and `data-ending-style` for exit:

```html
<ui-popover id="details">
  <ui-popover-trigger><button>Details</button></ui-popover-trigger>
  <ui-popover-content
    class="origin-(--transform-origin) transition-[opacity,scale] duration-150 data-starting-style:scale-96 data-starting-style:opacity-0 data-ending-style:scale-96 data-ending-style:opacity-0 motion-reduce:transition-none"
  >
    <ui-popover-title>Project Details</ui-popover-title>
    <p>Last updated today.</p>
    <ui-popover-close><button>Done</button></ui-popover-close>
  </ui-popover-content>
</ui-popover>
```

The popup stays shown until its exit transition or animation finishes, then becomes hidden. Put exit styles on `data-ending-style`; `data-closed` describes state but doesn't wait for an exit.

Popups provide `--anchor-width` and `--available-height` for sizing. Use those and `data-slot` rather than generated IDs. [Popups](./popups) covers placement and containers.

## Content Security Policy

A few behaviors need a little CSS, like keeping a closed popup hidden or dimming the page behind a sheet, so ui-sdk adds it to the page. It goes before your own styles, in a cascade layer named `ui-sdk`, so your styles win.

A Content Security Policy without `'unsafe-inline'` blocks styles added this way. Give ui-sdk your policy's nonce with a meta tag in the page's `<head>`. Vite reads the same tag for the styles it adds:

```html
<meta property="csp-nonce" nonce="your-nonce" />
```

If your policy has no nonce for styles, add the tag without the `nonce` attribute. ui-sdk then adds its CSS as constructed style sheets, which the browser places after yours, so declare its layer at the top of your stylesheet to keep your styles winning:

```css
@layer ui-sdk;
```
