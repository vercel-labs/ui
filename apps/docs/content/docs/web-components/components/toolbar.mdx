## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the toolbar before the components it contains, so its context is ready when their elements connect:

```ts
import "@ui-sdk/web/toolbar"
import "@ui-sdk/web/toggle"
import "@ui-sdk/web/menu"
```

## Usage

Put controls inside a named `ui-toolbar`. The toolbar provides one tab stop and moves focus between its controls with the arrow keys.

<span id="composition" />

```html
<ui-toolbar aria-label="History">
  <ui-toolbar-button><button>Undo</button></ui-toolbar-button>
  <ui-toolbar-button><button>Redo</button></ui-toolbar-button>
</ui-toolbar>
```

Use `ui-toolbar-button` for buttons, `ui-toolbar-link` for links and `ui-toolbar-input` for fields. Toggles and toggle groups join automatically. Give every icon-only control an accessible name.

### With a Menu

Wrap the menu trigger in `ui-toolbar-button`. Put this inside a [Menu](./menu) within the toolbar:

```html
<ui-toolbar-button>
  <ui-menu-trigger><button>Share</button></ui-menu-trigger>
</ui-toolbar-button>
```

### With Fields

Wrap a field in `ui-toolbar-input`. The field keeps Home and End, and Left and Right while they can move the caret. At the matching boundary, with no text selected, an arrow moves to the next toolbar item.

Entering a field with an arrow puts its caret at the far end in that direction: press the same arrow again to leave, or the other arrow to edit. A [Number Input](./number-input) keeps Up and Down for stepping its value.

## Behavior and Options

### Keyboard

Tab enters on the first enabled item, then returns to the item focused last on later visits. The next Tab leaves the toolbar.

| Key                        | Action                                          |
| -------------------------- | ----------------------------------------------- |
| `ArrowRight` / `ArrowLeft` | Move focus in a horizontal toolbar              |
| `ArrowDown` / `ArrowUp`    | Move focus in a vertical toolbar                |
| `Home` / `End`             | Focus the first or last item, except in a field |
| `Enter` / `Space`          | Activate a button or toggle, or open its popup  |

Controls keep the keys they use: Down can open a menu, and Up and Down can step a number input. Toolbar navigation does not press toggles.

### Vertical

Set `orientation="vertical"` to move with Up and Down. Separators expose the perpendicular orientation for styling.

<ComponentExample
  name="toolbar/vertical"
  caption="Use Up and Down to move between tools and Delete. Space changes the focused tool."
/>

### Disabled

Disabled items stay reachable with `aria-disabled` by default. They ignore activation, including keys that would activate a component rendered through them. Toolbar navigation still works.

Set `focusable-when-disabled="false"` to skip an item instead. A disabled field cannot be edited. Disabling the whole toolbar preserves a tab stop so users can still find it.

<ComponentExample
  name="toolbar/disabled"
  caption="Arrow from Reply to the disabled Archive button. Delete is skipped. The Comment toolbar stays focusable but cannot be edited or submitted."
/>

### Loop

Arrow keys wrap by default. Set `loop="false"` to stop at the ends.

<ComponentExample
  name="toolbar/loop"
  caption="Focus Last and press Right. Focus stays there; Home still moves to First."
/>

### Controller

The toolbar element's `api.focus()` moves focus to its last focused item. Call it from a button or a keyboard shortcut.

## Custom Rendering

Wrap the component's trigger or input in the corresponding toolbar part. The wrapper finds the native control inside it and adds the toolbar behavior to the same element. See [Parts and Composition](../parts-and-composition) for the rendering contract.
