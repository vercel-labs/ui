A hover card shows a preview of where a link goes, like a person's profile, to someone who pauses on it. The link still works as a link.

<ComponentExample
  name="hover-card/basic"
  caption="Hover @hollis, or Tab to it and wait, to open Hollis Grant's profile preview. Move the pointer away or press Escape to close it."
/>

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the component to register its elements. The import is safe on the server.

```ts
import "@ui-sdk/web/hover-card"
```

## Composition

Use the following composition to build a `ui-hover-card`:

```text
ui-hover-card
├── ui-hover-card-trigger
│   └── a
└── ui-hover-card-content
    └── ui-hover-card-arrow
```

The trigger wraps your own link (an `<a>`, so give it an `href`), and pressing it follows the link. The content is the preview, and the arrow is optional.

The card only adds a preview for people who pause on the link: everything in it should be reachable from the page the link goes to, since touch and screen reader users may never open it. For a tip on a button, use a [Tooltip](./tooltip). For content that opens with a press, use a [Popover](./popover).

## Usage

Import the parts and put them together:

```html
<script type="module">
  import "@ui-sdk/web/hover-card"
</script>

<ui-hover-card>
  <ui-hover-card-trigger><a href="/people/hollis">@hollis</a></ui-hover-card-trigger>
  <ui-hover-card-content hidden>
    <p>Hollis Grant</p>
    <p>Design engineer on the payments team.</p>
  </ui-hover-card-content>
</ui-hover-card>
```

## Positioning

`side` picks where the card opens, `bottom` by default, and `align` lines it up with the start, center or end of the link. The card flips to the other side when there isn't room and shifts along the link to stay on screen.

`ui-hover-card-arrow` follows the side the card actually lands on, including after a flip, and gets the same `data-side`. It points at the middle of the link and keeps `arrow-padding` away from the corners; `data-arrow-clamped` tells you when it can't reach the middle.

<ComponentExample
  name="hover-card/side"
  caption="Choose a side and an alignment, then hover @ines. The card opens there and its arrow points at the link."
/>

`side-offset` is the gap to the link, 4 pixels by default. `align-offset` shifts the card along it, and `collision-padding` is the space kept from the edges of the window. `anchor` positions the card against something other than the link, named by a CSS selector.

```html
<ui-hover-card-content
  side="right"
  align="start"
  side-offset="8"
  collision-padding="16"
  anchor="#row"
  hidden
></ui-hover-card-content>
```

## Delays

`delay` is how long the pointer rests on the link, or keyboard focus stays on it, before the card opens: 600 milliseconds by default. `close-delay` is how long it stays open once the pointer leaves the link and the card: 300 milliseconds by default. The pointer can cross the gap between the link and the card without closing it.

`disabled` stops the card from opening and leaves a plain link.

```html
<ui-hover-card delay="300" close-delay="150" disabled></ui-hover-card>
```

## Controlled

Set the element's `open` property and listen for `openchange`; the `open` attribute sets where it starts. Every change carries a [reason](#reasons) in `event.detail.reason`, like `trigger-hover`, `trigger-focus`, `focus-out`, `escape-key` or `outside-press`. Call `event.preventDefault()` to stop it.

```html
<ui-hover-card></ui-hover-card>

<script type="module">
  const card = document.querySelector("ui-hover-card")
  card.addEventListener("openchange", (event) => (open = event.detail.value))
  card.open = true
</script>
```

## One Card for Many Links

A feed or a list can share one card instead of rendering one per link. Give the card an `id` and name it from each trigger with `for`. Each trigger takes a `payload` property, like its person, read when it connects, so set it before the trigger goes into the page. The card's `payloadchange` event carries it in `event.detail.value`; render the content from it there. Only the link that opened the card gets `data-open`. The card's `api.open({ payload })` opens it from code.

```html
<ui-hover-card id="profile">
  <ui-hover-card-content hidden><p></p></ui-hover-card-content>
</ui-hover-card>

<script type="module">
  const card = document.querySelector("#profile")
  for (const person of people) {
    const trigger = Object.assign(document.createElement("ui-hover-card-trigger"), { payload: person })
    trigger.setAttribute("for", "profile")
    trigger.innerHTML = `<a href="${person.url}">${person.name}</a>`
    feed.append(trigger)
  }
  card.addEventListener("payloadchange", (event) => {
    card.querySelector("p").textContent = event.detail.value?.bio
  })
</script>
```

A card can have links of its own. Tab from a link with an open card moves into the card, and Tab past its end moves on to the page after the link. Focus leaving the card closes it.

## Container

Cards render in place and show in the top layer, so no ancestor clips or covers them. `container` renders the card somewhere else, named by a CSS selector, for iframes, shadow roots or a specific stacking context. See the shared [popup guide](../popups).

```html
<ui-hover-card-content container="#card-host" hidden></ui-hover-card-content>
```

## Animation

The content has `data-starting-style` while it opens and `data-ending-style` while it closes. Transition from those states, and the card stays mounted until the exit finishes. `openchangecomplete` fires after the transition, and `keep-mounted` keeps the closed card in the page, hidden, for animation libraries that drive the exit from state.

<StyleTabs>

```css
[data-slot="hover-card-content"] {
  transition:
    opacity 150ms,
    scale 150ms;

  &:is([data-starting-style], [data-ending-style]) {
    opacity: 0;
    scale: 0.96;
  }
}
```

```html
<ui-hover-card-content
  class="origin-(--transform-origin) transition-[opacity,scale] duration-150 data-starting-style:scale-96 data-starting-style:opacity-0 data-ending-style:scale-96 data-ending-style:opacity-0"
  hidden
></ui-hover-card-content>
```

</StyleTabs>

## Custom Rendering

Elements have no render functions. The trigger wraps your own link, so the link can hold anything, like an avatar and a name. The link gets `data-open` while the card is open from it.

```html
<ui-hover-card-trigger>
  <a href="/people/hollis">
    <span aria-hidden="true">HG</span>
    Hollis Grant
  </a>
</ui-hover-card-trigger>
```

## Styling

Each element has a `data-slot`, such as `hover-card-content`, and shows its state through the attributes listed under [Data Attributes](#data-attributes). Use `data-open` on the trigger's link to mark the link whose card is showing, and `data-side` to style the content and arrow for the side they landed on. Put `transform-origin: var(--transform-origin)` on the content so it scales from the link.

Keep overflow visible around an arrow that extends outside the card. If the body needs to scroll, put scrolling on an inner element.

### Controller

Create one with `createHoverCardController<Payload>()` from `@ui-sdk/web/hover-card` and assign it to the root
element's `controller` property. The root element's `api` property has the same methods, and its `open` property reads
and sets whether the card is open. `Payload` is the type of the data triggers and `open()` pass.

Every write method takes an optional `{ reason, event }`, passed to `openchange`.

### Events

Events fire on their own element and don't bubble, with the new state in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on `openchange` cancels the change.

| Member                     | On                      | Description                                                                     |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| `open` property, attribute | `ui-hover-card`         | Whether the card is open. The attribute sets where it starts, and is live       |
| `api` property             | `ui-hover-card`         | The [controller](#controller)                                                   |
| `controller` property      | `ui-hover-card`         | A controller from `createHoverCardController()`, to drive it from code          |
| `openchange` event         | `ui-hover-card`         | `detail: { value: open, reason, event }`                                        |
| `openchangecomplete` event | `ui-hover-card`         | `detail: { value: open }`, after the animation                                  |
| `payloadchange` event      | `ui-hover-card`         | `detail: { value: payload, reason, event }`, when the content's payload changes |
| `payload` property         | `ui-hover-card-trigger` | Data for the content, read when the trigger connects                            |
| `for` attribute            | `ui-hover-card-trigger` | The `id` of a card the trigger opens from outside it                            |

## Accessibility

The trigger stays a plain link, and the card is a preview beside it, not a dialog. Every line below is an automated test.

### Keyboard

| Key    | Does                                                                         |
| ------ | ---------------------------------------------------------------------------- |
| Tab    | On the link, opens the card after `delay`; with the card open, moves into it |
| Enter  | Follows the link                                                             |
| Escape | Closes the card and leaves focus on the link                                 |

Keyboard focus opens the card after the same `delay` as the pointer, so tabbing through a page of links doesn't flash a card at every stop. Focus leaving the card closes it.

Touch screens have no hover, so a tap follows the link without opening the card. Anything in the card should be on the page the link goes to.
