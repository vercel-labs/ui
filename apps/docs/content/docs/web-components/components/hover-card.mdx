## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Importing the component defines its elements. On the server the import does nothing.

```ts
import "@ui-sdk/web/hover-card"
```

## Composition

Use the following composition to build a `ui-hover-card`:

```text
ui-hover-card
├── ui-hover-card-trigger
│   └── a
└── ui-hover-card-content
```

Wrap a link and its preview in a hover card.

The trigger wraps your own `<a>`, so it stays a link.

The trigger is a link, and pressing it follows the link. The card only adds a preview for people who pause on it: everything in it should be reachable from the page the link goes to, since touch and screen reader users may never open it. For a tip on a button, use a [Tooltip](./tooltip). For content that opens with a press, use a [Popover](./popover).

## Examples

### Side

`side` picks where the card opens: `bottom` by default. It flips to the other side when there isn't room, and shifts along the link to stay on screen.

<ComponentExample name="hover-card/side" caption="Hover each link to compare the four preferred sides." />

### Delays

`delay` is how long the pointer rests on the link, or keyboard focus stays on it, before the card opens: 600 milliseconds by default. `closeDelay` is how long it stays open once the pointer leaves the link and the card: 300 milliseconds by default. The pointer can cross the gap between the link and the card without closing it.

`disabled` stops the card from opening and leaves a plain link.

<ComponentExample
  name="hover-card/delay"
  caption="Change the delays, then move between the link and card to see when it opens and closes."
/>

### Offsets

`sideOffset` is the gap to the link, 4 pixels by default. `alignOffset` shifts along it, and `collisionPadding` is the space kept from the edges of the window.

### Arrow

The arrow follows the side the card actually lands on, including after it flips away from an edge, and gets the same `data-side`. It points at the middle of the link, even after the card shifts, and keeps `arrowPadding` away from the corners. Change the side and alignment, then hover the link.

### Anchor

Position the card against something other than the link with `anchor`: an element, a CSS selector, a point like `{ x, y }`, or anything with `getBoundingClientRect()`. Here a name in a commit row opens a card lined up with the whole row.

### Controlled

The element's `open` property is live: read it, or set it to open or close the card. The `open` attribute
sets where it starts, and changing it later opens or closes the card too. Listen for `openchange`, and call
`preventDefault()` on it to cancel the change.

Every change carries a [reason](#reasons), like `trigger-hover`, `trigger-focus`, `focus-out`, `escape-key` or `outside-press`. A [controller](#controller), from `createHoverCardController()`, opens the card from anywhere.

The element's `api` is its controller.

### One Card for Many Links

A feed or a list can share one card instead of rendering one per link. Put the links anywhere on the page and connect them to the card with its controller. Each link passes a `payload`, like its person, and the content reads it from its state. Only the link that opened the card gets `data-open`.

Name the card with `for`, and set each trigger's `payload` property. The trigger reads it when it connects, so set it before the trigger goes into the page. Render the content when `payloadchange` fires, with the payload in `event.detail.value`. It fires when a link with another payload opens the card, and when the pointer or focus moves on to another link while it's open, which hands the card over without an `openchange`.

The card here has a link of its own. Tab from a link with an open card moves into the card, and Tab past its end moves on to the page after the link. Focus leaving the card closes it.

<ComponentExample
  name="hover-card/payload"
  caption="Move between authors. One card updates its preview; Tab can reach View profile inside it."
/>

### Container

Cards render in place and show in the top layer, so no ancestor clips or covers them. `container` renders the card somewhere else, for iframes, shadow roots or a specific stacking context.

### Animation

`openchangecomplete` runs once the card has finished opening or closing, after any
animation, with the new open state. `keepMounted` on the content keeps the closed card in the page, hidden,
for animation libraries that drive the exit from state. See [Styling](#styling) for the attributes to animate.

It's an `openchangecomplete` event with the open state in `event.detail.value`. Add `keep-mounted` to `<ui-hover-card-content>`.

## Keyboard and Touch

Keyboard focus on the link opens the card after the same `delay` as the pointer, so tabbing through a page of links doesn't flash a card at every stop. Escape closes it and leaves focus on the link, and Enter follows the link. When the card has something to focus, Tab moves into it, and focus leaving the card closes it.

Touch screens have no hover, so a tap follows the link without opening the card. Anything in the card should
be on the page the link goes to.

## Styling

Parts are unstyled. Style them through the attributes they render, which are the same in every framework.

<DataAttributes component="hover-card" />

Open cards also set CSS variables for sizing and animation, listed under [HoverCardContent](#hovercardcontent).

Animate with `data-starting-style` and `data-ending-style`. The card stays mounted until its exit animation finishes.

```css
[data-slot="hover-card-content"] {
  transition:
    opacity 150ms,
    scale 150ms;
  transform-origin: var(--transform-origin);
}

[data-slot="hover-card-content"]:is([data-starting-style], [data-ending-style]) {
  opacity: 0;
  scale: 0.96;
}
```

### Events

Events fire on their own element and don't bubble, with the new state in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on `openchange` cancels the change.

| Member                     | On                      | Description                                                                     |
| -------------------------- | ----------------------- | ------------------------------------------------------------------------------- |
| `open` property, attribute | `ui-hover-card`         | Whether the card is open. The attribute sets where it starts, and is live       |
| `api` property             | `ui-hover-card`         | The [controller](#controller)                                                   |
| `openchange` event         | `ui-hover-card`         | `detail: { value: open, reason, event }`                                        |
| `openchangecomplete` event | `ui-hover-card`         | `detail: { value: open }`, after the animation                                  |
| `payloadchange` event      | `ui-hover-card`         | `detail: { value: payload, reason, event }`, when the content's payload changes |
| `payload` property         | `ui-hover-card-trigger` | Data for the content, read when the trigger connects                            |
| `for` attribute            | `ui-hover-card-trigger` | The `id` of a card the trigger opens from outside it                            |
