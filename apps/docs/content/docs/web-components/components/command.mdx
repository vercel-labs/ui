Command puts a search field over a list of actions. The list stays open while someone searches. You can use it on its own, or put it in a dialog to build a command palette.

<ComponentExample
  name="command/demo"
  caption="Type “bil” to find Billing. Arrow keys move the highlight; Escape clears the search."
/>

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the element definitions once in your application:

```ts
import "@ui-sdk/web/command"
```

## Composition

Use the following composition to build a `ui-command`:

```text
ui-command
├── ui-command-input
│   └── input
├── ui-command-empty
└── ui-command-list
    ├── ui-command-item
    └── ui-command-item
```

Give the input an accessible name and each command a unique value. Keep empty and status messages outside the list, which holds commands and groups.

Typing filters the commands. Arrow keys move the highlight, and Enter runs the highlighted command. Focus stays in the input, which points to the highlight with `aria-activedescendant`. `action` reports the value of the command that ran; read it from `event.detail.value`.

## Examples

### Dialog

Put Command inside a [Dialog](./dialog) for a command palette. Give the dialog a title, put `shortcut="mod+k"` on its trigger, and close it when a command runs. The dialog handles dismissal and returns focus to the trigger.

<ComponentExample
  name="command/dialog"
  caption="Press Search or use Cmd+K / Ctrl+K. Choose a command to run it and close the palette."
/>

### Shortcuts

An item’s `shortcut` can run it while the command list is mounted, even when the search or current page hides it. `ui-command-shortcut` displays the keys for the current platform, and the item gets `aria-keyshortcuts`. Shortcuts inside a dialog run while it is open.

<ComponentExample
  name="command/shortcuts"
  caption="Press Cmd+P / Ctrl+P to run Profile, even when the search hides it. The result appears below."
/>

### Groups

Use `ui-command-group` and `ui-command-group-label` to name related commands. Groups and separators disappear when filtering leaves them empty.

### Scrollable

Give the list a height limit and `overflow-y-auto`. Keyboard navigation scrolls the highlighted command into view. Keep the input outside the scrolling area so it stays available.

### Highlight Matches

`ui-command-item-text` marks the matched text. The default fuzzy filter can match letters that are apart, so one command may have several marked segments.

<ComponentExample
  name="command/highlight"
  caption="Type “prf” to find Profile. Matching letters are marked even when they are not next to each other."
/>

### Icons

`ui-command-item-icon` keeps decorative icons out of accessible names and filtering. Add `mirror` for directional icons, as the Go back command does below. An icon-only command still needs an `aria-label`.

When mixing commands with and without icons, `data-has-icons` on the list and `data-has-icon` on each item let you reserve matching space with logical padding.

### Suggestions

Pass `emptyItems` alongside `items` to show suggested or recent commands while the first page’s search is empty. Once someone types, the full collection is searched.

### Pages

Set an item’s `page` to the value of a `ui-command-page` to open it. An unnamed page holds the first set of commands. The `pages` array records the stack of pages that have been opened.

Backspace in an empty search goes back and restores the previous page’s query. Escape clears the query first, then goes back. A Go back command can call `pop()` on the element’s API.

<ComponentExample
  name="command/pages"
  caption="Choose Change theme or Switch team. Use Go back, or press Backspace in an empty search field, to return."
/>

### Items as Data

Pass `items` to provide commands, groups, separators, and pages as `CommandData`. A data command with its own `items` opens a page. Its shortcut still works when another page or filter hides it.

Assign `items` as a property. A `<template>` supplies the markup and classes for generated parts. The example handles groups and separators as well as commands. [Lists and Menus](../lists-and-menus) covers the shared data format.

<ComponentExample
  name="command/data"
  caption="Choose Change theme to open its commands. Press Cmd+I / Ctrl+I to run Open inbox from any page."
/>

### Async Results

Use [async options](../utilities/async-options) to wait for typing to pause and discard stale results. Send query changes to `setQuery()`, render the returned items, and pass `status`. Set `filter` to `false` to keep the server’s order.

`ui-command-status` describes loading and failures, and the list gets `aria-busy` while loading. `loadmore` can request another page when scrolling or highlighting reaches the last command. Without a status part, `announcement` controls the result-count message after typing pauses.

<ComponentExample
  name="command/async"
  caption="Type “login” and wait for matching issues. Replace the text to start a new search; only the latest results appear."
/>

### Pending Actions

Pass a promise to `event.detail.waitUntil()` in an `action` or `select` listener. The command gets `data-pending` and `aria-busy` until it settles; further presses do not start another run. A rejection becomes the command’s `error` state, which clears when it runs again.

An item’s `select` runs before `action`. Call `preventDefault()` on the select event to stop the action.

<ComponentExample
  name="command/pending"
  caption="Run Deploy to production and try it again while it is pending. Sync with server demonstrates a failure and retry."
/>

### Filter

`"fuzzy"` is the default: `nf` matches New file. `"contains"` and `"startsWith"` match the text itself. A custom function returns a boolean or a score; zero hides a command and higher scores rank first.

Data commands are sorted by score. Commands written directly in markup keep their order, even though the best match can be highlighted.

<ComponentExample
  name="command/filter"
  caption="Type “nf” with Fuzzy to find New file. Choose Words and type “zo in” to find Zoom in."
/>

### Keywords

`keywords` adds search terms without changing the command’s label. Use it for synonyms or names someone might type instead.

### Auto Highlight

By default, Command highlights the first available command and the best match while typing. Set `auto-highlight` to `false` to wait for an arrow key or pointer movement. `loop` independently controls whether arrow keys wrap.

### Virtualized

Pass the full `items` collection so filtering and keyboard navigation include commands that are not mounted. Render only visible rows, giving each its index in the current results. `valuechange` includes that index so you can scroll a newly highlighted row into view.

<ComponentExample
  name="command/virtualized"
  caption="Search 10,000 commands or move through them with the arrow keys. Only the rows near the viewport render."
/>

### Custom Rendering

Render a command as an anchor when it should navigate. Enter follows the highlighted link; modified clicks keep their usual browser behavior. [Parts and Composition](../parts-and-composition) covers the `as-child` API.

<ComponentExample
  name="command/custom-rendering"

## State and Events

### Controlled

The highlighted command, search text, and page stack are separate:

| Value   | Shape                               | Change Notification |
| ------- | ----------------------------------- | ------------------- |
| `value` | A command’s string value or `null`. | `valuechange`       |
| `query` | The search text.                    | `querychange`       |
| `pages` | An array of page values.            | `pageschange`       |

Read or write these properties on the element. Change events expose the requested value in `event.detail.value`; call `event.preventDefault()` to reject it. `action` reports activation, so moving the highlight alone does not run a command. [State and Events](../state-and-events) covers the shared binding pattern.

### Controller

Use the element’s `api` property. It can read and set the highlight, query, and page stack. Use `push()` and `pop()` to navigate pages, `run()` to run the highlighted command or a named one, and `focus()` to focus the search. See [Controllers](../controllers) for setup and lifecycle.

### RTL

Set `dir="rtl"` on a containing element. Text, logical spacing, and icons marked with `mirror` follow that direction without a provider.

## Styling

### Events

Events fire on their own element and don't bubble, with the new state in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on a change event cancels it.

| Member              | On                | Description                                                           |
| ------------------- | ----------------- | --------------------------------------------------------------------- |
| `value` property    | `ui-command`      | The highlighted command. Setting it highlights, as a controller would |
| `query` property    | `ui-command`      | The search text                                                       |
| `pages` property    | `ui-command`      | The stack of pages                                                    |
| `api` property      | `ui-command`      | The [controller](#controller-1)                                       |
| `valuechange` event | `ui-command`      | `detail: { value, reason, event, source, index }`                     |
| `querychange` event | `ui-command`      | `detail: { value: query, reason, event, source }`                     |
| `pageschange` event | `ui-command`      | `detail: { value: pages, reason, event, source }`                     |
| `action` event      | `ui-command`      | `detail: { value, waitUntil(promise) }`, when a command runs          |
| `loadmore` event    | `ui-command`      | When the last command is reached                                      |
| `select` event      | `ui-command-item` | The command ran. `preventDefault()` skips the `action` event          |
