title: Date Picker

Date Picker combines a text field with [Calendar](./calendar). People can type a date in their language or choose it from the popup. Your application receives an ISO date string either way.

<ComponentExample
  name="date-picker/basic"
  caption="Type a date and press Enter, or open the calendar and choose a day. The field formats the date when you commit it."
/>

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the element definitions once in your application. This also defines the Calendar elements:

```ts
import "@ui-sdk/web/date-picker"
```

## Composition

Use the following composition to build a `ui-date-picker`:

```text
ui-date-picker
├── ui-date-picker-input
│   └── input
├── ui-date-picker-trigger
├── ui-date-picker-hint
└── ui-date-picker-content
```

The input accepts a date, the trigger opens the calendar, and the hint describes the expected format. An empty content part renders a calendar for you.

Every [Calendar part](./calendar#composition) also works inside `ui-date-picker-content` and is exported from the Date Picker entry. Write those parts out when you need to add styles, change the layout, or include custom day content.

An input element wraps your native `<input>` or creates one. The trigger, Clear, and presets wrap a `<button>` or create one around their content.

## Values

Dates are strings such as `"2026-10-16"`, with no time or time zone attached. No date library is needed.

| Mode                 | Value                                                 |
| -------------------- | ----------------------------------------------------- |
| `"single"` (default) | A date string or `null`.                              |
| `"range"`            | `[start, end]` or `null`, with an input for each end. |

## Typing a Date

The input parses text when you press Enter or leave the field. It uses the locale’s date order, such as `10/16/2026` in American English or `16.10.2026` in German. It also accepts ISO dates, digits without separators, two-digit years, and month names in the locale or English. Dates without a year use the current year.

The field formats a valid date after it is committed, leaving your typing alone until then. Invalid text stays visible and sets `aria-invalid` and `data-invalid`; the previous value stays unchanged. Until the text is a date again, or empty, the input reports "Enter a valid date." as its validation message, so its form won't submit. The hint’s state includes an example date you can show alongside the field.

## Examples

### Range

`mode="range"` uses one input for the start and another with `end` for the end. The calendar stays open after the start is picked and closes once both dates are chosen. A typed end before the start is invalid.

The range is `null` until both ends are valid. Clearing either input clears the complete value while leaving the other input’s date visible.

<ComponentExample
  name="date-picker/range"
  caption="Choose October 20, then October 23. The calendar stays open after the first date and closes after the second."
/>

A booking can combine two months, range limits, unavailable dates, and form submission. Here, `page-by="page"` moves both months together, and `allow-unavailable` allows a stay to cross a booked date. The `form` option connects the picker to a form elsewhere on the page.


### Presets

`ui-date-picker-preset` chooses its `value` and closes the popup. It exposes `aria-pressed` and `data-selected` when that value matches the selection. Your application calculates relative dates, such as the last seven days. In markup, a range preset holds two comma-separated ISO dates.

<ComponentExample
  name="date-picker/presets"
  caption="Open the calendar and choose Last 7 days. Reopen it to see the selected preset."
/>

### Min, Max and Unavailable Dates

`min`, `max`, and `unavailable` apply to both typing and calendar selection. A date outside those rules is invalid when typed. [Calendar](./calendar#unavailable-dates) explains the available matchers and how unavailable dates differ from the bounds.

<ComponentExample
  name="date-picker/min-max"
  caption="Try typing 11/21/2026, then 10/16/2026. Dates outside the allowed bounds are invalid and cannot be picked."
/>


For ranges, `min-days` and `max-days` count both endpoints. `allow-unavailable` permits unavailable dates between them, but never as an endpoint. See [Range Limits](./calendar#range-limits).

### Language

`locale` sets the input’s format, hint, month names, and date labels. Without it, Date Picker follows the surrounding page’s `lang`, then the browser’s language. Date strings remain Gregorian ISO dates.

The trigger, popup, and calendar navigation have English accessible labels by default. Pass `aria-label` to translate those controls too.

<ComponentExample
  name="date-picker/locale"
  caption="Enter 3.12.2026 and press Enter. The field, format hint, and calendar use German dates."
/>

Calendar’s `week-starts-on`, `weekday-format`, `fixed-weeks`, `show-outside-days`, and `time-zone` options apply here too. [Calendar](./calendar#language) shows these options without the popup.

### The Popup

`ui-date-picker-content` opens below the input by default. Position it with `side`, `align`, and offsets, or provide a custom `anchor`. `container` changes where it renders; `keep-mounted` retains it while closed, and `final-focus` controls focus after it closes. [Popups](../popups) covers these shared options.

`presentation="auto"` uses a sheet on small touch screens and a popover elsewhere. `presentation="sheet"` always uses a sheet. Style the two layouts using `data-presentation`, as this example does.

<ComponentExample
  name="date-picker/popup"
  caption="Open the calendar to see it placed above the field when there is room. On a small touch screen, it opens as a sheet. The text below reports changes."
/>

### Staying Open

Set `close-on-select` to `false` to keep the calendar open after choosing a date, completing a range, or pressing a preset.


### Keep It Open Until Both Dates Are Picked

Set `dismissible` to `false` while a choice is incomplete. Escape, an outside press, or the system back gesture then leave the popup open. `dismissattempt` reports intentional attempts, so you can explain what is missing. Focus leaving is refused quietly. The trigger and imperative controls can still close it.

<ComponentExample
  name="date-picker/dismissible"
  caption="Choose a check-in date, then press outside the calendar. The message asks for a check-out date before the popup can be dismissed."
/>

### Clear

`ui-date-picker-clear` clears the value and focuses the input. It gets `data-empty` when there is nothing to clear. Emptying a single-date input clears its value too.

<ComponentExample
  name="date-picker/clear"
  caption="Press Clear to empty the value and focus the input. The Clear button disappears until there is a value again."
/>

### Disabled and Read Only

`disabled` prevents typing, opening, and selection. `read-only` lets people open the calendar and inspect its dates without changing the value.



## Forms

`name` submits an ISO date. In range mode, use `start-name` and `end-name` for separate fields, or `name` to submit both ends under the same name. `required` blocks an empty submission, text that isn't a date blocks one too, a form reset restores `default-value`, and a disabled `fieldset` disables the picker. Form participation begins once the custom elements are defined.

<ComponentExample
  name="date-picker/form"
  caption="Press Submit with an empty field, then enter a date and submit again. A valid date submits as an ISO string."
/>

A [Field](./field) connects the label, description, and errors to the input, and shows an error for an empty required date or text that isn't a date. Its `name` is used when the picker has none, and a disabled field disables the picker.


## Behavior and Options

### Controlled

The selected value, displayed month, and open state are separate. `value` uses the shape for the chosen mode; `month` is the first displayed month, such as `"2026-10"`; `open` is a boolean.

Read and write the element’s `value`, `month`, and `open` properties. Listen for `valuechange`, `monthchange`, and `openchange`; call `event.preventDefault()` to reject a change. [State and Events](../state-and-events) covers the binding pattern, and the [reason tables](#reasons) list Date Picker’s reasons.

### Driving It from Anywhere

The element’s `api` can set the value, show a month, open or close the popup, and focus a date in the open calendar. [Controllers](../controllers) covers setup and lifecycle; the [controller reference](#controller) lists the methods.

## Keyboard

| Key             | Where   | Action                                                                        |
| --------------- | ------- | ----------------------------------------------------------------------------- |
| Enter           | Input   | Commit the typed date.                                                        |
| Alt+Down Arrow  | Input   | Open the calendar.                                                            |
| Enter / Space   | Trigger | Open or close the calendar.                                                   |
| Escape          | Popup   | Cancel an unfinished range first; otherwise close the popup.                  |
| Tab / Shift+Tab | Popup   | Move through controls. Leaving the popup closes it when dismissal is allowed. |

Opening focuses the selected date, otherwise today, otherwise the first focusable date. The calendar’s [arrow keys and month navigation](./calendar#keyboard) work here too. An ancestor’s `dir="rtl"` reverses Left and Right Arrow to follow the visual order.

## API Reference

Props are attributes in kebab case, like `default-value`, `close-on-select` and `start-name`, and numbers are
numbers. `value`, `default-value` and `unavailable` take comma-separated dates, and the `unavailable`
property takes any matcher, like `{ weekday: [0, 6] }`. `container` takes a `#id`. `controller` is a
property. Callbacks are DOM events. The element is form-associated, so it submits with
no hidden input.

### Events

Events fire on their own element and don't bubble, with the new value in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` cancels the change. Type the element as `UiDatePickerElement` for typed listeners.

| Member                     | On               | Description                                               |
| -------------------------- | ---------------- | --------------------------------------------------------- |
| `value` property           | `ui-date-picker` | The selected value. Setting it selects it                 |
| `open` property            | `ui-date-picker` | Whether the popup is open. Setting it opens or closes it  |
| `month` property           | `ui-date-picker` | The calendar's first month. Setting it turns there        |
| `api` property             | `ui-date-picker` | The [controller](#controller)                             |
| `controller` property      | `ui-date-picker` | A controller from `createDatePickerController()`          |
| `valuechange` event        | `ui-date-picker` | `detail: { value, reason, event, source }`                |
| `openchange` event         | `ui-date-picker` | `detail: { value: open, reason, event, source }`          |
| `openchangecomplete` event | `ui-date-picker` | `detail: { value: open }`, once any animation finished    |
| `monthchange` event        | `ui-date-picker` | `detail: { value: month, reason, event, source }`         |
| `dismissattempt` event     | `ui-date-picker` | `detail: { reason, event }`, when a dismissal was refused |

## Accessibility

It follows the [WAI-ARIA date picker dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/examples/datepicker-dialog/): a plain text input that every screen reader handles, a button with `aria-haspopup="dialog"` and `aria-expanded` named by the date chosen, and a dialog holding the calendar's grid. Focus moves into the grid when the dialog opens and back to the button when a date is picked or Escape closes it. Every line below is an automated test.
