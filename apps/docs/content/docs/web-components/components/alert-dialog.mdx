Use an alert dialog when someone needs to answer a question before an action continues, such as deleting a project.

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

To use the examples' Tailwind classes, add the [example theme](../styling-and-animation#example-theme) to your global stylesheet.

## Anatomy

Importing the component defines its elements; on the server the import does nothing. Put the question in `ui-alert-dialog-title`, explain what happens in `ui-alert-dialog-description`, and wrap each answer’s native button in `ui-alert-dialog-close`:

```ts
import "@ui-sdk/web/alert-dialog"
```

```html
<ui-alert-dialog>
  <ui-alert-dialog-trigger><button>Delete project</button></ui-alert-dialog-trigger>
  <ui-alert-dialog-content hidden>
    <ui-alert-dialog-title>Delete this project?</ui-alert-dialog-title>
    <ui-alert-dialog-description>
      The project and its files will be deleted for everyone.
    </ui-alert-dialog-description>
    <ui-alert-dialog-close><button>Cancel</button></ui-alert-dialog-close>
    <ui-alert-dialog-close value="confirm"><button>Delete</button></ui-alert-dialog-close>
  </ui-alert-dialog-content>
</ui-alert-dialog>
```

The dialog uses the `alertdialog` role and keeps the rest of the page inert while it is open. Screen readers announce its title and description. Add `ui-alert-dialog-backdrop` when you want to dim the page, as the examples do. Give the content and backdrop `hidden` to keep them hidden before the elements upgrade.

Put Cancel first. By default, a keyboard open focuses the first Close part. Escape closes the dialog, but pressing outside never does. [Dialog](./dialog#focus) covers other initial and final focus targets.

[Dialog](./dialog#keyboard-shortcut) covers trigger shortcuts. `AlertDialogShortcut` uses the same pattern.

A Close part reports its `value` when it closes. `value="confirm"` is the agreeing answer that the [confirm helper](#confirm) recognizes. Closing the basic example only answers the question; the next examples show how to act on that answer.

### Controlled

Set the element’s `open` property to open or close it from your app. Listen for `openchange` to follow changes made by its parts. [State and Events](../state-and-events) explains controlled state and canceling a change.

/>

### Confirm

Use `createConfirm<Payload>()` to ask a question from an event handler and await the answer. Create it once, then pass its `controller` to your alert dialog. Import `createConfirm` from `@ui-sdk/web/alert-dialog` and assign `confirm.controller` to the root element’s `controller` property. The `payloadchange` event provides the current question in `event.detail.value`.

`await confirm({ name })` resolves `true` when the Close part with `value="confirm"` closes the dialog. Cancel, Escape, and other answers resolve `false`. This lets several rows share one dialog:

<ComponentExample
  name="alert-dialog/confirm"
  caption="Delete a project. Cancel or Escape keeps it; Delete removes it and focuses a neighboring row's button. Reset projects brings the list back."
/>

When the action removes the button that opened the dialog, choose a useful place for focus to go. This example focuses a neighboring row, or Reset projects when the list is empty.

### Queued Questions

Calls to the same confirm function wait their turn. You can ask two questions at once; the second appears only after the first has an answer.

<ComponentExample
  name="alert-dialog/queue"
  caption="Choose Review two projects. Answer the Acme question, then the Globex question. Each result appears below the button after both questions are answered."
/>

### Async Action

Add `action` to a Close part and listen for its `action` event. Pass a Promise to `event.detail.waitUntil()` during that event to keep the dialog open until the work finishes. A resolved Promise closes it with the reason `action`; a rejection keeps it open and puts the error in that part's state.

<ComponentExample
  name="alert-dialog/async-action"
  caption="Choose Delete project, then Delete. The first attempt fails so you can try again. While Deleting… is shown, Cancel and Escape leave the dialog open. A successful retry closes it."
/>

While the action runs, its button stays focusable and gets `data-pending`, `aria-busy`, and `aria-disabled`. Other Close parts and dismissals cannot close the dialog until it settles. `dismissattempt` reports refused dismissals; a controller can still close it.

The root’s `pending-announcement` attribute sets what screen readers hear after a second of waiting. The error clears on the next attempt or when the dialog opens again. The action event’s `detail.source` describes the input that started it; [Changes After an Await](./button#changes-after-an-await) explains when to use it.

## API Reference

Alert Dialog shares [Dialog's](./dialog) options, except `modal`, `closeOnOutsidePress`, and `presentation`. It is always modal, never closes on an outside press, and does not present as a sheet.

## Accessibility

Give the dialog a title and a description, and put the least destructive answer first. It follows the [WAI-ARIA alert dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/alertdialog/). These behaviors are covered by automated tests:
