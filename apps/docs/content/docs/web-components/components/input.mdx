## Installation

```bash
pnpm add @ui-sdk/web @ui-sdk/core
```

Importing the component defines its elements. On the server the import does nothing.

```ts
import "@ui-sdk/web/input"
```

## Composition

Use the following composition to build a `ui-input` or a `ui-input-group`:

```text
ui-input
└── input

ui-input-group
├── ui-input
│   └── input
└── ui-input-clear
    └── button
```

`<ui-input>` wraps your own `<input>`, which keeps every native behavior. A plain `<input>` works in a field too; wrap it when you want `valuechange`, `data-filled` or the `api`.

`Input` renders a native `<input>`, so every native attribute works: `type`, `placeholder`, `autoComplete`, `minLength`, `pattern`. Inside a [Field](./field), it takes the field's `id`, its label as its name, its description and errors as its description, and `aria-invalid`.

## Examples

### Field

Wrap the input in a [Field](./field) to associate a visible label and description. Field also supplies its name when the input does not have one.

### Disabled

Set `disabled` on the input or its Field to prevent editing and remove it from the tab order.

<ComponentExample
  name="input/disabled"

### Invalid

Set `invalid` on Field for an error your app decides. The input gets `aria-invalid`, and Field associates the error message with it.

<ComponentExample
  name="input/invalid"
  caption="Focus Email. The field is marked invalid, and its error message explains the expected address format."

### Required

Use the native `required` attribute for browser validation. Field shows the error after an unsuccessful submit.

<ComponentExample
  name="input/required"
  caption="Choose Continue while Email is empty. The browser blocks submission and focuses the required field."
/>

### Input Group

Place text around an input with `InputGroup`. Clicking that text focuses the input. The prefix and suffix are display content; they are not added to the submitted value.

<ComponentExample
  name="input/input-group"
  caption="Click https:// or .com to focus Website, then type a domain name. Only the text you enter belongs to the input's value."
/>

### Clear Button

`InputClear` appears when the input has editable text. Pressing it clears the value, reports `clear-press`, and returns focus to the input. Controlled state and native input listeners receive the change too.

<ComponentExample
  name="input/clear"
  caption="Choose Clear search. The text clears, focus returns to the input, and the last change shows clear-press. Type again to bring the button back."
/>

### Controlled

Set the `value` property and listen for `valuechange`. Its detail contains the new value and the reason. The example derives a read-only profile URL from the display name.

<ComponentExample
  name="input/controlled"
  caption="Edit Display name. Profile URL updates with it and stays read-only."
/>

See [State and Events](../state-and-events) for the shared controlled-state conventions. Input's [reasons](#reasons) distinguish typing, clearing, resetting, and controller changes.

### Filtering What's Typed

Call `event.preventDefault()` in the `valuechange` listener to reject a change. The previous text and caret position are restored.

<ComponentExample
  name="input/filter"
  caption="Type 12a3 into Verification code. The letter is rejected and the value becomes 123. The input accepts up to six digits."
/>

### Controller

Use `createInputController()` for actions outside the input. Its methods update the input through the same change callbacks as typing.

<ComponentExample

  caption="Choose Quick reply to fill Message, Clear to empty it, and Focus to move the caret into the input."

## API Reference

`<ui-input>` has no attributes of its own: put native ones on the `<input>`. It fires a `valuechange`
event that doesn't bubble, with `detail: { value, reason, event, source }`, and `preventDefault()` cancels the change.
