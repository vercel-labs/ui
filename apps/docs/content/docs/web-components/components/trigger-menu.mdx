## Trigger Menu or Token Input

Trigger Menu owns the suggestions: matching a trigger, filtering, keyboard navigation, loading items, and command arguments. [Token Input](./token-input) owns a field whose value mixes text and tokens.

Use Trigger Menu with a textarea or input to insert text. Put it inside a Token Input to insert tokens. You can also connect it to another editor through an [adapter](#any-editor).

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Importing the component defines its elements. On the server the import does nothing.

```ts
import "@ui-sdk/web/trigger-menu"
```

## Composition

Use the following composition to build a `ui-trigger-menu`:

```text
ui-trigger-menu
├── ui-trigger-menu-input
│   └── textarea
├── ui-trigger-menu-status
└── ui-trigger-menu-content
    └── ui-trigger-menu-list
        ├── ui-trigger-menu-item
        └── ui-trigger-menu-item
```

Set `triggers` as a property. The input part wraps your own `<textarea>` or `<input>`. A list without items of its own renders the current trigger's data items.

The field keeps focus while the arrow keys move the highlight. A `<textarea>` stays a textbox, which ARIA allows no other role, and points at the list with `aria-controls` and, after an arrow key, `aria-activedescendant`. An `<input>` is a combobox. Counts and states are said through a polite status, never through the field.

## Examples

### Triggers as Data

Give each trigger a `char` and `items`. Items can be strings, objects, groups, or a loader. The same field can offer people after `@`, commands after `/`, and channels after `#`.

/>

### Commands with Arguments

A trigger with `boundary: "start"` matches only at the start of the text, so a leading space escapes it. An item with `arguments` asks for each one in order: `TriggerMenuHint` shows what's left at the caret, Tab accepts the highlighted suggestion and moves to the next argument, Enter finishes once only optional arguments remain, and Backspace past an argument's start goes back. An argument without `items` is free text. `after: "submit"` sends the form once the item is inserted.

<ComponentExample
  name="trigger-menu/commands"
  caption="Type /model, then use Tab to choose a model and an optional effort. Try /send to submit."
/>

### Icons

Put an item's icon in a `TriggerMenuItemIcon`, before its text. Screen readers skip it, and filtering and the text a choice inserts ignore it, so an SVG's `<title>`, an icon font's glyph or an emoji never joins the item's name or the field. Items as data have no icon, so compose the items that show one.

- **Icons that point a way**, like arrows and reply, flip in right-to-left text with `mirror`.
- **Items with only an icon** need an `aria-label`, which filtering matches too. In development, one with no name warns.
- **Lining up items.** Items with an icon get `data-has-icon`, and the list gets `data-has-icons` while any item has one, so items without an icon can leave its space: `in-data-has-icons:not-data-has-icon:ps-8`.

<ComponentExample
  name="trigger-menu/icons"
  caption="Type / to open commands with icons. Directional icons follow the text direction."
/>

### Loading Items

A trigger's `items` can be a loader, called with the query and an `AbortSignal` once typing pauses. A newer query aborts the older load, so only its results land, and the last results stay while the next ones load. The status and empty parts get `loading`.

While a load runs, `aria-busy` marks the list, or the content when there's no `TriggerMenuList`, so style stale results there, like `aria-busy:opacity-60` on the list.

<ComponentExample
  name="trigger-menu/async"
  caption="Type # and a channel name. Keep typing while results load to replace the pending request."
/>

### Custom Items

Compose `TriggerMenuItem`s with any content, in groups. `label` is what's matched and inserted, and `keywords` adds words to match. A trigger's `spaces`, `pattern` and `maxLength` decide what its query may hold, `filter` how it narrows the items, and `insert` what replaces the trigger and query. An item's own `select` fires first, on the item, and can insert something else with `event.detail.insert()`.

An adapter for another editor reads its text and selection, measures a rectangle at an offset, replaces a range as one undo step, and reports changes. Report changes that weren't the user's with `user: false`, like a collaborator's, and the menu never opens for them.

## Undo

Choosing an item preserves the native text field's undo history. Press Cmd+Z or Ctrl+Z to restore the query. Safari may combine the insertion with the preceding typing in one undo step.

A custom editor adapter must make each replacement one undo step; [Token Input](./token-input) handles its own token history.

### Callbacks

Events fire on their own element and don't bubble, with the new state in `event.detail.value`.

| Member                 | On                | Description                                                                                          |
| ---------------------- | ----------------- | ---------------------------------------------------------------------------------------------------- |
| `triggers` property    | `ui-trigger-menu` | The triggers and what each one lists                                                                 |
| `editor` property      | `ui-trigger-menu` | An editor adapter, for a field without an input part                                                 |
| `open` property        | `ui-trigger-menu` | Whether the menu is open                                                                             |
| `api` property         | `ui-trigger-menu` | The [controller](#controller-1)                                                                      |
| `openchange` event     | `ui-trigger-menu` | `detail: { value: open, reason, trigger }`                                                           |
| `querychange` event    | `ui-trigger-menu` | `detail: { value: query, reason, trigger, argument }`                                                |
| `select` event         | `ui-trigger-menu` | `detail: { value, arguments, insert(), waitUntil(promise) }`. `preventDefault()` skips the insertion |
| `dismissattempt` event | `ui-trigger-menu` | `detail: { reason, event }`, when a dismissal was refused                                            |

When `select` returns a Promise and the editor takes tokens, the token is inserted at once with `data-pending`, updated with what the Promise resolves to, and removed if it rejects. The menu closes either way, so you keep typing.
