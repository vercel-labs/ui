A popover keeps a small task close to the thing it belongs to. Put fields, buttons, or other interactive content inside; it handles placement, focus, and dismissal.

<ComponentExample
  name="popover/basic"
  caption="Open the popover and edit the dimensions. Escape, another press on the trigger, or a press outside closes it."
/>

## Installation

```package-install
npm install @ui-sdk/web
```

Import the component to register its elements. The import is safe on the server.

```ts
import "@ui-sdk/web/popover"
```

## Composition

Use the following composition to build a `ui-popover`:

```text
ui-popover
├── ui-popover-trigger
│   └── button
└── ui-popover-content
    ├── ui-popover-title
    ├── ui-popover-description
    └── ui-popover-close
        └── button
```

The content has the dialog role. Its title names it and its description adds context. The trigger can live inside the popover or [connect from elsewhere](#triggers-outside-the-popover).

## Examples

### With Form

An ordinary form can save a value and then close the popover. Focus starts on the first field and returns to the trigger when the task finishes. A form with `method="dialog"` closes on submission and returns its submit button’s value; the [row editor](#triggers-outside-the-popover) shows that version.

<ComponentExample
  name="popover/form"
  caption="Open Edit profile, change the name, and press Save. The popover closes and the readout shows the saved name."
/>

### Keep It Open While Editing

Set `dismissible` to false while there is unsaved work. Deliberate dismissal attempts report `dismissattempt`, so you can ask whether to discard it. Focus leaving is refused quietly. The trigger, Close parts, and controller can still close it explicitly.

<ComponentExample
  name="popover/draft"
  caption="Type a note, then press Escape or click outside. Keep editing returns to the field; Discard closes without saving, and Save keeps the note."
/>

### Placement

`side` chooses an edge; `align` chooses where along it to line up. Start and end follow text direction. The popover flips or shifts when the requested position does not fit.

`sideOffset` is the gap from the anchor, `alignOffset` shifts along its edge, and `collisionPadding` keeps space around the viewport boundary. The [popup guide](../popups) covers the shared positioning options.

### Arrow

The arrow follows the side the popover actually uses, including after a flip. `arrowPadding` keeps it away from corners; `data-arrow-clamped` tells you when it cannot point exactly at the anchor’s center. This example cancels dismissal when you press its placement controls, so the open arrow can move.

<ComponentExample
  name="popover/arrow"
  caption="Open Help, then change Side or Align. The panel stays open while its arrow follows the new position."
/>

Keep overflow visible around an arrow that extends outside the panel. If the body needs to scroll, put scrolling on an inner element. You can also draw an arrow with `::before`, using `data-side` and `--arrow-offset` to position it.

### Anchor

Set `anchor` to position against something other than the trigger. It accepts an element, a selector, a point such as `{ x, y }`, or an object with `getBoundingClientRect()`, such as a text range. The position is read again as the anchor moves.

<ComponentExample
  name="popover/anchor"
  caption="Open Search filters. The popover lines up with the search field instead of the small trigger beside it."
/>

### Modal

The default leaves the page usable and closes when focus leaves the popover. `modal="trap-focus"` keeps Tab inside while the page can still scroll and receive clicks. `modal` also makes the rest of the page inert and locks scrolling.

<ComponentExample
  name="popover/modal"
  caption="Compare Non-modal, Trap focus, and Modal. Try Tab, then press the counter below to see whether the page can receive the click."
/>

### Focus

Use `initial-focus` to choose the first focused element, or `"none"` to leave focus where it is. `final-focus` controls where focus returns. Hover opening leaves focus alone; touch opening focuses the panel itself so the keyboard does not appear unexpectedly.

<ComponentExample
  name="popover/focus"
  caption="Open each example: First field focuses its input, Specific element focuses Apply, and No focus change leaves focus on the trigger."
/>

### Open on Hover

`openOnHover` adds pointer opening while keeping click, keyboard, and touch activation. `delay` and `closeDelay` control the pause before opening and closing. You can cross the gap into the content and interact with it.

<ComponentExample
  name="popover/hover"
  caption="Hover over @ada, then move into the preview and press Close preview. You can also open it by pressing the trigger."
/>

### Controlled

Set the `open` property and listen for `openchange` to keep your state in sync. Use `event.preventDefault()` to reject a proposed change. A controller can open it from another control; [state and events](../state-and-events) and [controllers](../controllers) cover these shared patterns.

<ComponentExample
  name="popover/controlled"
  caption="Open Share directly or press Open from elsewhere. Close it to see the value and change reason in the readout."
/>

### Keyboard Shortcut

Set a trigger’s `shortcut` to toggle the popover from the keyboard. `mod+i` means Command+I or Control+I. The Shortcut part displays the platform’s keys, and the trigger advertises them through `aria-keyshortcuts`.

<ComponentExample
  name="popover/shortcut"
  caption="Press Command+I or Control+I to open Dimensions. Press the same shortcut again, or Escape, to close it."
/>

### Triggers Outside the Popover

Use `for="popover-id"` on each external trigger and assign its `payload` property. The popover reads the active payload through `api.getPayload()`. Only the active trigger is expanded and receives focus back. Opening from another row updates the same panel, so one editor can serve the whole list.

`api.open({ payload, anchor })` opens it from code and returns a promise with the closing reason and any `returnValue`. The payload stays available during the exit animation.

<ComponentExample
  name="popover/payload"
  caption="Edit Grace Hopper or Alan Turing and save a new role. The owner cannot be edited. Edit the newest member opens the same editor from code and reports its result."
/>

### Container

Popovers render in place by default and use the browser’s top layer. `container` moves their DOM to another element while keyboard order still follows the trigger. See [popups](../popups) for the shared container behavior.

<ComponentExample
  name="popover/container"
  caption="Open in the box. The popover is rendered inside the marked container in the DOM while remaining positioned by its trigger."
/>

### Animation

Animate `data-starting-style` and `data-ending-style`; `openchangecomplete` reports when each transition finishes. `keepMounted` leaves the closed content in the DOM, hidden. See [styling and animation](../styling-and-animation) for the common lifecycle.

<ComponentExample
  name="popover/animation"
  caption="Open Animated, then dismiss it. The readout follows Opening, Open, Closing, and Closed."
/>

### Presentation

`presentation="sheet"` shows the task as a sheet; `"auto"` chooses a sheet on small touch screens each time it opens. A sheet is modal by default and can be swiped down to dismiss. If dismissal is disabled, it springs back and reports the attempt.

Style `data-presentation` for both layouts. The sheet manages its own position and movement, so leave its translation alone and avoid the floating panel’s fixed width. `--sheet-backdrop` sets the dim behind it.

<ComponentExample
  name="popover/presentation"
  caption="Open Dimensions as a sheet. Edit a value, then dismiss it with Escape, the dimmed area, or a downward swipe on a touch screen."
/>

### Events

Events fire on their own element and don't bubble, with the new state in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on `openchange` cancels the change.

| Member                     | On                   | Description                                                                             |
| -------------------------- | -------------------- | --------------------------------------------------------------------------------------- |
| `open` property, attribute | `ui-popover`         | Whether the popover is open. The attribute sets where it starts, and is live            |
| `api` property             | `ui-popover`         | The [controller](#controller)                                                           |
| `openchange` event         | `ui-popover`         | `detail: { value: open, reason, event, source }`                                        |
| `openchangecomplete` event | `ui-popover`         | `detail: { value: open }`, after the animation                                          |
| `payloadchange` event      | `ui-popover`         | `detail: { value: payload, reason, event, source }`, when the content's payload changes |
| `dismissattempt` event     | `ui-popover`         | `detail: { reason, event }`, when a dismissal was refused                               |
| `payload` property         | `ui-popover-trigger` | Data for the content, read when the trigger connects                                    |
| `for` attribute            | `ui-popover-trigger` | The `id` of a popover the trigger opens from outside it                                 |
