## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

To use the examples' Tailwind classes, add the [example theme](../styling-and-animation#example-theme) to your global stylesheet.

Import the component in your client entry point to register its elements:

```ts
import "@ui-sdk/web/toggle"
```

The demos use icons from `lucide`. Install that package if you copy their source.

## Usage

Wrap a native button in `ui-toggle`. It reports its state with `aria-pressed` and always uses `type="button"`, so pressing it does not submit a form.

<span id="anatomy" />

```html
<ui-toggle>
  <button>Bookmark</button>
</ui-toggle>
```

Keep the label the same in both states. Screen readers announce whether the button is pressed. An icon-only toggle needs an `aria-label`, as in the first demo.

## Behavior and Options

### Controlled

Read or set the element's `pressed` property. `pressedchange` reports the next state in `event.detail.value`. Call `event.preventDefault()` during `pressedchange` to cancel it.

The element's `api.toggle()` and `api.setPressed()` methods let another button change it.

<ComponentExample
  name="toggle/controlled"
  caption="Press Notifications, then Toggle from outside. The status shows whether it is pressed and why it changed."
/>

### Focusable When Disabled

Set `focusable-when-disabled` to keep a disabled toggle focusable. It uses `aria-disabled` and still ignores presses. Give it an `aria-describedby` message when you can explain why it is unavailable.

## Group

Put toggles in `ui-toggle-group` to share a value and arrow-key navigation. Give the group an accessible name and each toggle a `value`.

<ComponentExample
  name="toggle/group"
  caption="Press Bold and Italic to keep both pressed. Use Left and Right to move focus without changing either state."
/>

```html
<ui-toggle-group multiple aria-label="Text formatting">
  <ui-toggle value="bold"><button>Bold</button></ui-toggle>
  <ui-toggle value="italic"><button>Italic</button></ui-toggle>
</ui-toggle-group>
```

The group owns which toggles are pressed, so a toggle's own `pressed` and `default-pressed` do not apply inside it. The group has the `group` role and its toggles remain buttons with `aria-pressed`.

### Vertical

Set `orientation="vertical"` to use Up and Down instead of Left and Right. The group and its toggles expose `data-orientation` for styling.

### One or Several

By default, pressing a toggle unpresses the others. Pressing it again clears the selection. Set `multiple` to allow several pressed toggles, as in the formatting group above.

The value is always an array. With a single selection it holds one value or none; with multiple selections it follows the toggles' document order.

<ComponentExample
  name="toggle/group-single"
  caption="Press Align center to replace Align left. Press Align center again to clear the selection."
/>

### Deselectable

Set `deselectable="false"` to prevent a press from clearing the last selection. It does not choose an initial value for you and is ignored when `multiple` is set.

<ComponentExample
  name="toggle/group-deselectable"
  caption="Choose a different alignment, then press it again. One alignment stays pressed."
/>

Use [Radio](./radio) when arrow keys should select an option as they move focus. Toggle groups move focus first and wait for a press.

### Keyboard

A group is one tab stop. Tab initially enters on its first enabled pressed toggle, or its first enabled toggle. After you move focus within it, Tab returns to the last focused toggle.

| Key                        | Action                              |
| -------------------------- | ----------------------------------- |
| `Tab`                      | Enter or leave the group            |
| `ArrowRight` / `ArrowLeft` | Move focus in a horizontal group    |
| `ArrowDown` / `ArrowUp`    | Move focus in a vertical group      |
| `Home` / `End`             | Focus the first or last toggle      |
| `Enter` / `Space`          | Press or unpress the focused toggle |

Arrow keys wrap by default. Set `loop="false"` to stop at the ends.

<ComponentExample
  name="toggle/group-loop"
  caption="Focus Strikethrough and press Right: focus stays there. Home still moves to Bold."
/>

### Controlled Group

Read or set the group element's `value` array. Listen for `valuechange` to receive the next array in `event.detail.value`. Cancel the change with `event.preventDefault()`. A toggle's `pressedchange` event fires first and can cancel the group change too.

Call `group.api.setValue([])` to clear the group from another button.

<ComponentExample
  name="toggle/group-controlled"
  caption="Press a formatting toggle, then Clear. The status shows the selected values and the reason for each change."
/>

See [State and Events](../state-and-events) for controlled state, cancellation and debugging.

### Forms

Toggles do not submit values. Use [Checkbox](./checkbox#group) for multiple form choices or [Radio](./radio) for one. If you keep a toggle group, copy its value into hidden inputs yourself.

### Render Functions

## API Reference

Props are attributes in kebab case, like `default-pressed` and `focusable-when-disabled`: `"false"` is
false, as in `deselectable="false"` and `loop="false"`. A group's `value` and `default-value` take
comma-separated values, like `default-value="bold,italic"`. `pressed` is a live property and attribute.
Callbacks are DOM events. Elements have no `controller` attribute: their `api` property
is one.

### Events

Events fire on their own element and don't bubble, with the new state or value in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` cancels the change.

| Member                        | On                | Description                                                                                                                   |
| ----------------------------- | ----------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `pressed` property, attribute | `ui-toggle`       | Whether the toggle is pressed. The attribute sets where it starts, and is live                                                |
| `api` property                | `ui-toggle`       | The [controller](#toggle-controller)                                                                                          |
| `pressedchange` event         | `ui-toggle`       | `detail: { value: pressed, reason, event, source }`. In a group, it fires before the group's `valuechange`, and can cancel it |
| `value` property              | `ui-toggle-group` | The pressed toggles' values. Setting it presses toggles                                                                       |
| `api` property                | `ui-toggle-group` | The [controller](#togglegroup-controller)                                                                                     |
| `valuechange` event           | `ui-toggle-group` | `detail: { value, reason, event, source }`                                                                                    |

## Accessibility

The toggle follows the toggle button in the [WAI-ARIA button pattern](https://www.w3.org/WAI/ARIA/apg/patterns/button/). Every line below is an automated test.

<SpecList spec="toggle" />

### Groups

A group follows the keyboard of the [WAI-ARIA toolbar pattern](https://www.w3.org/WAI/ARIA/apg/patterns/toolbar/): one tab stop, arrow keys between toggles, and Home and End. It has the `group` role, not `toolbar`, so it can sit inside a [Toolbar](./toolbar), and not `radiogroup`, since its toggles are buttons with `aria-pressed`.
