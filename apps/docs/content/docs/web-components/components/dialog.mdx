A dialog gives a task its own space: share a link, edit a record, or collect a few details. It manages focus, Escape, outside presses, and returning to where you started.

<ComponentExample
  name="dialog/basic"
  caption="Open Share, then close it with either Close button, Escape, or a press outside. Focus returns to Share."
/>

## Installation

```package-install
npm install @ui-sdk/web
```

Import the component to register its elements. The import is safe on the server.

```ts
import "@ui-sdk/web/dialog"
```

## Composition

Use the following composition to build a `ui-dialog`:

```text
ui-dialog
├── ui-dialog-trigger
│   └── button
├── ui-dialog-backdrop
└── ui-dialog-content
    ├── ui-dialog-title
    ├── ui-dialog-description
    └── ui-dialog-close
        └── button
```

The title names the dialog; the description gives it context. A dialog can have several Close parts. Give an icon-only close button an accessible name, as the first example does.

<span id="custom-close-button" />

The backdrop is optional. Without one, style the content’s `::backdrop`. For a question that requires an explicit answer, use [Alert Dialog](./alert-dialog).

## Examples

### Scrollable Content

<span id="sticky-footer" />

Keep the header and actions outside the scrolling area. A viewport height limit, a shrinking middle grid row, and `overflow-y: auto` keep long content usable. `initial-focus="content"` focuses the dialog itself so reading starts at the top.

<ComponentExample
  name="dialog/scrollable"
  caption="Open Scrollable content in a short window. Scroll the terms while the title and Decline/Accept buttons stay in view."
/>

### Modal

`modal` controls how the dialog shares the page:

- `true`, the default, makes the page inert, locks scrolling, and keeps Tab inside.
- `"trap-focus"` keeps Tab inside while the page can still scroll and receive clicks.
- `false` lets focus leave the dialog. Escape closes it while focus is inside; outside presses close it only when `closeOnOutsidePress` is enabled.

<ComponentExample
  name="dialog/modal"
  caption="Choose a mode, open Notes, and try Tab or clicking the page. Enable closeOnOutsidePress to compare dismissal behavior."
/>

### Warn Before Closing a Dirty Form

Set `dismissible` to false while there are unsaved changes. Escape, an outside press, or a back gesture then keeps the dialog open and reports `dismissattempt`. Explicit Close parts and controller calls still work, so you can offer a deliberate way out.

<ComponentExample
  name="dialog/dirty-form"
  caption="Type a post, then press Escape or click outside. Keep editing returns to the field; Discard closes the dialog and clears the draft."
/>

### Nested Dialogs

A dialog opened inside another joins its stack. Escape closes the topmost dialog and returns focus to its trigger. Closing the parent also closes its children. `data-nested-open` and `--dialog-stack` let you show which layer is active.

<ComponentExample
  name="dialog/nested"
  caption="Open Account, then Change password. Press Escape once to return to Account, and again to close it."
/>

### Opening from a Menu Item

Render the dialog outside the menu and open it with `api.open()`. When the item disappears, the menu’s trigger becomes the place to return focus.

<ComponentExample
  name="dialog/from-menu"
  caption="Open File actions and choose Rename. Close the dialog to return focus to the File actions button."
/>

### Opening from Anywhere

Connect an external `ui-dialog-trigger` with `for="dialog-id"`, and assign its `payload` property. The dialog’s `api.open({ payload })` opens it from code and returns a promise that resolves when it closes, with the reason and any `returnValue`. Each trigger remains the return-focus target for the dialog it opened. See [controllers](../controllers) for the shared controller pattern.

<ComponentExample
  name="dialog/payload"
  caption="Open a reminder from either unpaid invoice, or press Open from code. The same dialog shows that invoice and reports how it closed."
/>

### Forms

A form with `method="dialog"` closes the dialog on a valid submission. The submit button’s `value` becomes the `returnValue`, just like a Close part’s `value`. An ordinary form stays open until you close the dialog yourself.

<ComponentExample
  name="dialog/form"
  caption="Open New article and choose Save draft or Publish. The readout shows the submitted button’s value. An empty title prevents submission."
/>

### Focus

Use `initial-focus` to pick where focus starts, and `final-focus` to choose where it goes next. The default returns to the trigger or the element focused before a controller opened the dialog. See [popup focus](../popups) for the shared focus rules.

<ComponentExample
  name="dialog/focus"
  caption="Open Invite. Focus starts on Email; closing the dialog moves it to Next step."
/>

### Controlled

Set the element’s `open` property and listen for `openchange` to keep another control in sync. Cancel a proposed change with `event.preventDefault()`. `openchangecomplete` reports when opening or closing has finished; see [state and events](../state-and-events) for the common change contract.

<ComponentExample
  name="dialog/controlled"
  caption="Use the open checkbox or Open button, then close the dialog. The log records each change and its completion."
/>

### Keyboard Shortcut

A trigger’s `shortcut` opens it from the keyboard. `mod+j` means Command+J on Apple platforms and Control+J elsewhere. The Shortcut part displays the right keys and the trigger exposes `aria-keyshortcuts`.

<ComponentExample
  name="dialog/shortcut"
  caption="Press Command+J or Control+J to open Search docs. Escape returns to the trigger; choosing a page closes the dialog with that page as its value."
/>

### Persistent Elements

Keep a small part of the page usable while a modal dialog is open. `persistent-elements` accepts selectors; assign `persistentElements` an array of elements or a function returning them. The chat launcher here uses a native popover to sit above the backdrop; persistent elements alone do not change stacking.

<ComponentExample
  name="dialog/persistent"
  caption="Open Upgrade plan, then press Chat with us. Its count changes while the dialog stays open."
/>

### Container

Dialogs render where you put them and use the browser’s top layer. Set `container` when their DOM needs to live elsewhere. The shared [popup guide](../popups) covers containers, shadow roots, and iframes.

<ComponentExample
  name="dialog/container"
  caption="Open in the box. The dialog still appears over the page, but its content is rendered in the marked container in the DOM."
/>

### Animation

The content and backdrop receive `data-starting-style` and `data-ending-style`. They stay present through exit animations, and `openchangecomplete` runs after the transition. This example keeps the content mounted; see [styling and animation](../styling-and-animation) for the shared lifecycle.

<ComponentExample
  name="dialog/animation"
  caption="Open the dialog and close it. The readout follows Opening, Open, Closing, and Closed; focus returns as closing starts."
/>

### Presentation

`presentation="sheet"` presents the same task as a sheet. Use `"auto"` to choose a sheet on small touch screens and a centered dialog elsewhere, decided each time it opens. A swipe down closes a dismissible sheet; a protected one springs back and reports a dismissal attempt.

Style `data-presentation` to support both layouts. The sheet manages its own position and movement, so do not apply the centered dialog’s translation to it. `--sheet-backdrop` styles the dimmed page when no Backdrop part is present.

<ComponentExample
  name="dialog/presentation"
  caption="Open Edit profile as a sheet. On a touch screen, drag it down to dismiss it, or use Cancel or Save changes."
/>

### Controller

The element's `api` property has the same methods. The `open` property reads and sets whether the dialog is
open.

Every write method takes an optional `{ reason, event }`, passed to `openchange`. Closing with a controller always works, even when the dialog isn't dismissible or an action is running.

<ControllerTable path="../../packages/core/src/components/dialog/dialog.ts" name="DialogController" />

### Events

Events fire on their own element and don't bubble. Calling `preventDefault()` on `openchange` cancels the change.

| Member                     | On                  | Description                                                                             |
| -------------------------- | ------------------- | --------------------------------------------------------------------------------------- |
| `open` property, attribute | `ui-dialog`         | Whether the dialog is open. The attribute sets where it starts, and is live             |
| `api` property             | `ui-dialog`         | The [controller](#controller)                                                           |
| `controller` property      | `ui-dialog`         | A controller from `createDialogController()`, to drive it from code                     |
| `openchange` event         | `ui-dialog`         | `detail: { value: open, reason, event, returnValue }`                                   |
| `openchangecomplete` event | `ui-dialog`         | `detail: { value: open }`, after the animation                                          |
| `payloadchange` event      | `ui-dialog`         | `detail: { value: payload, reason, event, source }`, when the content's payload changes |
| `dismissattempt` event     | `ui-dialog`         | `detail: { reason, event }`, when a dismissal was refused                               |
| `payload` property         | `ui-dialog-trigger` | Data for the content, read when the trigger connects                                    |
| `for` attribute            | `ui-dialog-trigger` | The `id` of a dialog the trigger opens from outside it                                  |

## Accessibility

The trigger is a button that opens a dialog, and the dialog follows the [WAI-ARIA modal dialog pattern](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/): `aria-modal` while it's modal, labelled by its title, described by its description only while one is rendered.
