Use a Tree when items have children, like files in folders or pages in a docs sidebar. Start with nested parts, then add selection, checkboxes, or children loaded from a server as you need them.

<ComponentExample
  name="tree/demo"

/>

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the element definitions once in your application:

```ts
import "@ui-sdk/web/tree"
```

## Composition

Use the following composition to build a `ui-tree`:

```text
ui-tree
├── ui-tree-item
│   ├── ui-tree-item-label
│   │   └── ui-tree-item-indicator
│   └── ui-tree-group
│       └── ui-tree-item
│           └── ui-tree-item-label
└── ui-tree-item
    └── ui-tree-item-label
```

Give the tree an accessible name and every item a unique `value`. An item with a `ui-tree-group` inside it is a branch. The group holds its children; the label names the item.

The tree has one Tab stop. Arrow keys move between visible items, open branches, and return to their parents. The indicator and checkbox are optional; they belong to the item around them, so you can put them inside or beside its label.

## Examples

### Items as Data

Pass `items` to give the tree its full hierarchy, including collapsed branches. Each `TreeItemData` has a `value`, a `label`, and optional `children`.

The element can render bare parts from that property, or a `<template>` can supply their markup and classes. Keep `items` on the tree when rendering your own rows so keyboard navigation, item counts, and controllers know the whole hierarchy.

/>

### File Paths

Pass `paths` for a file explorer. Folders become branches and sort before files; a path ending in `/` represents an empty folder. `treeFromPaths()` returns the same data when you want to render the rows yourself.

Selection and activation are separate. This example uses `activation="automatic"` so arrow keys select a file, then `action` opens it. Pass a promise to the action event’s `detail.waitUntil()` to show a pending state while it opens.

<ComponentExample
  name="tree/paths"
  caption="Move through the files with arrow keys, then press Enter to open one. Selection changes immediately; opening shows a pending state."
/>

### Checkboxes

Add `checkable` and `ui-tree-item-checkbox` for a checked state separate from selection. Space checks the focused item. Checking a branch checks its descendants, and a partly checked branch reports a mixed state.

`check-strategy` chooses what the `checked` array reports:

| Strategy        | Reported Values                          |
| --------------- | ---------------------------------------- |
| `"leaf"`        | Checked leaves. This is the default.     |
| `"trunk"`       | The outermost fully checked items.       |
| `"branch"`      | Every fully checked item.                |
| `"independent"` | Each item on its own, without cascading. |

<ComponentExample
  name="tree/checkboxes"
  caption="Press Space on Vue, then on Frontend. A branch is mixed while some of its descendants are checked."
/>

### Multiple Selection

`selection-mode="multiple"` makes the value an array. Cmd-click or Ctrl-click toggles one item, Shift extends a range, and Cmd+A or Ctrl+A selects the visible items.

### Links

Set `selection-mode="none"` for a navigation tree, then render labels as links. `current` identifies the current page with `aria-current="page"`, expands its ancestors, and gives it the initial Tab stop. Update it when your route changes.

<ComponentExample
  name="tree/links"

### Loading Children

Mark an item as a `branch` before its children exist. `loadChildren` runs the first time that branch expands while empty. Load and render its children, then let the promise resolve; the tree expands the branch once they are ready.

Use the supplied `signal` to cancel a request. Trying to expand the branch again while it loads aborts it. A rejection sets `data-failed`, and the next attempt retries. `announcement` lets you customize loading and failure messages.

<ComponentExample
  name="tree/lazy"
  caption="Expand users to load its files. Archive fails on its first attempt; expand it again to retry."
/>

### Virtualized

Pass the full `items` hierarchy and use `visibleTreeRows(items, expanded)` to flatten the open branches. Render the nearby rows with their level and position; the tree supplies the correct ARIA hierarchy even though the DOM is flat.

`itemfocus` reports the focused item’s index among visible rows. Use it to scroll before mounting a row that is outside the rendered range. This example indents rows by their level and keeps each row 28 pixels high.

<ComponentExample
  name="tree/virtualized"
  caption="Expand folders or press End to focus Folder 100. The tree has 10,100 items, but only nearby rows render."
/>

### Right to Left

Set `dir="rtl"` on an ancestor. Left and Right Arrow swap their expand/collapse roles, and logical padding keeps nested rows indented from the correct side. No provider is needed.

## Behavior and Options

### Keyboard

Tab enters at the current page, selected item, or first item, then remembers the last focused item. From there:

| Key                         | Action                                                 |
| --------------------------- | ------------------------------------------------------ |
| Down / Up Arrow             | Focus the next or previous visible item.               |
| Right Arrow                 | Expand a branch, or enter its first child.             |
| Left Arrow                  | Collapse a branch, or focus its parent.                |
| Home / End                  | Focus the first or last visible item.                  |
| Alt+Right / Alt+Left Arrow  | Expand or collapse a branch and its descendants.       |
| `*`                         | Expand sibling branches.                               |
| Enter                       | Select and run the item’s action, or follow its link.  |
| Space                       | Check the item when checkable, otherwise select it.    |
| Shift+Down / Shift+Up Arrow | Extend a multiple selection.                           |
| Cmd+A / Ctrl+A              | Select visible items in multiple selection mode.       |
| Typing                      | Focus the next item whose label starts with that text. |

Option is Alt on a Mac. Left and Right swap in right-to-left text.

### Selection

The default `selection-mode="single"` uses one string value or `null`. Use `"multiple"` for an array, or `"none"` when items should only navigate or perform actions.

`activation="automatic"` selects while arrow keys move in single selection mode. Pressing a branch also expands or collapses it; set `expand-on-press` to `false` to leave expansion to the indicator and arrow keys.

### Disabled

Disabled items cannot be selected, checked, expanded, or run. They remain focusable so screen readers can find them. Set `focusable-when-disabled` to `false` to skip them, or `disabled` on the root to disable the whole tree. A disabled `<fieldset>` around the tree disables it too.

### Find in Page

`hidden-until-found` keeps collapsed groups in the DOM with `hidden="until-found"`. In browsers that support it, Find in Page can match a hidden item and open its ancestors. Use `keep-mounted` when you only need collapsed content to stay mounted, without browser search.

<ComponentExample

/>

### Animation

A group exposes its measured height as `--tree-group-height`. Animate between that height and zero using its starting and ending attributes:

```html
<ui-tree-group
  class="h-(--tree-group-height) overflow-hidden transition-[height] data-starting-style:h-0 data-ending-style:h-0"
></ui-tree-group>
```

The group stays mounted until its closing animation ends. Groups open on the first render, or revealed by Find in Page, do not animate.

### Controlled

Selection, expanded branches, and checkboxes are independent:

| Value      | Shape                                          | Change Notification |
| ---------- | ---------------------------------------------- | ------------------- |
| `value`    | A string or `null`; an array in multiple mode. | `valuechange`       |
| `expanded` | An array of branch values.                     | `expandedchange`    |
| `checked`  | An array shaped by the check strategy.         | `checkedchange`     |

Read or write these properties on the element. Events expose the requested value in `event.detail.value`; call `event.preventDefault()` to reject it. [State and Events](../state-and-events) covers the shared binding pattern.

### Reveal an Item

The element’s `api` can expand or collapse branches, change selection and checkboxes, or focus an item. `reveal(value)` opens an item’s ancestors, scrolls it into view, and focuses it. Supply the hierarchy through `items` or keep collapsed groups mounted so their descendants are known. See [Controllers](../controllers) for setup and lifecycle.

## Styling

Style each row through `ui-tree-item-label`, which carries its item’s data attributes. Styling a nested item’s background would also cover its children. The focused item remains the parent, so use `[:focus-visible>&]` on its label:

```html
<ui-tree-item value="example" class="outline-none">
  <ui-tree-item-label
    class="rounded-xl px-2 data-selected:bg-neutral-100 [:focus-visible>&]:ring-3 [:focus-visible>&]:ring-neutral-400/50"
  >
    Label
  </ui-tree-item-label>
</ui-tree-item>
```

### Events

Events fire on `<ui-tree>` and don't bubble, with the new state in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on `valuechange`, `expandedchange` or `checkedchange` cancels the change. `action` fires when an item is pressed or gets Enter, with the item's value in `event.detail.value`. Pass a Promise to `event.detail.waitUntil()` to keep the item pending until it settles.
