Use a Time Input for a time of day, like a meeting or an opening hour. It works like [Date Input](./date-input), with segments for the hour, the minute and, on a 12-hour clock, AM or PM.

<ComponentExample
  name="date-input/time"
  caption="Click the hour and type 230, then P. Press ArrowUp or ArrowDown on a part to step it."
/>

## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Importing the component defines its elements. Import the field too if you use it. On the server the import does nothing.

```ts
import "@ui-sdk/web/time-input"
import "@ui-sdk/web/field"
```

## Composition

Use the following composition to build a `ui-time-input`:

```text
ui-time-input
├── ui-time-input-segment
│   └── input
└── ui-time-input-segment
```

`<ui-time-input>` renders a group with one `<ui-time-input-segment>` for each part of the time, and the text between them.

## Usage

Put the input in a [Field](./field) and give it a label:

```html
<script type="module">
  import "@ui-sdk/web/time-input"
  import "@ui-sdk/web/field"
</script>

<ui-field>
  <ui-field-label>Meeting time</ui-field-label>
  <ui-time-input default-value="09:30"></ui-time-input>
</ui-field>
```

The value is a 24-hour time like `"14:30"`, the same as a native time input's, whatever clock the input shows. Typing, stepping and pasting work as they do in [Date Input](./date-input#usage).

## Clock and Seconds

The input shows the locale's clock. Set `hour-cycle` to `12` or `24` to choose one, and `granularity` to `"second"` to add seconds, or `"hour"` to show the hour alone.

## Min and Max

`min` and `max` take times like `"09:00"`. A time outside them is invalid: the input sets `data-invalid`, and its form won't submit.

## Form

The element is form-associated and submits the time under `name`, with no hidden input. Set `required` to need a time before the form submits, and `form` to the id of a form elsewhere in the page to submit with it. The [Date Input form example](./date-input#form) has a time in it.

## Controlled and Controller

Listen for `valuechange` and set the `value` property, or drive the input with its `api`, as in [Date Input](./date-input#controlled).

## Styling

Style it like [Date Input](./date-input#styling). The AM/PM segment sets `data-type="dayPeriod"`.

Each part has a `data-slot`, such as `time-input-segment`, and its state attributes are listed under [Data Attributes](#data-attributes).

### Events

Events fire on their own element and don't bubble, with the value in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` on `valuechange` cancels the change.

| Member              | On                | Description                                                           |
| ------------------- | ----------------- | --------------------------------------------------------------------- |
| `value` property    | `<ui-time-input>` | The time, or null while empty or partly typed                         |
| `api` property      | `<ui-time-input>` | The [controller](#controller)                                         |
| `valuechange` event | `<ui-time-input>` | `detail: { value, reason, event }`, as a whole value forms or empties |

## Accessibility

The root is a group, named by its Field's label or by your `aria-label`. Each segment is a spinbutton named by its unit, like "hour" or "AM/PM", with its value, range and text. The keys are the same as in [Date Input](./date-input#keyboard).
