## Installation

```bash
npm install @ui-sdk/web @ui-sdk/core
```

Import the component in your client entry point to register its elements:

```ts
import "@ui-sdk/web/radio"
```

## Usage

Give each radio a `value` and put it inside a named `ui-radio-group`. The group's value is the checked radio's value. Without `default-value`, nothing starts checked and Tab enters on the first enabled radio.

<span id="composition" />

```html
<ui-radio-group default-value="comfortable" aria-label="Density">
  <label>
    <ui-radio value="comfortable"><ui-radio-indicator></ui-radio-indicator></ui-radio>
    Comfortable
  </label>
  <label>
    <ui-radio value="compact"><ui-radio-indicator></ui-radio-indicator></ui-radio>
    Compact
  </label>
</ui-radio-group>
```

The custom elements are the controls. The group is form-associated and submits without hidden inputs. Wrap a radio in a label, or connect a separate label with `for` and `id`.

## Behavior and Options

### Controlled

Read or set the group element's `value` property. `valuechange` reports the next value in `event.detail.value`. Call `event.preventDefault()` during `valuechange` to cancel it.

Use the group's `api.setValue()` method to check a radio from another button.

<ComponentExample
  name="radio/controlled"
  caption="Choose Starter, then Choose Team. The status shows the selected value and the reason for each change."
/>

See [State and Events](../state-and-events) for controlled state, cancellation and debugging.

### Read Only

Set `read-only` on the group to keep the value fixed while letting users focus and read the options. Arrow keys still move focus. The current value still submits with a form.

<ComponentExample
  name="radio/read-only"
  caption="Move focus from Pro to Team, or click Team. Pro remains checked."
/>

### Form

Set `name` to submit the selected value. `required` blocks submission until there is a choice. A form reset returns to `default-value`.

The demo keeps the group outside its form and connects them with the form's `id` through the group's `form` prop.

<ComponentExample
  name="radio/form"
  caption="Choose Express and Submit to see the form value. Reset returns the choice to Standard."
/>

### Horizontal

Use your own layout classes to put radios in a row or column. There is no orientation option: arrow keys work on both axes, like native radios.

### Loop

Arrow keys wrap from the last radio to the first. Set `loop="false"` to stop at the ends.

### Indicator

The indicator stays visible during its exit animation, then gets `hidden`. Set `keep-mounted` to leave it visible while unchecked so your CSS can show a hover preview.

Use `data-starting-style` and `data-ending-style` for entry and exit animations. The demo also uses the kept indicator to preview an unchecked option on hover.

## Forms

`ui-radio-group` is form-associated: `form.elements`, `checkValidity()`, `setCustomValidity()` and `:invalid` work on it. The group submits nothing without a `name` or a checked option. Enter on a radio submits its form; Space checks the focused option.

Use [Field](./field) for inline validation and the [Forms guide](../forms) for shared form behavior.

### Controller

The element's `api` property has the same methods. The `value` property reads and sets the checked value.

Every write method takes an optional `{ reason, event }`, fires the change event like a press, and returns `false` when the change is canceled.

### Events

Events fire on their own element and don't bubble, with the new value in `event.detail.value` and the `reason` and `event` beside it. Calling `preventDefault()` cancels the change.

| Member                      | On               | Description                                                        |
| --------------------------- | ---------------- | ------------------------------------------------------------------ |
| `value` property, attribute | `ui-radio-group` | The checked value. The attribute sets where it starts, and is live |
| `api` property              | `ui-radio-group` | The [controller](#controller)                                      |
| `valuechange` event         | `ui-radio-group` | `detail: { value, reason, event, source }`                         |
