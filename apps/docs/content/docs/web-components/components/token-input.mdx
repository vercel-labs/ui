## Token Input or Trigger Menu

Token Input holds the text and tokens. [Trigger Menu](./trigger-menu) suggests what to insert when someone types `@`, `/`, or another trigger.

Use Token Input on its own when your code supplies the tokens. Add a Trigger Menu for suggestions, as in the demo above. Trigger Menu also works with ordinary inputs and textareas.

## Installation

```bash
pnpm add @ui-sdk/web @ui-sdk/core
```

## Usage

A value is an array of text and tokens. Each token has a type, a value for your app, and a label for the reader:

```ts
import "@ui-sdk/web/token-input"
```

```html
<ui-token-input value="Explain [@routes.ts](file:src/routes.ts)">
  <ui-token-input-editor aria-label="Prompt"></ui-token-input-editor>
</ui-token-input>
```

The `value` attribute uses the text format. Set the element's `value` property to pass an array of text and tokens instead.

The editor manages its content, including tokens, selection, and undo. Let it render that content; use the token renderer when you want custom markup for a token. A child `<template>` can provide token markup, with `data-token-label` marking where its label goes. Use `renderToken(token, host)` for rendering from code.

### Deleting Tokens

Choose what Backspace does at a token with `tokenDeletion`:

- `whole` removes the token in one press.
- `select` selects it first, then removes it on the next press.
- `revert` turns it back into editable text.

### Codec

A codec converts tokens to text for the clipboard, forms, and saved drafts. The default writes `[@label](type:value)`. Copy that text into another app and paste it back to restore the token.

Use `toText`, `fromText`, and `toLabel` to convert values yourself. Supply a custom codec for another format, as this example does for `<@ada>`. The default parser accepts letters, digits, `_`, and `-` in token types; other types need a custom codec.

## Editing

Tokens are edited as a unit: the caret never stops inside one. Typing keeps the browser's spelling, autocorrect, and input-method support. Undo and redo belong to this input; typing is grouped, while pastes and token changes create their own history steps. Updating a token's status does not add a step.

The remove part is a pointer shortcut. Keep its default non-focusable element; keyboard users remove tokens with Backspace. Token labels, types, and changes are announced to screen readers.

## Styling

Apply Tailwind classes directly to the editor and token parts. Token hosts expose `data-token-type`, `data-pending`, `data-unresolved`, and `data-selected`, even without a custom token renderer.

### Callbacks

Events fire on their own element and don't bubble, with the new state in `event.detail.value`.

| Member              | On               | Description                                          |
| ------------------- | ---------------- | ---------------------------------------------------- |
| `value` property    | `ui-token-input` | The value. Setting a string parses it with the codec |
| `api` property      | `ui-token-input` | The [controller](#controller-1)                      |
| `valuechange` event | `ui-token-input` | `detail: { value, reason, inputType, removed }`      |

The submit shortcut submits the form the element is in, so the form's own `submit` event hears it.

Setting the `value` property is one undoable step, like `setValue()`. For the first value, use the `value` attribute with codec text, or set `defaultValue` and `codec` before the element connects: the `value` attribute reads with the default codec. `history` applies from the next edit whenever you set it.
